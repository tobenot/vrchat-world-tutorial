# 2. AI 是你的创作搭档

你打开 Unity，看到一整面面板。你搜一个报错，出来十几个答案。你问朋友，朋友说「这个简单」，然后发来一段你看不懂的脚本。

这时候 AI 很有用。

它可以陪你把问题拆小，可以把英文文档翻成你能读下去的话，可以帮你写第一版 UdonSharp 脚本，也可以在你卡住的时候给你几个排查方向。

但你要先记住一件事：AI 给的是建议，Unity 和 VRChat SDK 给的是结果。最后以你本地跑出来的东西和官方文档为准。

## 先把 AI 放到正确的位置

我建议你把 AI 当成旁边那位会查资料、会写草稿、很有耐心的搭档。

它擅长这些事：

- 把一个大问题拆成几个小步骤；
- 把英文文档解释成更顺口的中文；
- 根据你的目标写一份脚本草稿；
- 看到报错后列出可能原因；
- 帮你把「我想做一个效果」翻译成 Unity 里的对象、组件和脚本。

它也会犯这些错：

- 把旧版 SDK 的做法当成现在还能用；
- 编出一个看起来很像真的组件名；
- 写出标准 C# 能跑、UdonSharp 里会炸的代码；
- 漏掉 VRChat 多人同步、权限、平台限制这些麻烦点；
- 给出太大的方案，让你第一步就动不了。

所以我们用 AI，但不把方向盘交给它。

## 一个好问题长什么样

糟糕的问题通常太短：

```text
VRChat 怎么做门？
```

AI 可能会给你一整套门系统，里面有动画、按钮、音效、同步、权限和 UI。看起来很厉害，落地时你连第一个脚本挂哪里都不知道。

更好的问法是这样：

```text
我在做 VRChat World，用 Unity 和 UdonSharp。
我现在想做一扇最简单的门：玩家点击门，门旋转 90 度打开。
先不要做多人同步，也不要做动画曲线。
请你给我一个最小可运行步骤：
1. 场景里要建哪些物体
2. 每个物体要挂哪些组件
3. UdonSharp 脚本写什么
4. 我应该怎样测试
```

这段问题里有几个关键点：

- 说明环境：VRChat World、Unity、UdonSharp；
- 限制范围：最简单的门、先不做同步；
- 要求结果：最小可运行步骤；
- 指定输出结构：物体、组件、脚本、测试。

你给 AI 的边界越清楚，它越像搭档。你只说「帮我做一个超酷的门」，它就开始自由发挥。

## 用 AI 读官方文档

VRChat 和 Unity 的官方文档很重要，但新手直接读会累。

你可以把官方页面链接发给 AI，然后这样问：

```text
请只根据这个官方页面回答，不要补充你记忆里的内容：
https://creators.vrchat.com/worlds/components/vrc_scenedescriptor/

我刚开始做 VRChat World。
请用新手能懂的话解释 VRC Scene Descriptor 是什么，为什么每个世界都需要它。
最后列出我现在最该关心的 3 个字段。
```

这类问题有两个好处。

第一，它把 AI 的回答限制在官方资料附近。第二，它让文档从「一整页术语」变成「我眼下该懂什么」。

以后你遇到 `VRC_Pickup`、`VRCObjectSync`、`VRCSpatialAudioSource` 这些组件，也可以这样读。

## 用 AI 拆报错

报错不要只复制最后一行。尽量给完整上下文。

你可以这样问：

```text
我在 Unity 里做 VRChat World，使用 UdonSharp。
我点击 Build & Test 后失败了。
下面是 Console 里的报错，请你帮我判断可能原因，并按「最可能」「次可能」「需要更多信息」分类。

[把完整报错贴在这里]

请不要直接让我重装 Unity。先从项目设置、组件缺失、脚本编译错误这些方向排查。
```

这个问法能避免 AI 一上来就给你大动作。很多 Unity 问题最后只是少挂了组件、脚本没编过、场景里少了 Descriptor，先从小地方查。

## 用 AI 写脚本草稿

AI 写脚本的时候，你要让它写小一点。

比如你想做一个按钮开灯，可以先问：

```text
请写一个 UdonSharp 脚本：
- 挂在一个可点击按钮上
- 玩家 Interact 时切换一盏 Light 的 enabled 状态
- 先不做多人同步
- 代码里用清楚的字段名
- 最后告诉我在 Unity Inspector 里要把哪个对象拖到哪个字段
```

拿到代码后，不急着复制。先看它有没有提到这些东西：

- 类继承 `UdonSharpBehaviour`；
- 交互方法是 `public override void Interact()`；
- 需要在 Inspector 里把灯拖进公开字段；
- 脚本只控制本地效果，其他玩家暂时看不到。

如果它没说清楚，就继续追问。追问比重开一个新问题更好，因为上下文还在。

## 从第一天开始做记录

我建议你给每个小功能留一段「实验记录」。不用很正式，像这样就够：

```text
目标：点击按钮让灯开关
今天做到：本地可以开关，其他玩家还看不到
关键组件：Light、Collider、UdonSharp 脚本
卡住的点：按钮没有 Collider 时无法点击
下次要查：多人同步变量、SendCustomNetworkEvent
```

这段记录以后很值钱。你做第二个世界的时候，会感谢现在的自己。

AI 也可以帮你整理记录。你把聊天记录、报错和最终做法贴给它，让它输出成「问题、原因、解决步骤、以后注意」四段。

## 这一章你要带走的东西

- AI 是搭档，负责查资料、拆问题、写草稿和陪你排查；
- 结果以官方文档、本地 Unity、VRChat SDK 和实际测试为准；
- 问问题时写清环境、目标、限制和输出格式；
- 第一个版本永远做小，跑起来之后再加同步、动画和细节。

下一章，我们开始装工具。那一步会有点像整理工位：先把该用的东西放好，后面做世界才不会到处找螺丝刀。
