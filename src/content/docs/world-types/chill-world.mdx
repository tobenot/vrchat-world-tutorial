Chill World 指以休息、闲聊和观看环境为主要用途的世界。它可以是一间小屋、一个公共休息厅，也可以是一处户外景观。场景是否包含脚本、机关有多少，都不能直接说明它是否适合这些用途。

## 把用途转成空间检查项

- **入口**：出生后能看见通路、主要座位或区域标识，不落在墙内或家具中。
- **尺度**：从玩家视角检查天花板、门框、桌面和座位高度。用不同身高的 Avatar 与站姿、坐姿分别测试。
- **通行**：座椅有人使用时，其他玩家仍能通过；镜子前的聚集区不堵住入口。
- **交谈**：两个人用正常语音交谈时，音乐和环境音不遮盖语音。
- **个人设置**：音乐音量、镜子、额外特效是否需要由每位玩家独立选择。

房间面积和座位数量按计划容纳的人数确定，不存在适用于所有 Chill 世界的固定数值。

### 可选方案：一间窗边小屋

先画一个包含入口、窗边座位、吧台和通路的平面图，再决定是否加入背景乐、本地镜子开关和可拿起的杯子。它们都是待制作的对象，不是每个休息空间的必备配置。

| 使用情境 | 布置与检查 |
| :--- | :--- |
| 首次进入 | 出生朝向窗边座位，吧台或主灯作为另一个可辨认的位置；不读长说明也能找到座位、出口和个人设置 |
| 再次使用 | 从入口走到同一座位，检查移动过的家具是否挡路、个人设置是否符合保存规则 |
| 公共休息厅 | 分散座位组，并在各组之间保留通路；按实际人数检查语音干扰 |
| 景观厅 | 先选主要观看方向，再放座位；检查远景是否被镜子、标牌或高家具遮挡 |

完成上述小屋后，世界简介可写成“窗边聊天与休息空间，提供个人音量、镜子开关和可复位杯子”；只列实际完成并测试的功能。

在场景副本中，只改天花板高度，例如对照 `2.4` 米与 `5` 米；保持座位、头像和观察位置相同，记录视线、可达位置与通行差异。这是尺度比较样本，不是建议把所有房间做成这两个高度。第一画面的焦点也可以比较：窗边亮、吧台亮、均匀照明各试一次，检查座位和通路是否仍可辨。

如果原清单包含多面镜子、多个传送点和一组道具，可先保留一组座位、一个本地镜子开关和一个有复位方式的杯子，跑通进入、就座、交谈、离开，再按用途补充功能。删减依据是当前原型要验证的动作，不是交互数量与停留时间之间的假定关系。

## 出生点与座位

在出生点的 Transform 上调整位置和朝向，然后用 `Build & Test` 检查实际落点。Scene 视图里朝向正确，不代表玩家落地时不会被高家具挡住视线。

座位使用 `VRC Station` 时，检查进入位置、坐下后的视高和退出位置。退出位置应有可站立的地面，不能夹在桌椅之间。没有 Station 的窗台或地毯也可以作为空间构图的一部分，不必让每件家具都承担交互。

私人小屋可以围绕一组座位布置；多人休息厅可以分成几个相互有距离的座位组。隔墙本身不会自动使 VRChat 语音隔音；需要私密谈话时，还要实测语音距离和相关音频逻辑。

## 光照与材质

先检查入口、通路、桌面和座位是否可辨认，再调整主光、环境光和局部灯的亮度与颜色。降低整体亮度可能使暗处的台阶或文字不可见，增加局部光可以单独改善这些位置。

不以某个固定 Intensity 或色温作为通用配方。相同灯光数值在不同材质、曝光和显示设备上会产生不同结果。

- 不移动且光照不变化的表面，可以按场景条件使用烘焙光照。
- 动态物体需要检查 Light Probe 等间接光来源。
- 金属或光滑表面需要合适的反射来源，例如 Reflection Probe。
- 灯要在运行中开关时，检查所用方案是否真的改变光照。仅关闭一个已烘焙的 Light，并不会自动移除 Lightmap 中的贡献。

墙、地面和家具的 Albedo、Metallic、Smoothness、Normal 应与预期表面对应。使用低光环境时，也要检查这些表面在玩家头像旁边的可读性。

### 可选练习：逐项调整暖光

在场景副本保存当前设置，并固定材质、观看位置和目标设备。先只降低主光强度，与原值对照；例如原值是 `1` 时试 `0.5`，记录入口、台阶和桌面哪些位置变暗。再单独试暖色主光；通过 `Window → Rendering → Lighting` 的 Environment 设置比较环境照明。最后只在仍看不清的角落加一盏短 Range 的 Point Light，逐步缩小范围，使它覆盖目标位置。

每改一项都从同样位置截图；使用烘焙方案时重新烘焙后再比较。不要同时改主光、环境与材质，否则难以判断变化来源。灯光类型与烘焙步骤见[光照配置](/placeness/light/)，材质通道见[材质与表面](/placeness/surfaces/)。

## 三种音乐需求分别配置

| 需求 | 播放控制 | 空间化 |
| :--- | :--- | :--- |
| 进入世界就播放的 BGM | Audio Source 的 Play On Awake，或明确的初始化逻辑 | 2D，音量不随玩家位置衰减 |
| 跨进咖啡厅边界才播放，离开停止 | 本地玩家进入 / 离开 Trigger 时调用 Play / Stop | 2D，在区域内移动不改变声源方向 |
| 室内音箱持续播放 | 持续播放或由音箱开关控制 | 3D，听者移动会改变相对方向和距离 |

[第 14 章的区域音乐](/come-alive/trigger-zones/)采用第二种方案。Trigger 决定何时播放，Spatial Blend 决定是否按空间位置表现声音，两者是独立设置。

使用 2D 音频时，把 Audio Source 的 Spatial Blend 设为 0；若有 `VRC Spatial Audio Source`，同时关闭其空间化选项。第三种方案才需要配置 3D 空间化与距离衰减。在 SDK 3.10.5 的 Advanced Options 中，Enable Spatialization 开启且 Use AudioSource Volume Curve 关闭时使用空间化器的默认衰减；开启 Use AudioSource Volume Curve 时按 Audio Source 的曲线配置。3D 音箱不会自动把声音限制在房间里，墙体也不会自动隔音。

提供本地音量或静音开关，并分别在入口、座位和区域边缘测试。Volume 的数值不能代替试听：音频文件本身的响度也会影响结果。

## 镜子与小道具

镜子可以默认关闭，由玩家本地开启。`Reflect Layers` 控制反射包含的层；例如把不需要出现在镜中的远景或特效放到合适的层并从反射中排除，再比较开镜与关镜的帧时间。反射开销还取决于分辨率、材质、头像和可见内容，不能按物体数量直接推算。VRChat 镜子不渲染 Water 层。

Pickup、按钮或小型游戏是可选功能。若加入这些物体，给它们留出使用范围、复位方式和音量控制，避免与主要通路或聊天位置冲突。静态景观本身也可以构成完整的世界内容。

## 本地状态与共享状态

镜子和音量可按玩家分别设置。若需要所有人看见同一盏灯开关、同一个道具位置，才为对应状态增加同步。需求应逐项确定，不能从“Chill”这个分类推断所有交互都无需同步。

多人测试时检查：一个玩家调整个人设置，是否意外改变其他玩家的设置；共享物体被移动后，其他客户端和后加入者看到的位置是否符合预期。

## 一份布局与测试记录

1. 画出出生点、主要座位、通路和镜子范围。
2. 给每个音源注明“全局 2D / 区域触发 2D / 固定 3D”，再注明本地或共享控制。
3. 列出目标平台与人数，用相应设备测试入口、座位和开启镜子后的表现。
4. 记录需要调整的具体位置、参数、现象和修改后的结果。

可选的小屋草图可以这样填写：入口看见窗边座位；座位区进入后播放本地 2D 雨声，离开停止；吧台的固定 3D 音箱独立持续播放。先分别试听雨声、持续音色或咖啡馆环境声等候选内容，再决定是否叠加，不把所有音轨同时铺满。至少在座位与吧台两处用正常语音交谈，记录声层、音量控制和区域边界是否符合设计。

用三问完成这张图：进入后看见什么？每个位置听见哪些声层？停留时站在哪里或坐在哪里？把答案转成待建清单，例如墙地、窗框、座椅、局部灯、区域 Trigger、两个 Audio Source、音量按钮与杯子复位点。每项注明已有资源或待制作资源，然后先验证本地流程，再增加确有需要的共享状态。

同一个按钮也可以服务不同用途：休息厅切换个人镜子，游戏提交动作请求，展厅播放作品解说。先写按钮改变什么、影响谁，再选实现；组件相同不代表同步与反馈要求相同。
