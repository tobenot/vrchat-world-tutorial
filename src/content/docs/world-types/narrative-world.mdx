Narrative World 用场景、文字、音频、动画或交互呈现故事。恐怖场景、探索短篇和密室解谜都可以采用这种形式。故事不一定要求玩家行走或解谜，也可以用静态布置、观看或阅读完成。

## 把剧情写成可检查的节点

对每个节点记录：

| 项目 | 例子 |
| :--- | :--- |
| 当前状态 | 玩家尚未找到钥匙 |
| 触发条件 | 本地玩家持有钥匙并与门交互 |
| 动作 | 打开门，显示文本，播放音效 |
| 结果状态 | 门已开启，当前章节完成 |
| 重复执行 | 不重复奖励，门保持开启 |
| 恢复方式 | 重生后保留进度，重开故事时重置 |

[区域 Trigger](/come-alive/trigger-zones/)用于检测位置事件，[门与状态](/come-alive/doors-and-states/)中的状态变量用于限制动作。位置事件不应自行代表全部剧情进度：玩家可能重复进出，也可能从其他路线到达。

## 信息放在哪里

环境、旁白和文字可以互相补充。例如烧黑的墙面能表现受损环境，文字或对话能提供无法从视觉确定的日期、人物或原因。

如果某条信息是推进剧情的必要条件，应检查它是否可能因观看方向、音量、语言或移动速度而错过。可选细节则不必强制所有玩家停留。

- 关键音频配字幕或可回放记录。
- 长文字分段显示，并保留退出阅读的方式。
- 场景线索与操作提示区分清楚，装饰物不必都能交互。
- 使用颜色指引时，同时提供形状、灯位或文本线索。

### 可选练习：把一句故事变成三张故事板

先写一句话故事，例如：“回到久无人住的老屋，找到留下的记录，确认住户离开的原因。”只搭入口、旧房间和记录所在的区域；其余背景可以放在照片、物件或可选纸条中，不要求全部做成必经房间。

把文字信息分别转成可观察线索，再注明哪些事实仍需明确说明：

| 想表达的信息 | 可选场景线索 | 仅凭外观还不能确定什么 |
| :--- | :--- | :--- |
| 曾发生火灾 | 烧黑墙面、地面焦痕、受损家具 | 时间、起因和当时在场的人；用可读取的记录补充 |
| 长期无人照料 | 积灰桌面、枯植物、停在旧日期的日历 | 准确离开日期；日历只是线索，需与便条或记录核对 |
| 某个房间值得调查 | 半开门、门缝光、断续声音、可辨认的房号 | 门内内容；不能只依靠声音或冷暖颜色指路 |

故事板记录感官信息与动作，不能用一个“已触发”布尔值替代：

| 节点 | 看见什么 | 听见什么 | 能做什么 | 新确认的信息 |
| :--- | :--- | :--- | :--- | :--- |
| 入口 | 灰尘、枯植物、通向旧房间的开口 | 可选环境声，静音也可找到出口 | 看房号与日历，选择继续 | 房间缺少日常照料，离开原因仍未知 |
| 旧房间 | 半开门和可读取的便条 | 可选录音，同时有文字稿 | 查看便条，主动播放或跳过录音 | 确认日期，得到记录所在位置 |
| 记录处 | 完整记录、明确的结束牌 | 可选结束音 | 读记录、返回、重开 | 确认离开原因，知道主线已结束 |

为每个节点画一张草图，把关键线索与可选细节用不同符号标出。按“只看必要信息”和“查看全部细节”各走一次，核对揭示顺序：关键原因是否过早露出，结尾是否仍有缺失。长走廊可以作为距离或阻隔的表达方案，但应测量重复行走成本，不假定所有人都会产生同一种感受。与节点无关的提示窗或音乐可以暂时停用，比较是否更容易辨认当前线索。

## 谜题与恢复

需要解谜时，写清物品、可操作对象、成功条件和失败后的状态。对能被移动的关键物品提供复位途径，检查它掉出地图、被另一玩家持有或被重复提交时的结果。

提示可由玩家主动请求，也可以按已发生的动作逐步提供。若设置跳过功能，界面写“跳过谜题”即可，不需要给玩家表现作评价。

可选的三级提示例：第一次请求只说“检查桌面”；第二次突出便条轮廓并显示文字；第三次说明便条上哪项信息用于开锁。若改为停留计时触发，计时只在该谜题未解且玩家处于区域时累计，离开、解开或重开时按规则清除，并提供关闭自动提示的选项。每一级记录已显示状态，避免来回进入反复叠播。组队测试时让一人读线索、一人操作，检查彼此能否传达解题所需信息。

重开故事与重新进入当前区域是不同动作。重开时要一致地重置变量、门、动画、音频和物品，避免场景处于新旧状态混合的情况。

## 本地故事与共享故事

**本地进度**：每个玩家独立触发剧情。条件判断使用本地玩家过滤，个人字幕和音频不发送全局事件。但场景里仍会看见其他玩家，应检查一个玩家开门、另一个玩家尚未开门时的通行和显示。

**共享进度**：组队玩家共同推进。指定写入方，保存剧情阶段、关键物品和门状态；后加入者按当前状态恢复，或留在等待区。组队人数较少不等于无需同步。

实例容量限制人数，Friends、Group 等实例类型限制访问范围；这些设置不会自动处理剧情进度。世界说明应列出支持的人数和中途加入方式。

## 动画、声音与光照

Animator 可控制门、道具或角色动画；Timeline 可编排一段连续事件。场景中使用的组件和脚本调用仍需符合 VRChat 的支持范围，并在客户端验证。

可选的段落表是“玩家按继续 → 角色在可观察位置出现 → 台灯降低亮度 → 一扇布景门关闭 → 显示记录提示”。在表中给每步写开始条件、持续时间和跳过后的终态；布景门不封住唯一出口，台阶照明不随表演灯一起熄灭。首次恢复进度可以直接显示终态，不把整段演出当作历史事件重放。

需要 Timeline 时，先确认项目中已有对应包。在场景副本选中用于承载演出的 GameObject，打开 `Window → Sequencing → Timeline`，选择 `Create` 并保存 Timeline 资产；Unity 会建立 Playable Director 与相应绑定。轨道仍需加入实际动画片段并绑定到待控制对象，创建空资产不会自动演出。具体操作见[创建 Timeline 资产和实例](https://docs.unity3d.com/Packages/com.unity.timeline@1.7/manual/wf_instance.html)。先在编辑器检查轨道与引用，再在 `Build & Test` 中检查触发、跳过、重新进入和复位；这两种测试分别记录。

场景动画不需要接管玩家的视角。优先让事件在玩家可以自行观察的位置发生，保留移动、暂停或跳过选项。Station 可以安排观看位置，但固定座位或禁止退出不能保证消除晕动，也不应作为默认的舒适度方案。

例如让“查看下一段”按钮推进一次演出，玩家自行站到能看到角色的位置再按；按下后显示当前阶段，并禁止同一阶段重复启动。不要把“主动推进”实现成强制拉动摄像机。

剧情灯光变化要检查实际来源。烘焙照明不会因关闭灯组件而从 Lightmap 消失。音效触发也要检查重复进入时是否叠播，离开或跳过段落时是否停止。

暗场景在不同显示器、头显、材质和平台上的表现可能不同。用目标设备检查台阶、出口、提示和关键道具，不以统一的低亮度数值代替测试。后处理的可用性取决于平台；不要把 VRChat 世界等同于任意 Unity 渲染管线项目。

搭建时若暗到无法摆放物体，可在 Scene 视图临时关闭 Scene Lighting，用编辑器的观察光操作；结束后重新启用它检查场景光照。这个开关只影响 Scene 视图，不会改变构建中的照明，不能代替客户端亮度测试。参见 [Unity Scene 视图工具栏](https://docs.unity3d.com/2022.3/Documentation/Manual/ViewModes.html)。

## 按故事形式检查设计

| 可选形式 | 设计产出 | 重点验证 |
| :--- | :--- | :--- |
| 恐怖或悬念场景 | 关键线索、效果提示与可关闭的附加效果 | 暗处通路、静音线索、退出和跳过 |
| 密室解谜 | 谜题条件、渐进提示与物品复位表 | 重复提交、提示使用和关键物品丢失 |
| 剧情短篇 | 三节点故事板与结束信号 | 快速通过和完整阅读都能确认必要事实 |
| 多结局故事 | 每次选择、分支条件与结局对应表 | 每条分支可达，重开清除旧选择 |
| 空间探索 | 可绕行区域、观察位置与可选细节图 | 不按预定顺序移动时仍可返回和辨认出口 |

这些形式可以组合；比较的是需要制作和验证的内容，不是技术或审美等级。

## 叙事流程测试

为每条分支记录预期到达的结局，再执行：

1. 按设计顺序完成一次。
2. 跳过可选内容并快速移动。
3. 在节点前后反复进出区域。
4. 重生、重开，或在剧情中途加入另一个客户端。
5. 关闭音频、切换语言，在桌面和 VR 检查必要信息。

记录触发节点、实际状态和缺失信息。体验时长通过测试测量，不把某个时长范围或推荐率当作叙事世界的通用标准。

再请没有读过故事板的人完整体验一次，作者先不口头补充。记录对方实际找到的线索、停留位置、误认的可操作物与到达的结局，用这些记录修改提示，再复测。
