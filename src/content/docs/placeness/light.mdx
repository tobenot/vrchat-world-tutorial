灯光的计算方式影响画面、运行时开销，以及开关灯后哪些部分会变化。第 9 章使用 Light 和材质调节外观；这里把静态房间的预计算光照与动态对象的受光分开配置。

## 三种 Light Mode

| 模式 | 计算方式 | 使用条件 |
| :--- | :--- | :--- |
| `Realtime` | 运行时计算直接光和所启用的阴影 | 需要移动或改变直接照明的灯；开销与灯型、范围、阴影及受光物体有关 |
| `Baked` | 将光照预计算到 Lightmap 和探针 | 固定照明；运行时关闭 Light 组件不会移除已烘焙的贡献 |
| `Mixed` | 组合预计算与实时部分 | 结果取决于 Lighting Mode；不能把它当成完全实时的开关灯 |

本例将固定装饰灯设为 Baked，需要由按钮控制的局部灯设为 Realtime。若主光源使用 Mixed，需明确哪些光照和阴影已经烘焙。

直接光从光源到达表面；间接光经过其他表面反射后到达。全局光照（GI）处理场景中的光照传播，烘焙可以预先计算这些结果。

## Emission 何时照亮周围

如果制作霓虹灯时字牌亮了、墙没有被照亮，可能只是材质的 Emission 自亮，没有实际灯光，也没有有效的烘焙发光贡献。

- 需要运行时开关、改变颜色并照亮附近表面时，可使用 Realtime Light；Emission 用于字牌自身的外观。
- 需要固定的发光贡献时，可在支持的 Shader 中启用 Emission，设置适当的 GI 模式，使物体参与烘焙，并重新生成光照。
- 烘焙完成后，运行时修改 Emission 不会自动重算已经存入 Lightmap 的照明。
- Bloom 是画面上的泛光效果，不能据此判断墙面是否实际接收了光。

使用 Unity Standard Shader 时，检查 Emission 的 Global Illumination 设置、发光物体的 `Contribute GI`、场景的 Baked GI，以及接收表面的配置。具体条件见 [Unity Emission 文档](https://docs.unity3d.com/2022.3/Documentation/Manual/StandardShaderMaterialParameterEmission.html)。

## 标记参与烘焙的物体

GameObject 顶部的 `Static` 下拉是一组独立标记，不是一个适合全部物体的总开关：

- `Contribute GI`：参与全局光照预计算
- `Reflection Probe Static`：参与 Baked Reflection Probe 的捕获
- `Batching Static`：参与静态批处理
- `Occluder Static` / `Occludee Static`：用于遮挡剔除

1. 选中固定地板、墙、天花板和家具。
2. 按用途勾选 `Contribute GI`，需要烘焙反射时勾选 `Reflection Probe Static`。
3. 对需要接收 Lightmap 的 Mesh Renderer 检查 `Receive Global Illumination` 设置。
4. 门板、Pickup 等运行时移动的物体不要按静态 Lightmap 物体配置；为它们检查 Light Probe 设置。

会被启用或禁用的物体也需要判断：关闭物体不会自动删除它在其他表面上留下的烘焙阴影或间接光。是否参与烘焙取决于这种残留是否符合设计。

## 生成 Lightmap

打开 `Window → Rendering → Lighting`，创建或指定 Lighting Settings 资产。不同 Unity 版本的字段分组可能不同。

小房间原型可从以下数值开始：

```text
Baked Global Illumination   开启
Lightmapper                 Progressive CPU 或可用的 Progressive GPU
Direct Samples              32
Indirect Samples            256
Bounces                     2
Lightmap Resolution         20 texels per unit
Lightmap Padding            2
Lightmap Size               1024
Compress Lightmaps          开启
```

这是比较烘焙结果的起点。更高分辨率增加内存与包体，更多采样增加烘焙时间；需要按具体瑕疵调整。

### Mixed Lighting 的模式

- `Baked Indirect`：烘焙间接光，直接光和阴影仍有实时开销
- `Shadowmask`：结合实时直接光、烘焙间接光与阴影遮蔽数据；具体实时阴影范围还受质量设置影响
- `Subtractive`：静态直接光和间接光均可烘焙，动态对象的受光与阴影表现有额外限制

模式必须与渲染管线、目标平台和 Shader 兼容。不能只凭 PC / Android 名称就认定某种模式适用于全部场景。

点击 `Generate Lighting`，等待烘焙完成并保存场景和生成的数据。烘焙耗时取决于场景规模、分辨率、采样和硬件。

### 按现象排查

| 现象 | 检查项 |
| :--- | :--- |
| 全部过暗 | 环境光来源、灯光模式、曝光、材质是否接收光照 |
| UV 接缝出现亮线或黑线 | Lightmap UV 是否重叠、边距与分辨率是否足够 |
| 表面斑点或噪声 | 间接光采样、降噪与小面积高亮发光源 |
| 个别物体未接收烘焙结果 | Contribute GI、Receive GI、Shader 与 UV 配置 |
| 结果与刚修改的场景不符 | 是否完成新烘焙、是否保存了正确场景与 Lighting Data |

导入模型时，可在 Model Importer 的 `Generate Lightmap UVs` 生成用于光照的 UV，但生成后仍要检查接缝和重叠。只有确认旧数据需要重建时才清除 Baked Data。

## Light Probe：动态对象的环境光

动态对象不能直接使用固定在静态表面上的 Lightmap。Light Probe Group 在空间中记录预计算光照，支持探针的 Renderer 根据附近探针插值取样。

1. 创建 `Light → Light Probe Group`。
2. 在 Inspector 点击 `Edit Light Probes`，用 `Add Probe` 添加，`Duplicate Selected` 复制，`Delete Selected` 删除选中的探针；在 Scene 视图移动它们，完成后退出编辑模式。
3. 覆盖玩家和 Pickup 活动的体积，包括不同高度；不要只摆成一个平面。
4. 在明暗变化处加密，避免探针位于墙内。
5. 重新烘焙，并让动态物体经过窗口、走廊和阴影区域。

探针的间距应由光照变化决定。可以从几米间隔开始；均匀受光区域减少冗余，变化剧烈的位置增加采样。头像的最终外观还受它自己的 Shader 和 Renderer 配置影响，不能保证所有头像以相同方式使用探针。

### 查看探针之间的连线

Unity 2022.3 的 Light Probe Group Inspector 提供 `Show Wireframe`：开启后，在 Scene 视图检查探针之间的连线与覆盖体积。至少分上下两层布点，检查连线是否跨过厚墙、是否在门口把明暗两区过早混合。不要把旧资料中的 `Light Probe Visualization → Tetrahedrons` 当作当前版本必有的同名菜单。

选择一段受光均匀的区域，先保存探针布局，再减少其中一组冗余点并重烘。让同一动态测试物沿同一路线移动，比较颜色是否连续；出现不符合预期的跳变时，恢复点位或在过渡处补点。连线显示的是插值结构，不能仅凭探针看起来颜色相近就认定删点无影响。[Unity 2022.3：Light Probe Group](https://docs.unity3d.com/2022.3/Documentation/Manual/class-LightProbeGroup.html)

## Reflection Probe：环境反射

`Metallic` 描述金属属性，`Smoothness` 描述表面光滑度，两者不是同一个参数。高 Smoothness 的非金属也能产生清晰反射。

Reflection Probe 从某个位置捕获环境并保存为 Cubemap。使用兼容 Shader 的物体可以显示这份环境反射。

1. 创建 `Light → Reflection Probe`，将 Type 设为 `Baked`。
2. 将探针放在需要代表的房间内，调整 `Box Size` 覆盖受影响区域。
3. 从 `Resolution = 128` 开始检查反射细节与内存。
4. 在封闭房间中可试用 `Box Projection`，以盒子近似修正反射视差。
5. 点击探针的 Bake，或使用 Lighting 面板中的反射探针烘焙命令。

Box Projection 不是精确的实时几何反射。两个空间的环境差别较大时，可分别放置 Probe；过渡混合是否生效还取决于 Renderer 和 Shader 的设置。

## 实时灯与烘焙灯共同使用

需要按按钮改变照明时，可以保留一盏 Realtime Light：

- 调整 Range，限制实际需要照亮的范围
- 关闭不需要的实时阴影
- 在多个灯同时影响同一片物体时测量开销
- 检查关闭实时灯后，是否仍留有不应存在的烘焙亮斑

没有适用于全部世界的「实时灯最多四盏」硬限制。性能取决于实际渲染路径、像素覆盖、阴影、材质和目标设备。

## 何时重新烘焙

改变参与烘焙的几何、灯光或材质，可能使旧数据失效：

- 移墙、加家具：检查 Lightmap、探针和遮挡关系
- 改 Albedo 或 Emission：间接反射和发光贡献可能变化
- 改 Smoothness 或 Metallic：检查 Reflection Probe 捕获与最终反射
- 改 Probe 位置或范围：重新检查并烘焙对应数据

保存一组修改前后的截图，以同一相机位置比较。烘焙是否有价值应由所需画面和运行时开销决定，不能据此给世界类型或作者水平分等级。

## 对照练习与检查清单

在场景副本做三组独立实验，固定模型、材质、相机位置、曝光、目标设备和画质设置。每组记录改动的字段、截图与可取得的帧时间；没有运行时测量工具时，不用编辑器数字代替客户端数字。

1. **实时光与烘焙光**：A 版把待比较的固定灯设为 Realtime，在副本中清除旧 Baked Data，并关闭 Realtime GI，记录墙根和遮挡处。B 版保持灯的位置、颜色和强度，把这些固定灯设为 Baked，按本章为接收表面设置 Contribute GI、Receive GI，并生成光照。只比较这一组照明方案，不同时换材质、加镜子或改变曝光。烘焙后的间接光差异和实时成本分别记录，不能保证两版像素一致。
2. **动态物体取探针光**：新建一个未标静态的球，赋予支持探针的受光材质。先把它的 Mesh Renderer 的 Light Probes 设为 Off，再设为 Blend Probes，使用同一份已烘焙探针数据，在窗口、房间中心、阴影区三个坐标分别截取画面。要在客户端移动它，可按[拾取物配置](/come-alive/pickup-and-throw/#第二步添加刚体和-pickup)添加 Pickup。这个实验只改变该 Renderer 是否采样探针，不需要用未核对的「固定 50 个探针」配额。
3. **反射来源**：新建球并赋予 Standard 材质，设 Metallic `1`、Smoothness `0.95`，放在本章已烘焙的 Reflection Probe 范围内。保持 Lighting 的 Environment Reflections 使用同一 Skybox，只将球的 Mesh Renderer 的 Reflection Probes 从 Off 改为 Blend Probes，观察由环境反射改为局部探针后的图案。再单独比较 Probe 的 Box Projection 开关；不移动球或相机来掩盖差异。

Mesh Renderer 的探针选项与 Shader 支持条件见[Unity 2022.3：Mesh Renderer](https://docs.unity3d.com/2022.3/Documentation/Manual/class-MeshRenderer.html)。
