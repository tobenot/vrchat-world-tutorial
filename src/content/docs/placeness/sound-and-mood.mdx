声音配置需要分别回答两个问题：什么时候播放，以及播放时是否随听者的位置改变方向和音量。

第 14 章的区域音乐采用本地 Trigger 控制：玩家跨入咖啡厅边界时播放，离开时停止，音源为 2D。本章保留这个模型，并说明另外两种独立需求。

## 三种方案的区别

| 需求 | 播放条件 | Audio Source | 移动时的结果 |
| :--- | :--- | :--- | :--- |
| 进入世界就播放的全局 BGM | `Play On Awake` | 2D，循环 | 不因玩家在世界中的位置改变方向和距离音量 |
| 跨过咖啡厅门槛才播放的区域 BGM | 本地玩家进入 / 离开 Trigger 时 `Play` / `Stop` | 2D，循环，关闭 `Play On Awake` | 区域内移动不产生声源方向和距离变化；边界由脚本判断 |
| 室内音箱持续播放的音乐 | `Play On Awake`，不接区域开关 | 固定位置的 3D 声源，循环 | 靠近、远离或绕过音箱时，相对方向和距离发生变化；室外也可能听见 |

**Trigger 决定何时播放，Spatial Blend 决定是否按空间位置处理声音。** 把音源改成 3D 不会自动把声音限制在某个 Trigger 内。墙和关闭的门也不会自动阻挡 Audio Source；若需要遮挡、低通滤波或隔音，需另行设计并测试。

## Audio Source 与空间化组件

`Audio Source` 是 Unity 的播放组件，音频文件导入后成为 `AudioClip`。添加 `VRC Spatial Audio Source` 时，SDK 会同时确保物体上有 Audio Source。`VRC Spatial Audio Source` 配置 VRChat 的空间化与衰减参数，两者配合使用。

Audio Source 的主要字段：

- `Audio Clip`：要播放的音频
- `Loop`：播放到末尾后循环
- `Play On Awake`：组件启动时自动播放，适合持续播放的音源
- `Volume`：基础音量；同一值在不同音轨上的听感可能不同
- `Spatial Blend`：`0` 为完全 2D，`1` 为完全 3D
- `Doppler Level`：相对运动造成的音调变化强度；不需要这种效果时设为 `0`

空间化配置参考官方 [VRC Spatial Audio Source 文档](https://creators.vrchat.com/worlds/components/vrc_spatialaudiosource/)。下表采用已核查的 Worlds SDK 3.10.5 Inspector；高级字段位于 `Advanced Options`：

| 字段 | 含义与条件 |
| :--- | :--- |
| `Gain` | 世界可设 `0–24 dB`，默认 `10 dB`；调音时同时检查它与 Audio Source 的 Volume |
| `Near` | 开始衰减的近端距离，默认 `0` 米 |
| `Far` | 衰减到静音的远端距离，默认 `40` 米 |
| `Volumetric Radius` | 让远处声源呈现较大体积，默认 `0`；数值必须小于 Far |
| `Use AudioSource Volume Curve` | 开启后使用 Audio Source 的音量曲线；关闭时采用空间化器的默认衰减 |
| `Enable Spatialization` | 控制空间化；制作完全 2D 音频时关闭，并把 Spatial Blend 设为 0 |

在 SDK 3.10.5 中，启用 `Enable Spatialization` 并关闭 `Use AudioSource Volume Curve` 使用空间化器默认衰减；开启后者则使用 Audio Source 的音量曲线。官方网页仍出现 `Use Spatializer Falloff`、`Use Spatialized Audio` 等旧称，当前 Inspector 没有这两个同名复选框。调整 Near / Far 时要先核对实际采用哪一套曲线。

不要把 Unity 的 `Max Distance` 一概理解成静音边界：Unity 自带曲线在最大距离之外可能维持末端音量。判断结果要结合所选曲线和 VRChat 空间化设置。

## 方案一：全局自动播放的 2D 音乐

1. 新建空物体 `Audio_Background`，添加 Audio Source 和 VRC Spatial Audio Source。
2. 指定音轨，勾选 `Loop` 和 `Play On Awake`。
3. 将 `Spatial Blend` 设为 `0`，关闭空间化组件中的空间化选项。
4. 将 `Volume` 从较低值开始调，例如 `0.2`。这是本例试音起点，不是适用于所有音轨的响度标准。
5. `Build & Test` 后，分别站在房间各处、室外和不同楼层试听。

预期：场景加载并启动该音源后开始播放；在没有其他脚本调整音量的条件下，走远或转头不产生距离衰减和方位变化。

### 本地静音开关

静音开关只改变当前玩家听到的音乐，不同步给别人：

```cs title="MusicSwitch.cs"
using UdonSharp;
using UnityEngine;

public class MusicSwitch : UdonSharpBehaviour
{
    public AudioSource musicSource;

    public override void Interact()
    {
        if (musicSource == null) return;
        musicSource.mute = !musicSource.mute;
    }
}
```

把脚本挂在带 Collider 的按钮上，将音乐 Audio Source 拖入 `Music Source`。`mute` 保留播放进度，解除静音后听到当前播放位置。它不是暂停，也不是释放音频资源。

若需求是暂停后接着播放，使用 `Pause()` / `UnPause()`；若需求是停止后重新开始，使用 `Stop()` / `Play()`。不要用组件 `enabled` 的开关代替暂停语义。对区域音乐使用独立的 `mute` 开关，也可避免玩家关闭音乐后被 Trigger 再次自动解除静音。

## 方案二：区域触发的本地 2D 音乐

第 14 章的 [区域触发教程](/come-alive/trigger-zones/) 已给出脚本与挂载步骤。配置应保持一致：

- 咖啡厅区域使用勾选 `Is Trigger` 的 Box Collider，覆盖整个需要播放的室内空间；只放薄门槛会让跨过门槛后立刻触发 Exit
- Audio Source 保持启用，关闭 `Play On Awake`，勾选 `Loop`
- `Spatial Blend = 0`，空间化关闭
- `OnPlayerTriggerEnter` 只处理 `player.isLocal`，进入时调用 `Play()`
- `OnPlayerTriggerExit` 只处理本地玩家，离开时调用 `Stop()`

预期测试：

1. 出生点在区域外时，音乐不播放。
2. 本地玩家跨过门槛进入区域后开始播放。
3. 在区域内走近窗边或房间另一端，音乐不会转向固定音箱，也不会随距离减小。
4. 本地玩家离开区域后停止；再次进入从头播放。
5. 第二位玩家进出区域，不改变第一位玩家的音乐。

本例把出生点放在区域外，以便验证进入事件。若允许直接出生或传送到区域内，需要单独测试初始播放状态和事件顺序。若改用淡入淡出，脚本仍在本地控制 Volume；淡化不等于空间化。

## 方案三：持续播放的固定室内 3D 声源

这个方案用于「收音机或音箱一直在播放」的需求，与区域触发方案分别配置：

1. 新建空物体 `Audio_Radio`，放在室内一个明确位置；已有音箱模型时再与模型对齐，保持这个声源位置固定。
2. 添加 Audio Source 和 VRC Spatial Audio Source，指定音轨，勾选 `Loop`、`Play On Awake`。
3. 设 `Spatial Blend = 1`，启用空间化；不需要多普勒效果时设 `Doppler Level = 0`。
4. 在 `Advanced Options` 中保持 `Enable Spatialization` 开启、`Use AudioSource Volume Curve` 关闭，可从 `Near = 0`、`Far = 8`、`Volumetric Radius = 0` 开始试听。
5. 不把这个音源交给咖啡厅 Trigger 的 Play / Stop 脚本。

在 VRChat 客户端测试：

- 靠近音箱时音量增加，远离时按曲线衰减
- 从音箱左侧走到右侧，听者与音箱的相对方向变化；声源自身没有换位置
- 转头时，听者朝向变化会改变空间化的方位表现
- 走到室外但仍在有效距离内时，可能仍听到音乐；墙体不自动隔音

如果室外完全不能听到才符合需求，应使用区域开关或其他明确的隔音逻辑。不能用「改成 3D」替代这个播放条件。

### 体积半径的使用条件

`Volumetric Radius` 用于需要听起来具有面积的远处声源，例如远处无法走近的瀑布。官方建议听者不要靠近这个半径，并要求它小于 Far。玩家可以走到中心的火堆、收音机或花园，不适合直接用大半径覆盖整个可活动区域。

可走入的环境音区域可以采用区域触发 2D，或布置多个低音量 3D 声源并检查叠加。选择取决于是否需要明确方向和距离变化。

## 环境音、混响与一次性音效

雨、风、设备噪声都可以按上述三类需求配置，不存在一种固定的「环境音设置」。例如，整段立体声雨声可作为本地区域 2D 音频；窗外水管滴水可作为固定 3D 音源。

`Audio Reverb Zone` 为处于区域内的 Audio Listener 提供混响。是否作用于某个 Audio Source，还取决于该音源的混响发送与 bypass 设置。混响不会自动实现隔墙遮挡，也不能据此保证其他玩家的语音一定带上相同混响。

可选对照：在场景副本中新建 `Reverb_Test`，添加 Audio Reverb Zone，选择一个非 Off 的 Reverb Preset；先用 Min Distance `2`、Max Distance `4`，在 Scene 视图检查球形范围。使用已经配置的持续 3D 测试音源，核对其 Reverb Zone Mix 与 Bypass Reverb Zones 设置，让听者从范围外走到范围内，再只禁用 Reverb Zone 重走一次。记录实际音轨的混响差别，不用球形半径冒充与房间墙体完全一致的隔音边界；多人语音另行实测。

按钮和门的短音效可用 `PlayOneShot`：

```cs title="LocalClickSound.cs"
using UdonSharp;
using UnityEngine;

public class LocalClickSound : UdonSharpBehaviour
{
    public AudioSource sfxSource;
    public AudioClip clickSfx;

    public override void Interact()
    {
        if (sfxSource != null && clickSfx != null)
            sfxSource.PlayOneShot(clickSfx);
    }
}
```

新建同名 U# 脚本并挂在带 Collider 的按钮上。创建独立 Audio Source，关闭 Play On Awake 与 Loop；按本章 2D 或 3D 配置空间化，再将它拖入 `Sfx Source`，将获准使用的短音轨拖入 `Click Sfx`。这里音轨由 `PlayOneShot` 参数提供，Audio Source 的 Audio Clip 槽可以留空。保存并检查编译后，Build & Test 分别点一次、快速连点、让第二位玩家点击；本例只在发起 Interact 的客户端播放。

`PlayOneShot` 不会停止该 Audio Source 上其他已播放的声音。连续触发可能叠加音量，需要测试点击频率和最大响度。

## 可选：区域 2D 音乐的淡入淡出

这个变体仍是本地 Trigger 控制的 2D 音乐，只把边界处的立即播放／停止改成渐变。它不接到上面的独立持续 3D 音源，也不产生自动隔墙效果。先在场景副本中停用原 `MusicZone`，同一个音源只保留一个播放控制器：

```cs title="LocalZoneFade.cs"
using UdonSharp;
using UnityEngine;
using VRC.SDKBase;

public class LocalZoneFade : UdonSharpBehaviour
{
    public AudioSource musicSource;
    public float insideVolume = 0.2f;
    public float fadeSeconds = 1f;
    private bool inside;

    private void Start()
    {
        if (musicSource == null) return;
        musicSource.volume = 0f;
        musicSource.Stop();
    }

    public override void OnPlayerTriggerEnter(VRCPlayerApi player)
    {
        if (!Utilities.IsValid(player) || !player.isLocal) return;
        if (musicSource == null) return;
        inside = true;
        if (!musicSource.isPlaying) musicSource.Play();
    }

    public override void OnPlayerTriggerExit(VRCPlayerApi player)
    {
        if (!Utilities.IsValid(player) || !player.isLocal) return;
        inside = false;
    }

    private void Update()
    {
        if (musicSource == null) return;
        float level = Mathf.Clamp01(insideVolume);
        float target = inside ? level : 0f;
        float step = level * Time.deltaTime / Mathf.Max(0.01f, fadeSeconds);
        musicSource.volume = level <= 0f
            ? 0f : Mathf.MoveTowards(musicSource.volume, target, step);
        if (!inside && musicSource.volume <= 0f && musicSource.isPlaying)
            musicSource.Stop();
    }
}
```

把脚本挂在覆盖整片播放区域、勾选 Is Trigger 的 Box Collider 上；Music Source 指向启用的音源，Loop 开启、Play On Awake 关闭、Spatial Blend 为 `0`，Advanced Options 中 Enable Spatialization 关闭。Spawn 放在区外，Inside Volume 设为 `0.2`、Fade Seconds 设为 `1`，保存、检查 Console 编译结果后执行 Build & Test。

进入后音量渐升，离开后渐降到零再 Stop。淡出未结束就返回时，从当前音量回升且不重新开播；完全停止后再进入，则从头播放。用同一音轨比较 Fade Seconds `0.2 / 1 / 3`，一次只改时长；再测试快速往返和第二位玩家进出。沿用 MusicSwitch 的 mute 不会被此脚本解除。出生或传送到区域内部、多个重叠区域仍需单独处理，不能把这个单区域练习当作完整混音系统。

一个可选的混音顺序是：先单独配置需要的区域雨声，再单独配置固定滴水声，最后决定是否加全局音乐；每加一层，都在相同站位比较单独与叠加结果，并复测语音和提示音。全局底声、区域声和点声源都不是必填项，也不要求已有壁炉、家具或音轨。

## 调音与检查

使用同一段音轨，分别测试三种配置。先一次只启用一个方案，确认行为，再测试混音：

- [ ] 播放开始和停止的条件符合需求
- [ ] 2D 音源的 Spatial Blend 与空间化开关一致
- [ ] 3D 声源在近处、远处、转头和室外位置的表现符合预期
- [ ] 背景音开启时，语音和操作提示仍可辨认
- [ ] 玩家可以本地静音或调节背景音量
- [ ] 多段环境音叠加时没有异常增响
- [ ] 桌面端与目标 VR 设备均试听过
- [ ] 音轨的使用与分发许可允许打包进世界
