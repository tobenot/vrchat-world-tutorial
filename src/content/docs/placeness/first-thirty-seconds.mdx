出生区决定玩家加载场景后的初始位置和朝向。检查目标是：落在可站立的地面上、能看见可走的方向，并能识别世界名称和必要操作。

## 配置 Spawn 的位置与朝向

找到第 5 章的 `Spawn` 空物体。它的 Transform 被填入 `VRC Scene Descriptor` 的 `Spawns` 数组。

使用 `Align Player With Spawn Point` 时，玩家朝向与 Spawn 的旋转对齐，Scene 视图中的蓝色箭头表示本地 Z 轴正方向。`Align Room With Spawn Point` 对齐的是 VR 玩家现实房间的 room-scale 空间；两者不能混为「保持朝向不变」。本例采用前一种。

做一组对照：

1. 将 `Spawn` 的 Rotation Y 设为 `0`，执行 `Build & Test`，记录初始画面。
2. 将 Rotation Y 改为 `180`，重新构建测试。
3. 对照画面中入口、可通行地面、说明牌的位置。
4. 调整 Spawn，避免出生在墙内、地板下或关闭的门后。

测试头部空间时使用不同视高。上方预留 `2` 米可作为房间原型的起点，但不能覆盖所有头像尺寸。

## 多个出生点

多名玩家使用同一个落点时，头像可能重叠。可以增加出生点，也可以调整 `Spawn Radius`，使落点在半径内分散。半径覆盖范围必须仍是可站立的地面。

1. 复制 Spawn，创建 `Spawn_A`、`Spawn_B`、`Spawn_C`。
2. 在入口附近分开摆放，例如相距 `1.5` 米，并检查各点面向同一条主要路线。
3. 将 Transform 填入 `Spawns` 数组。
4. 按需求设置 `Spawn Order`。

| 选项 | 作用 |
| :--- | :--- |
| `First` | 使用第一个出生点 |
| `Random` | 随机选择出生点，不保证各点均匀分配 |
| `Sequential` | 按数组顺序使用出生点 |
| `Demo` | 将出生点作为 room-scale 空间中心，玩家现实位置的偏移会影响落点 |

`Spawn Radius = 0` 表示使用指定位置。不要用随机半径覆盖楼梯边缘、落差或传送门。

`Object Behaviour At Respawn` 控制 Pickup 掉到重生高度以下时是销毁还是回到初始位置，不是「玩家重生时把所有 Pickup 归位」。

## 欢迎牌只写已存在的功能

在入口设置一块 World Space Canvas，显示世界名、可用功能与出口方向。不要写场景里尚未实现的功能。

1. 创建 `UI → Canvas`，将 `Render Mode` 改为 `World Space`。
2. 将 Rect Transform 的 Width / Height 设为 `400 / 200`，Scale 设为 `0.005, 0.005, 0.005`。最终宽度为 `2` 米。
3. 将牌子放在 Spawn 前方约 `3` 米处，调整旋转使文字正对入口。
4. 在 Canvas 下创建 `UI → Text - TextMeshPro`，按提示导入 TMP Essentials。
5. 添加深色底板或选择足够对比度的文字颜色，并在客户端检查实际阅读距离。

例如：

```text
Moonlight Room / 月光小屋
Light switch on the left / 灯开关在左侧
Exit on the right / 出口在右侧
```

TMP 默认字体不包含所有中文。固定文字可用 Font Asset Creator 导入具有所需字符的字体；也可按 [VRChat 官方 TMP 文档](https://creators.vrchat.com/worlds/components/textmeshpro/) 配置客户端 fallback 字体。编辑器显示方框不代表客户端一定相同，两处都需验证。

## 让行走路线可辨认

出生区的视线中可以包含目的地、开口和路径标识。它们提供方向信息，但不能保证玩家一定按设计路线移动。

- 用灯光亮度或颜色差异标出入口、开关或展示物
- 保持门洞和走廊可见，避免说明牌挡住唯一出口
- 将详细规则放在可停留阅读的位置，不占满出生点
- 在分岔处使用箭头或简短目的地名称

如果邀请测试者，让对方描述看到了哪些入口和功能，再对照设计目标。记录不能辨认的位置，调整后重测。

## 本地 Trigger：经过入口时显示提示

可以用第 14 章的 `OnPlayerTriggerEnter` 在本地玩家经过入口时启用一个提示物体：

```cs title="WelcomeStep.cs"
using UdonSharp;
using UnityEngine;
using VRC.SDKBase;

public class WelcomeStep : UdonSharpBehaviour
{
    public GameObject toEnable;
    private bool triggered;

    public override void OnPlayerTriggerEnter(VRCPlayerApi player)
    {
        if (!Utilities.IsValid(player) || !player.isLocal) return;
        if (triggered || toEnable == null) return;

        triggered = true;
        toEnable.SetActive(true);
    }
}
```

1. 创建独立区域物体，添加 Box Collider 并勾选 `Is Trigger`。
2. 挂载脚本，调整 Collider 覆盖入口经过的位置。
3. 将默认禁用的提示牌拖入 `To Enable`。脚本和 Trigger 本身保持启用。
4. 从区域外进入，确认提示牌启用；再次进出时不重复执行。
5. 用第二位玩家测试：对方进入区域，不应启用本机的提示。

`player.isLocal` 限定本机玩家。`triggered` 是本地字段，表示这台客户端已触发，不会自动同步给别人。区域直接包住 Spawn 时，还需测试出生过程是否符合预期。

## 出生区灯光检查

可以用一盏低强度环境光配一盏局部灯做对照，观察说明牌和出口的对比度：

```text
Directional Light
Color       #9AB4C8
Intensity   0.4

Point Light（照向入口标识附近）
Color       #FFE0B0
Intensity   2.0
Range       6
Shadows     None
```

这些参数只用于对照测试。实际亮度还取决于材质、环境光、曝光与显示设备。降低全局光后，检查地面边缘和操作提示是否仍可辨认。

若使用烘焙光照，可在出生区放置 Light Probe Group 并重新烘焙，为支持探针的动态对象提供环境光。检查探针是否覆盖玩家活动高度，避免落入墙内。

## 日夜对照与无文字盲测

先另存场景副本，记录 Spawn、材质、灯光、Lighting Settings 和曝光。固定测试设备、视高、出生点与行走路线。以下灯光数值是实验条件，不是通用的日夜亮度。

1. **入夜版**：在副本中将用于整体照明的 Directional Light 设为 Realtime、Intensity `0.1`，保留本章创建的局部 Point Light。检查出口、台阶边缘和提示牌能否辨认。没有创建局部灯时，先按本章参数添加，不能假定它已经存在。
2. **晴天版**：从入夜版只把 Directional Light 的 Intensity 改为 `0.8`，拍同一站位的画面；再单独将光色改为偏白；最后才关闭局部 Point Light，分别记录每一步。这样能分清强度、光色和局部灯各自的影响。环境光、材质和曝光保持原值；若也要调整环境光，单列一轮。依赖烘焙光的场景应为每版重新烘焙，不能用旧 Lightmap 判断新灯光。
3. **无文字盲测**：恢复同一套基准光照，仅禁用欢迎牌的 Canvas，不禁用灯光、通道或提示控制器。请没见过该场景的测试者从指定 Spawn 进入，不提前解释路线，问「你看见哪些出口，接下来想往哪走？」记录对方指出的入口和实际路线，再恢复欢迎牌做对照。

同一位测试者第二次进入已经知道布局，因此恢复文字后的结果不能当作独立的首次进入测试；条件允许时让另一位未见过场景的人测试有文字版本。路线选择与预期不同时，记录是入口不可见、标识不清，还是对方选择了别的目标，不预先把原因归到任何一方。

可按用途选择初始画面：聊天区可面向实际已放置的座位与通道；游戏区可面向规则牌和起点；展厅可面向首件作品与导览入口；Hub 可让多个分区入口同时可见。测试只使用已经建成的对象。

## 出生区检查清单

- [ ] 每个 Spawn 均有可站立地面，朝向符合入口布局
- [ ] Spawn Radius 不覆盖墙体、落差或传送门
- [ ] 不同视高和多人出生时均测试过
- [ ] 初始视线内能看见可通行路径
- [ ] 欢迎牌内容与当前场景功能一致
- [ ] 文字在实际观看距离上可读，所用字符可显示
- [ ] Trigger 只响应所需玩家，脚本与提示物体分开配置
- [ ] 入口光照和动态对象的环境光表现经过客户端检查
