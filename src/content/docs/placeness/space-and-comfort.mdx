门洞、走廊和桌椅的尺寸决定玩家能否通过、看清和操作。Unity 编辑器中的俯视画面不能直接反映 VR 中的视高、观看距离和手部触及范围。

## 区分头像外观、视高与碰撞

- **Avatar 外观尺寸**：模型和骨架决定外观；宽大的衣服、尾巴或装饰不等于玩家移动碰撞体。
- **视高（Eye Height）**：眼睛相对脚底的高度，受头像配置、校准和缩放影响。`1.6` 米可以作为本例的测试视高，不能当成全部玩家的默认值或中位数。
- **玩家碰撞与移动**：由 VRChat 的玩家控制器处理，不能仅凭模型是否穿过门框判断能否通行。

VRChat 的 Avatar Scaling 使用视高米数。玩家手动缩放范围的最小值不能低于 `0.2` 米、最大值不能高于 `5` 米；世界通过 Udon 直接设定视高是另一种模式，不能把这两个数当成全部缩放 API 的范围。具体可用范围仍受世界和客户端设置影响。世界内需要同时测试不同视高，不能假定所有玩家都使用同一身高。

## 建一个比例尺

1. 新建空物体 `_Ruler_Player`。
2. 创建子 Cube，Local Position 设为 `0, 0.8, 0`，Scale 设为 `0.5, 1.6, 0.3`。
3. 给它使用明显的纯色材质；作为编辑辅助时移除 Collider。
4. 把比例尺移到门洞、桌边和走廊里，检查几何关系。
5. 复制两个比例尺，观察迎面通过时是否留有空间。

这个 Cube 表示本例选定的外观参照，不是 VRChat 玩家控制器的精确复制。构建前删除辅助物，或将它标为 `EditorOnly`，避免打包。

## 门洞、走廊与天花板

以下是房间原型的可测试起点，不是 SDK 硬限制，也不保证适合所有头像：

| 元素 | 本例起点 | 检查内容 |
| :--- | :--- | :--- |
| 门洞 | 高 `2.2` 米、宽 `1.2` 米 | 不同视高能否通过，头部视角是否进入门框 |
| 双向走廊 | 宽 `1.5`–`1.8` 米 | 两人迎面时是否遮住视线、难以操作旁边物体 |
| 房间 | 高 `3.0` 米 | 头部、吊灯、天花板之间的距离 |
| 桌面 | 高 `0.75` 米 | 坐姿与站姿下能否看清、拿取物品 |
| 沙发座面 | 高 `0.4`–`0.5` 米 | Station 的坐姿位置与模型是否对应 |

调整一个尺寸后，重新检查相邻物体。例如门洞加宽可能挤占开关的位置；桌子抬高会改变 Pickup 的触及范围。

## 搭一间可测量的小房间

以下是可选的比例原型，净空约为 `4 × 4 × 2.6` 米。它不是人体工学标准，也不要求已有家具。先另存场景副本，创建空物体 `ScaleRoom`，Position、Rotation 都归零，Scale 保持 `1, 1, 1`。在它下面创建这些 Cube；表中 Position 都是局部坐标，尺寸顺序都是 X、Y、Z：

| 对象 | Position | Scale |
| :--- | :--- | :--- |
| Floor_Test | `0, -0.1, 0` | `4.4, 0.2, 4.4` |
| Wall_Left_Test | `-2.1, 1.3, 0` | `0.2, 2.6, 4` |
| Wall_Right_Test | `2.1, 1.3, 0` | `0.2, 2.6, 4` |
| Wall_Back_Test | `0, 1.3, 2.1` | `4.4, 2.6, 0.2` |
| Door_Left_Test | `-1.4, 1.3, -2.1` | `1.6, 2.6, 0.2` |
| Door_Right_Test | `1.4, 1.3, -2.1` | `1.6, 2.6, 0.2` |
| Door_Top_Test | `0, 2.4, -2.1` | `1.2, 0.4, 0.2` |
| Ceiling_Test | `0, 2.7, 0` | `4.4, 0.2, 4.4` |
| TableTop_Test | `0, 0.725, 0.6` | `1.4, 0.05, 0.7` |
| Seat_Test | `0, 0.425, -0.3` | `0.5, 0.05, 0.5` |

保留这些 Cube 的 Box Collider。门洞净宽 `1.2` 米、净高 `2.2` 米，桌面顶面为 `0.75` 米，座面顶面为 `0.45` 米。`Seat_Test` 只是尺寸占位物，还不能让玩家坐下；需要实际坐姿测试时按[座位配置](/come-alive/sit-mirror-teleport/#第一节用-vrcstation-做座椅)添加 Station 和锚点。

1. 在副本中停用与原型重叠的旧房间，将测试 Spawn 放在 `0, 0.2, -1.5`，Rotation Y 设为 `0`。Descriptor 的 Spawns 只引用这个测试点，Spawn Radius 设为 `0`。
2. 门外再放一块 Cube 地面，Position 为 `0, -0.1, -3`、Scale 为 `4.4, 0.2, 1.6`，连接门口，避免把门洞测试变成跌落测试。
3. 保持已有照明可辨认，执行 `Build & Test`。走过门洞、绕过桌面，再用两位玩家从门内外相向经过，记录遮挡和碰撞位置。
4. 固定同一 Avatar、视高与设备，只把门洞加宽到 `1.6` 米：两侧门柱的 X 改为 `±1.5`、Scale X 改为 `1.4`，门楣 Scale X 改为 `1.6`。重新构建，比较通行结果。
5. 恢复门洞尺寸，再单独改变桌面高度；不要同时修改玩家缩放和房间几何。分别记录桌面端与 VR 测试，未测的设备留空。

其他用途也可按成套参数搭原型。以下保留地面、层高、通道与主要物体的组合，都是设计选项，不能从尺寸推定容纳人数或舒适性：

| 原型 | 地面与净层高 | 通道与主要物体 |
| :--- | :--- | :--- |
| 客厅或咖啡厅 | `8 × 6` 米，高 `3` 米 | 预留 `1.5` 米走道；长桌长 `2`、宽 `0.8`、顶面高 `0.75` 米；座面高 `0.4` 米 |
| 展厅 | `12 × 8` 米，高 `4` 米 | 预留 `2` 米走道；先把画作中心放在 `1.55` 米高，再测不同视高和观看距离 |
| 活动场 | `20 × 12` 米，高 `6` 米 | 舞台宽 `8`、深 `4`、高 `0.6` 米；先用半径 `8` 米的扇形标出观众区，再检查视线及进出通道 |

## 楼梯：把外观与碰撞分开

如果实际台阶 Collider 导致上下移动不连续，可以让楼梯外观保留台阶，另用连续坡面承载玩家：

```text
StairsVisual
├─ Mesh Renderer：启用
└─ 台阶 Collider：移除或禁用

StairsRamp
├─ Mesh Renderer：禁用
└─ 连续坡面 Collider：启用
```

1. 让坡面连接上下两层地面，不留下缝隙或凸出的边缘。
2. 检查坡面与门、栏杆的交接处。
3. 在客户端从上往下、从下往上、斜向行走各测一次。
4. 若无法攀爬，降低坡度，检查碰撞网格及玩家移动设置。

坡度越大，同样的水平移动对应越大的高度变化。不要把某个角度直接称为所有设备、玩家和移动配置的舒适界限。旋转的薄 Cube 可以做坡道原型；正式碰撞网格需检查厚度和两端衔接。

## 移动方式与舒适性测试

强制位移、镜头旋转和持续加速可能造成不适，个体差异很大。可执行的设计检查包括：

- 玩家能主动选择进入载具或过场，并能退出
- 保留不需要连续移动的路径，例如传送点
- 移动平台的速度、加减速和转弯分别可调
- 载具内部保留相对玩家固定的参照物，例如座椅或边框
- 近处的大面积旋转、摇晃效果可以关闭

`VRC Station` 能把玩家放到座位上并配合移动物体，但它不会使现实身体产生相同的加速度，不能保证消除晕动。`TeleportTo` 与连续移动的效果也不同，需按玩法和目标设备分别测试。

## 桌椅与 Pickup 的测试

在场景中放一张测试桌：Position `0, 0.75, 1`，Scale `1.5, 0.05, 0.8`。桌板中心在 `0.75` 米，顶面还需加上厚度的一半。

需要抓取测试时，先按[拾取物制作步骤](/come-alive/pickup-and-throw/#第二步添加刚体和-pickup)准备一个带 Collider、Rigidbody 和 VRC Pickup 的测试物，再放到桌面上方。没有 Pickup 时，只记录桌面、视线和通行测试，不能把可见模型当作已能抓取。

`Build & Test` 后检查：

1. 桌面是否挡住需要阅读的文字或玩家视线。
2. 坐姿和站姿下是否能拿起桌上的 Pickup。
3. 不同视高下，交互提示和物体是否仍可见。
4. 物品放回桌面时，Collider 是否承托住它。

将桌子高度改为 `0.5` 或 `0.9` 米，记录操作距离的变化。若没有头显，可先做桌面端与 ClientSim 的碰撞检查；这不能替代 VR 手部操作和舒适性的验证。

## 跳跃与重力

`Networking.LocalPlayer.SetJumpImpulse(float)` 设置本地玩家的跳跃冲量参数，`SetGravityStrength(float)` 调节重力强度。玩家能跳多高由这些设置共同决定，不能只根据平台高度给出固定跳跃参数。

若项目使用 `VRCWorld` Prefab 内的玩家移动设置，先检查当前值，再通过测试平台逐步调整。增加跳跃能力后，还要测试玩家是否能越过原本用于限制路线的墙和栏杆。

## 按用途检查布局

- 聊天空间：检查多人站坐时的视线、座位间距和通道
- 游戏空间：检查移动路线、目标可见性与碰撞边界
- 展览空间：检查作品中心高度、观看距离和不同视高的阅读位置
- 活动空间：按计划人数检查入口、站位和出口，而不是仅扩大整个房间

## 场景检查清单

- [ ] 门、走廊和桌椅有明确的尺寸记录
- [ ] 不同视高下可以通过并完成必要交互
- [ ] 楼梯或坡道两端没有碰撞缝隙
- [ ] Station 的座位锚点与模型对应
- [ ] 强制移动有明确用途和退出方式
- [ ] 桌面端与目标 VR 设备分别测试过
- [ ] 未完成的设备测试有记录，未写成已通过
