Quest 独立运行与 PC VR 使用不同的世界构建。Quest 通过 Link 或串流运行 PC 客户端时使用 PC 构建；在头显上独立运行 VRChat 时使用 Android 构建。Android 手机也属于 Android 平台，但输入方式与性能条件不等同于头显。

是否提供 Android 版本由目标用户和项目范围决定，不能用没有来源的玩家比例代替这个选择。

## 安装模块与切换目标

1. 为项目当前使用的 Unity 版本安装 Android Build Support 及其配套工具。Unity 版本应与 VRChat 当前支持版本一致。
2. 打开 `VRChat SDK → Show Control Panel → Builder`。
3. 在 Build 区域的 Platforms 选项中选择 Android，并确认切换。
4. 等待资源重新导入，检查 Console 与 SDK 验证信息。
5. 检查场景、材质、音频和 UI，在目标设备执行可用的 Build & Test 流程或使用已上传的私有测试版本。

具体构建入口以当前 SDK 为准。[官方跨平台设置](https://creators.vrchat.com/platforms/android/cross-platform-setup/) 说明了模块、平台切换和同一 Blueprint 的上传关系。

**切换平台不会自动备份并恢复所有场景设置。** 纹理的 Android Override 可以按平台生效；手动替换材质、修改 Lighting Settings、禁用 GameObject 都是项目改动。切回 Windows 并不会撤销它们。

## 材质与 Shader

Android **头像**的 Shader 有硬性白名单；Android **世界**可以使用自定义 Shader，但必须验证移动平台编译、画面和性能。不能写成「所有非 Mobile 材质都会变粉色」。

世界可优先评估 SDK 的 Mobile Shader，按所需功能选择：

- 只需基础色与烘焙光：检查 Lightmapped 或 Diffuse 类
- 需要法线细节：检查支持 Normal Map 的变体
- 需要较完整材质参数：检查 Standard Lite 等变体的实际成本
- UI 与粒子：选择对应用途的 Shader，不把所有材质直接替成同一个 Lightmapped

不同 Shader 的菜单路径与功能以当前 SDK 为准。缺少特定贴图功能时，替换后必须检查颜色、法线、透明度和反射。

### 需要两套材质时

```text
Materials/
├─ PC/Mat_Wall_Brick.mat
└─ Android/Mat_Wall_Brick_Android.mat
```

两份材质可以引用同一张纹理资产，由纹理的 per-platform 导入设置控制各平台分辨率和压缩。材质本身不会因文件名包含 Android 而自动替换。

可选择经过验证的平台切换工具，或维护两份场景。官方跨平台文档提及 EasyQuestSwitch；使用任何工具前检查其支持的 SDK、作用范围和还原行为，不必依赖没有核实功能的工具名单。

### 只替换一面墙的对照

1. 保存 PC 场景，在 Project 中复制为 `MyWorld_Android.unity`；保留原场景。复制 `Mat_Wall_Brick` 为 `Mat_Wall_Brick_Android`，避免修改两版共用的材质资产。
2. 打开 Android 场景并切到 Android。先选一个确实包含在当前 SDK、满足这面墙需求的 Mobile Shader；将同一张颜色图填入它对应的纹理槽，再把新材质赋给这面墙的 Mesh Renderer。记录不再支持的 Normal、AO 或反射通道，不把贴图丢失当作无差别替换。
3. 固定墙的位置、UV、Tiling、观察位置和光照。构建测试这一处替换，比较颜色、细节、Shader 错误和资源统计。需要重烘时，给这份场景保存独立的 Lighting Settings 与烘焙数据。
4. 只对这张纹理设置 Android Override，例如 Max Size `1024`；重新构建后比较原图与降分辨率版，分别记下载包大小和可取得的运行时内存，不能用源图片的文件大小代替两者。
5. 切回 Windows，重新打开原 PC 场景，核对墙仍引用原材质和原照明。两份场景若用于同一世界上传，继续核对同一 Blueprint ID 和网络对象标识，不因测试副本而新建世界。

这项实验先完成单个材质的输入、赋值和还原，再按测量结果扩展到其他资源。没有目标设备时可以记录构建与静态检查，实际移动端画面仍标为未测。

## 灯光配置

Android 移动硬件的实时光与阴影预算有限，可将固定灯光烘焙，并为动态对象配置 Light Probe。需要根据 Shader 与目标平台选择支持的 Mixed Lighting 模式，不能把 `Subtractive` 当作所有世界的必选项。

固定 Baked 光已经写入 Lightmap。运行时 `SetActive(false)` 或关闭 Light 组件不会删除这份光照。若需要真正切换两套烘焙照明，需专门实现与验证 Lightmap 数据切换；普通按钮并不自动完成此事。

Emission 只保证材质自身的显示效果。让它参与固定照明，还需要符合 Shader、GI、静态贡献与重新烘焙的条件。

## 分清硬限制与建议

按 [Android Content Optimization](https://creators.vrchat.com/platforms/android/quest-content-optimization/) 核查：

| 项目 | 性质 |
| :--- | :--- |
| Android 世界构建压缩后不超过 `100 MB` | 上传与访问限制 |
| 纹理尽量不超过 `1024 × 1024` | 优化建议，不是每张纹理的统一硬上限 |
| 世界总三角面约 `250,000` 的预算 | 优化建议，还需给头像和运行时效果留余量 |
| 减少透明覆盖、材质与实时光 | 性能建议，实际开销需测量 |
| Android 上的 Cloth、Post Processing | 官方列为禁用 |
| 世界中的 Camera、Rigidbody、Collider、Joint | 可用，但需要控制开销 |

这些限制与建议会更新，构建时还需查看当前 SDK 验证结果。世界的预算不能直接套用头像 Performance Rank。

## 纹理、音频与包体

### 纹理

在 Texture Importer 的 Android 标签启用 Override，按需要设 `Max Size` 与压缩格式。例如先比较 ASTC `6×6` 和 `8×8` 的画面与尺寸，不把其中一种说成所有项目的默认值。

同一格式下，纹理边长翻倍约使像素数量增加四倍。包体与显存占用是不同指标；压缩下载体积较小，不代表运行时内存同样小。

### 音频

音频压缩在 **AudioClip 导入设置** 中配置，不在 Audio Source 上。按音轨长度和用途检查 Compression Format、Quality、Load Type 与实际内存。源文件是 WAV 并不表示构建后一定原样无压缩打包。

### 构建大小

查看 SDK 构建结果和 Editor 日志中的资源统计，优先检查大纹理、长音轨与重复资源。仅仅放在 Assets 中、没有被构建内容引用的文件，不一定进入 AssetBundle；不要为了压包体无差别删除项目源素材。

## 一份工程里的平台差异

可选择以下一种明确的维护方式：

1. **同一场景 + 平台切换工具**：用工具切换材质和装饰物，验证切换与还原结果。
2. **两份场景 + 共享资产**：例如 `MyWorld_PC.unity` 与 `MyWorld_Android.unity`，分别维护表现差异。

两种方式均需注意：

- `EditorOnly` 会在所有平台构建中剥离，不是 Android 专用标签
- 禁用 GameObject 不等于一定从包体中剥离它的全部资源
- 平台分支与编辑器工具的行为需按实际 UdonSharp / SDK 版本核验
- 记录每个平台的 Lighting Settings 和烘焙数据，不假定它们自动按平台独立保存

## 跨平台同步与上传

各平台版本上传到同一个 Blueprint ID，客户端按平台下载对应构建。没有当前平台构建的世界不能靠 Portal 绕过兼容性限制。

平台之间可以减少装饰或简化材质，但不能任意改变需要同步的对象、组件顺序和网络标识。按 SDK 的 Network ID 工具检查一致性，并进行 PC 与 Android 同实例测试。

上传前核对 Pipeline Manager 中的 Blueprint ID。已有同一世界 ID 时不要为「做 Android 版」随意 Detach 创建另一个世界。

## 测试与验收

1. 在结构稳定的原型上切换一次 Android，查看 Shader 编译和 SDK 验证。
2. 在目标设备测量相同路线、相同人数下的帧时间与内存。
3. 检查桌面、头显与触屏的交互入口。
4. 让 PC 和 Android 玩家进入同一实例，验证灯、门、Pickup 和计分板。
5. 重测后加入、所有权变更和重置。
6. 切回 Windows，确认材质、照明和对象启用状态与记录一致。

若没有目标设备，可完成静态检查和构建，但这部分结果不能写成已经通过设备性能测试。
