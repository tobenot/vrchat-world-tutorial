第二部结束时，世界已经像个地方了——墙、地板、灯、桌椅、雨声都到位了。但是它还是一张照片：进去之后什么都不会发生。门是装饰，按钮是装饰，灯只能用 Inspector 里的开关切换，跟玩家没有半点关系。

第三部学完，那张照片开始有了被点击的能力。

## 看世界的方式变了一种

学一点代码之前，进别人的 VRChat 世界，看到一个会跳的方块、一个会自动开的门、一个走过去音乐就响的角落，反应大概是「哦，这做得真好」。看不出怎么做的，只能欣赏。

学一点代码之后，反应会变成「这个用 Trigger 检测玩家进入；那个挂了 UdonSharpBehaviour 在 Update 里推动门开；这盏灯八成是按了什么按钮把 enabled 切了」。

不是变得不能享受了。是多了一个角度：看见的不再只是表面，还有让表面动起来的那一层。**这一层之前是黑盒，现在是可以拆解的**。

这种「看穿」的感觉一旦有了，就回不去了。

## 静态空间和动态空间是两件事

第二部的工具盘——GameObject、Component、Material、Light、Prefab——能搭出非常漂亮的静态空间。把光打好、材质做对、空间比例调舒服，进去就觉得是个地方。

但 VRChat 世界跟一张概念图不一样。它要跟人发生关系：人会走、会按、会拿、会问「这个能不能动」。当人发现能动的时候，会愿意停下来多看一会儿。当人发现哪里都不能动的时候，会觉得这个世界更像样品间。

让世界从静态变成动态，需要的不是更多的物体，是给已有的物体装上反应。一段最简单的反应，就是一段 UdonSharp 脚本。

## 编程不是在写「另一种语言」

刚学语法的时候很容易把编程当成一门外语：要记住那些英文单词的拼法、那些标点符号的位置、那些规矩里的边角案例。这种感觉过几周会消退。

到那时会发现，写脚本时真正在做的事，是**把心里的意图翻译成机器愿意执行的步骤**。

「玩家按按钮，灯亮一下，三秒后灯暗。」  
→ 玩家按下按钮（Interact 方法被调用） → 把灯打开（targetLight.enabled = true） → 等三秒（SendCustomEventDelayedSeconds） → 把灯关上（targetLight.enabled = false）。

意图是模糊的、带温度的。步骤是机械的、可执行的。中间这道翻译过去就是写代码这件事的本体。学得越多，翻译得越流畅。但起点处的那个画面、那种意图，永远比代码本身更重要。

写脚本的人不是被代码奴役，是用代码服务自己想要的体验。

## 不会写代码也不是什么事都做不了

很多 VRChat 世界根本没用什么自定义脚本。出生点、镜子、传送门、Pickup 这些自带组件，配合好了已经能做出非常完整的体验。第五部会专门聊那种「轻代码或零代码」的世界路线。

学了一点代码之后回头看那些零代码世界，会发现它们也在用同样的语言：自带组件背后是同一套字节码、同一台虚拟机。它们只是被官方写好了。

理解这件事之后，做世界的态度会更放松一些：**该写代码的地方写代码，能用现成组件的地方用现成组件**，不需要为了「我也会写代码」就强行往里塞脚本。

## 接下来要做的事

第四部会把第三部学到的语法投入实战。每一节做一个具体的小交互：按钮开灯、走进区域音乐响、拿起东西扔出去、坐下、看镜子、开门、控状态。十来个小积木，做完手里就有一套能塞进任何项目的零件箱。

那一段会是这本书里动手节奏最密的一部分。每一节做完都能拿到一个具体的、能跑的、给朋友看一眼会有反应的小东西。

而那些小东西的共同名字叫做「世界活起来了」。
