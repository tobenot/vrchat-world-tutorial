程序由数据和指令组成。数据记录状态，指令读取或修改这些状态。VRChat 世界里的脚本可以响应事件，例如玩家与物体交互时改变一盏灯的状态。

本章用伪代码表达流程。伪代码用于说明逻辑，不能直接复制进 C# 文件编译。

## 把动作写成明确步骤

「调整灯光」没有说明目标、条件或数值。可执行的步骤需要更具体：

```text
收到与按钮交互的事件
找到按钮配置中指定的 Light
读取 Light 是否启用
把启用状态改为相反值
```

同样是按钮，目标引用或处理步骤不同，结果就不同。程序执行已经写明的操作，不会自行补上缺失的配置。

## 变量记录状态

变量把一个名称与值关联起来。值可以在运行中更新：

```text
分数 = 0
移动速度 = 1.5
灯是否开启 = 真
提示文字 = "打开灯 / Turn on light"
```

名称用于表达数据用途，类型用于约束能存什么值。布尔值表示真或假，数字表示数量或速度，对象引用指向具体物体或组件。

一次加分可以写成：

```text
分数 = 分数 + 1
```

先读取当前分数，加一，再存回分数变量。这个赋值动作不是数学等式。

## 条件选择要执行的分支

条件判断只在指定条件成立时执行某组动作：

```text
如果 分数 >= 10：
    显示完成提示
否则：
    显示当前分数
```

条件也可以检查对象引用：

```text
如果 目标灯不存在：
    记录配置错误
    结束本次处理
否则：
    修改目标灯状态
```

这样可以明确「满足条件时做什么」与「不满足时做什么」，避免在缺少目标的情况下继续调用它。

## 循环重复执行动作

对一组灯进行相同操作，可以遍历列表中的每一项：

```text
对 灯列表 中的每一盏灯：
    如果 这盏灯存在：
        关闭它
```

循环有继续条件，也需要能结束。C# 的 `for` 适合带计数器的循环，`while` 根据条件重复；两者的使用方式并非只能对应某一种任务。

普通循环在一次事件处理中连续执行，不会自动等待下一帧。如果需要每一帧移动一点，应该把单帧工作放进相应更新事件，而不是用无限循环等待时间经过。

## 方法组织一组动作

方法把相关步骤放在一起，通过方法名调用：

```text
方法 设置灯光(目标灯, 是否开启)：
    如果 目标灯存在：
        把目标灯的启用状态设为 是否开启

收到交互事件：
    调用 设置灯光(房间灯, 真)
```

括号中的输入是**参数**。方法也可以返回一个结果，例如读取当前分数或计算两个数的和。参数、返回值和对象字段的职责不同：参数属于一次调用，字段可以保存对象的持续状态。

## 事件决定什么时候执行

VRChat 世界不是把一个脚本文件从上到下运行一次就结束。脚本定义了事件入口，由运行环境在相应时机调用：

```text
行为开始运行                    → Start()
行为处于运行状态的每一帧        → Update()
本地玩家与目标物体交互          → Interact()
接收玩家加入实例的通知          → OnPlayerJoined(player)
```

`Interact` 是对特定 GameObject 的交互事件，不等于监听所有输入，也不等于拿起或使用手持物品。它需要相应 Udon Behaviour 和 Collider 等交互条件成立。设备按键由客户端输入映射决定。

`OnPlayerJoined` 还会在本地加入实例时，为已在实例中的玩家触发相应通知，因此不能把它只理解成「从现在起刚进来的其他人」。参见 [官方事件说明](https://creators.vrchat.com/worlds/udon/graph/event-nodes/)。

## 类归拢字段与方法

类是 C# 组织相关数据和行为的方式。例如，一个计数器可以表示为：

```text
类 计数器：
    字段：
        当前分数 = 0
    方法：
        增加分数(数量)：
            当前分数 = 当前分数 + 数量
        清零()：
            当前分数 = 0
```

UdonSharp 的行为脚本继承 `UdonSharpBehaviour`，通过场景组件与对象联系起来。类的代码定义行为，场景实例提供具体字段配置；两个实例可以使用相同代码而拥有不同目标引用。

## 错误与观察结果

编译错误表示源码没有通过语法、类型或编译器支持检查。运行错误发生在程序已经开始执行之后，例如调用了空引用。逻辑错误则可能没有报错，但结果与需求不符。

记录问题时，分别写出：

- 触发操作与发生条件
- 预期结果和实际结果
- 错误类型、文件位置或完整日志
- 相关字段与引用的实际值

日志不一定自动包含所有变量值，需要时由脚本输出。没有错误日志，也不能单独证明程序行为正确。

## 用流程检查一个开关

给定「每次交互切换一盏灯」的需求，检查这四项：

1. 事件是否是对正确物体发生的交互？
2. 字段是否引用了指定灯？
3. 修改的是启用状态，而不是物体位置等其他属性？
4. 连续交互两次后，状态是否恢复到起点？

这个检查只涉及一盏灯的本地行为，没有配置多人同步，因此不能把测试结果当作所有玩家都看到同一变化的证据。
