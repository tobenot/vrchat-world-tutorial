[基础 C# 章](/programming/csharp-just-enough/)中的灯光操作是：

```cs
public override void Interact()
{
    targetLight.enabled = true;
}
```

这是方法片段，假定类中已声明并配置 `targetLight`。它要产生效果，需要经历编译、程序关联、构建、加载与事件执行。

## 执行链路

```text
C# 源文件
    → UdonSharp 检查与编译
    → Udon Assembly / Udon 程序资产
    → 场景中的 Udon Behaviour 及其字段配置
    → SDK 构建世界资源
    → VRChat 客户端加载
    → 符合条件的交互触发 Interact
    → Udon 执行程序，调用开放的 Light API
    → Unity 根据新状态计算画面
```

本地 `Build & Test` 直接加载本机结果。上传后的版本由 VRChat 向有访问权限的客户端下载，两种入口都需要实际构建结果。

## 源码与编译

`.cs` 文件保存 C# 文本。UdonSharp 按语言规则分析声明和表达式，检查类型及受支持调用，再生成 Udon Assembly 等程序内容。

**Udon Assembly 是汇编形式的表示，Udon VM 执行的是编译后的程序。** 两者有关联，但不是把一份 C# 文本直接交给虚拟机逐行解释。

UdonSharp 的自动编译与 Unity 的资源刷新、配置有关。若关闭了自动编译，或仍存在编译错误，保存文件不代表新程序已成功生成。应检查 Console 与当前程序资产状态。

创建 U# 脚本时，工具会生成 `.cs` 和配套 `UdonSharpProgramAsset`。程序资产关联源码，场景中的行为则关联程序与序列化字段。仅有源码文件、不挂到对象上，不会自动产生一个接收交互的场景行为。

## 为什么使用 Udon

[C#、.NET 和 Unity 的关系](/getting-started/about-vrchat/)区分了语言、类库与运行环境。普通 Unity 脚本能使用的能力，并不全部开放给上传世界。

Udon 给世界脚本提供受限的执行环境，只允许使用开放的 API。它限制的是世界程序的能力，不能描述为替换掉整个 Unity 或 VRChat 客户端的 .NET 环境。

脚本能否编译，还同时受 UdonSharp 语言实现范围影响。一个功能不可用可能是 API 未开放，也可能是语法暂不支持；仅凭编译失败不能推断唯一原因。

## 场景配置与打包

构建时，SDK 准备世界所需的场景资源和 Udon 程序。字段中指定的 Light 引用也属于场景配置的一部分。

同一个脚本类的两个实例可以引用不同灯光：代码相同，字段配置不同，因此交互结果不同。更改 Inspector 引用需要保存场景或 Prefab，并使用包含该修改的新构建。

世界名称、可见性等上传记录与运行资源相互关联，但不是所有平台元信息都写在同一个程序文件中。本地测试也不会把结果加入公开世界搜索列表。

## 客户端中的事件执行

客户端加载场景与程序后，Udon Behaviour 在相应生命周期和事件条件下执行。`Start` 用于开始运行时的初始化；`Update` 在行为运行时每帧调用；`Interact` 在本地玩家与相应对象交互时触发。

下面是操作示意，不是实际 Udon 汇编指令：

```text
接收 Interact 事件
读取 targetLight 引用
通过开放接口把 Light.enabled 设为 true
结束本次事件处理
Unity 使用当前灯光状态渲染场景
```

程序通过开放接口调用 Light 的设置方法。可调用接口和虚拟机指令属于不同层面，具体指令形式以编译产物为准。

即使赋值成功，也不保证画面立刻有明显变化。例如，Light 本来已经启用、范围没覆盖目标、Shader 不受该光源影响，或它只是 Baked Light 的组件状态，这些都需要单独检查。

## 从现象定位环节

### 编译错误

检查错误位置、类型和完整信息，再判断是 C# 语法、类型不匹配、API 未开放还是编译器不支持。程序未成功编译时，不应只改场景交互设置。

### 事件没有触发

确认程序确实挂在目标对象上、对象与行为可运行、Collider 和交互距离满足条件。在事件入口记录日志，可以区分未进入事件与事件内部出错。

### 事件执行但没有预期结果

检查字段是否指向目标组件、值是否真的改变，以及目标组件生效所需的条件。赋值只修改属性，画面结果还依赖渲染配置。

### 运行开销过高

`Update` 每帧运行，循环次数和跨行为调用会重复发生。官方性能文档指出，一些等价代码在 Udon 中可能比普通 C# 慢约 200–1000 倍；这不是每种 API 的固定倍数，也不能直接推算世界帧率。应测量具体工作量与频率，缓存可复用引用，并考虑已有组件或动画。参见 [官方性能建议](https://creators.vrchat.com/worlds/udon/udonsharp/performance-tips/)。

### 其他玩家没有看到变化

Udon 在各客户端执行，本地属性赋值不自动成为网络消息。共享结果需要相应同步字段、网络事件或 SDK 同步组件，具体机制必须与需求匹配。

## 一次状态修改涉及哪些对象

对 `targetLight.enabled = true`，可以依次核对：源码中的字段声明、Inspector 引用、编译后的程序、事件入口日志、运行时 Light 值和受光表面。每一项都有独立证据，不需要从一张画面猜测全部执行过程。
