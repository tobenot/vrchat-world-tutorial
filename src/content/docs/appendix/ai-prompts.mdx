## I.1 翻译官方文档

读 VRChat 或 Unity 官方英文文档觉得吃力时：

```text
我刚开始做 VRChat 世界。下面这一段来自官方文档：

[贴原文段落]

请用大白话告诉我：
1. 这东西干嘛用
2. 我现在最该关心的三个字段是哪几个
3. 不动它会怎样
```

来源：[第 3 章 · AI 小助手](/getting-started/ai-partner/#把答案当假设不当结论)。

## I.3 写第一版脚本草稿

把模糊需求拆成最小版本：

```text
我用 Unity 和 UdonSharp。我想做 [一句话描述需求]。

约束：
- 先不要动画 / 平滑过渡
- 先不要音效
- 先不要多人同步
- 我要能跑起来的最小版本

请告诉我：
1. 场景里要建什么 GameObject
2. 每个物体挂什么组件
3. 脚本继承自 UdonSharpBehaviour，请把它的代码写出来
4. 怎么测：在编辑器里按什么、看什么变化
```

来源：[第 3 章 · 让它先做最小的那个](/getting-started/ai-partner/#让它先做最小的那个)。

## I.7 验证 UdonSharp API 是否真的存在

AI 给 VRChat 相关代码时**经常编 API 名**——`VRC_Teleporter`、`Networking.SendCustomEvent` 这种看着像那么回事但跑不起来的写法是常态。每次 AI 给你一个 `VRC*` / `Udon*` / `Networking.X` 开头的成员，先用这个模板让它自证：

```text
你刚才给我写了这一段 UdonSharp：

[贴代码]

请逐条回答：
1. 代码里出现的每一个 VRC* / Udon* / Networking.X 开头的成员（类、方法、字段）
2. 它在 SDK Control Panel 的 Class Exposure Tree 哪个节点下？给出完整路径，例如 `VRCPlayerApi → IsUserInVR()`
3. 它的当前签名是什么？（参数类型、返回值类型）
4. 它从哪个 SDK 版本起可用？是 SDK3 World 一直就有的，还是某个 3.x 之后加的？

如果你不确定某一项，就明确写"不确定，需要去 udonsharp.docs.vrchat.com 查"，不要猜一个像那么回事的答案。
```

来源：[第 12 章 · UdonSharp 长得像 C# 但它有脾气](/programming/udonsharp-personality/)、[附录 D · UdonSharp 限制](/appendix/udonsharp-limits/)。**经验**：让 AI 自己给"完整路径 + 签名 + 起始版本"三栏，会逼它把不确定的部分暴露出来；只问"这个 API 存在吗"它几乎永远说"存在"。

## I.8 设计网络同步策略（第 28 章后）

写多人世界遇到「这个状态要不要同步」「同步给谁」「什么时候同步」这一组问题时：

```text
我在做 VRChat 多人世界（UdonSharp，SDK3 World）。当前要同步的状态是：

[一句话描述：如"一扇门的开关状态"/"一个分数计数器"/"一个 Pickup 物体的位置"]

这个状态的特征：
- 谁会改它：[只有 Master / 任何玩家都可以改 / 只有 Owner 改]
- 改的频率：[偶尔 / 每秒一次 / 每帧]
- 容许误差：[必须严格一致 / 允许迟个 1-2 秒 / 演示性，丢一两帧无所谓]
- 玩家中途加入时：[必须看到当前状态 / 看不到也无所谓]

请帮我决定：
1. 用 [UdonSynced] 字段同步，还是用 SendCustomNetworkEvent 广播事件？
2. Behaviour 的同步模式（在 class 上写的 `[UdonBehaviourSyncMode]`）选 Continuous / Manual / NoVariableSync 哪一档？为什么？
3. 如果选 Continuous 且字段是数值类型，要不要加插值（`[UdonSynced(UdonSyncMode.Linear)]` 或 `Smooth`）？
4. 谁该是 Owner？需不需要在某些时候转 Owner？
5. Late Joiner 的兼容怎么做？需要 OnDeserialization 里做什么？
6. 列出 2-3 个最容易踩的坑（如"Master 离开时 Owner 自动转移导致状态丢"）。

不要直接给完整代码，先给方案，我自己写。
```

来源：[第 28 章 · 同步状态](/with-others/tell-everyone/)、[附录 E · 网络同步决策表](/appendix/networking-decision/)。**经验**：先让 AI 在三轴（同步什么 / 谁来改 / 什么时候打包）上做决策，再写代码——直接让它给代码，几乎一定会出现 Continuous 同步高频字段、或在 `Update` 里调 `RequestSerialization` 这种典型错配。

## I.9 排查光照烘焙问题（第 36 章后）

烘焙完发现画面不对（黑斑、漏光、整体偏暗、Quest 上不一样）：

```text
我在做 VRChat 世界，刚跑完一次 Lighting → Generate Lighting，结果：

[描述现象，例如：墙根有黑斑 / 阴影边缘有方块状马赛克 / 烘焙后整个房间比预览暗了一档 / Quest 上看比 PC 灰一档]

当前关键设置：
- Mixed Lighting > Lighting Mode：[Baked Indirect / Subtractive / Shadowmask]
- Lightmapping Settings > Lightmapper：[Progressive CPU / Progressive GPU]
- Lightmap Resolution：__ texels per unit
- Light Probe Group：[有 / 没有；如果有大概多少个探针]
- Reflection Probe：[有 / 没有；Box Projection 是否勾上]
- 主要 Directional Light 的 Mode：[Realtime / Mixed / Baked]
- 物体 Static 标志：[全勾 / 部分勾 / 没注意]

请按"先排除什么、再排除什么"的顺序帮我列检查清单，不要一次给十条建议。Quest 相关的注意事项放最后单独说。
```

来源：[第 36 章 · 光与影](/placeness/light/)、[附录 G · 性能检查清单](/appendix/performance-checklist/) 第 G.3 节烘焙部分。**经验**：让 AI 先给"按顺序的排查清单"，比直接让它"诊断"更有用——光照问题的可能原因太多，一次给十条建议你一条都跟不上。

## I.10 定位性能瓶颈（第 38 章后）

世界跑得卡，但不知道卡在哪：

```text
我在 VRChat 世界里测性能，目标平台是 [PC / Quest]。

当前测得的数字：
- Stats 面板：FPS __，Tris __，SetPass calls __，Batches __
- Profiler 主线程：__ ms（CPU），__ ms（Render）
- Profiler GPU：__ ms（如果开了 GPU profiling）
- 大致场景规模：__ 个 GameObject，主要内容是 [描述]

我已经做过的优化：
- [列出已做的，如"主要物体勾了 Static" / "材质开了 GPU Instancing" / "Reflection Probe 烘焙过"]

请按"瓶颈最可能在哪"的顺序回答：
1. 这组数字里哪一项最异常？（参考第 38 章给的 PC / Quest 预算）
2. 异常的那一项最常见的三个原因分别是什么？
3. 每个原因下，我应该用 Profiler / Frame Debugger / Stats / Occlusion Culling 哪个工具去验证？
4. 不要让我把所有优化都做一遍——按"最可能在 X 上，先验证 X"的顺序给我下一步。
```

来源：[第 38 章 · 性能](/placeness/performance/)、[附录 G · 性能检查清单](/appendix/performance-checklist/) 第 G.1 节"测量先于优化"。**经验**：性能优化最容易踩的坑是"全做一遍"——AI 一次性给 20 条建议，你做完两小时还没搞清楚卡哪。让它先**指认瓶颈**再给方向，能省至少一半时间。

## I.11 Chill World：用氛围描述起步参数（第 18 章后）

脑子里有画面但落不到 Unity 参数上时：

```text
我在做一个 VRChat 的 Chill 世界，氛围是「[描述：如"东京下雨天的小公寓，深夜，室内开着一盏暖色台灯，窗外能听到雨声"]」。
请给我一组起步参数：
- Directional Light 的 color、intensity
- Ambient（Lighting → Environment）的颜色和强度
- 室内主灯（Point Light）的 color、intensity、range
- 背景声 AudioSource 的 Spatial Blend、音量、Min/Max Distance
- 窗外的 SkyBox 颜色或推荐的免费 cubemap 风格
不要解释，直接给参数。
```

来源：[第 18 章 · Chill World](/world-types/chill-world/)。**经验**：AI 给的参数当起点用，不当最终值。进 Play Mode 凭眼睛再调，亮度刺不刺眼这件事 AI 没办法判断。但从一组合理起点开始，比从默认值开始调整快几倍。

## I.12 Game World：规则漏洞检查（第 19 章后）

规则写好之后让 AI 帮你找漏洞：

```text
我在做一个 VRChat 游戏世界，规则是这样：
[这里写核心循环和胜利条件]

请扮演四种玩家走一遍这套规则：
1. 一个想认真竞争的玩家
2. 一个只想搞笑捣乱的玩家
3. 一个半路加入的玩家
4. 一个掉线又重连的玩家
对每一种说出他们碰到的问题、能怎么钻规则空子、设计上需要补什么。
```

来源：[第 19 章 · Game World](/world-types/game-world/)。**经验**：这种「找漏洞」的角色扮演 AI 干得不错，能把作者自己想不到的边界情况列出来。具体的漏洞补法还是要自己设计，AI 给的方案多半过于理论。

## I.13 Social Hub：场景演练（第 20 章后）

空间布局画好之后让 AI 扮演不同成员走一遍：

```text
我在做一个 VRChat Social Hub，给一个 30 人的[社群类型]社群用。
空间布局是这样：[简要列出主厅、子区域、座位、设备]

请扮演四种成员各走一次空间：
1. 一个第一次被朋友带进来的路人
2. 一个每周来三次的常驻成员
3. 一个负责今晚活动的主持人
4. 一个想找个安静角落跟一个朋友聊天的成员
对每一种说出他们进门后会去哪、用空间的方式、可能撞上的不便。
```

来源：[第 20 章 · Social Hub](/world-types/social-hub/)。**经验**：AI 不知道具体社群的文化习惯（中文圈、英文圈、furry 圈……对空间的期待差很多）。给一段背景说明再让它扮演，结果更准。

## I.14 Gallery：光照参数 + 展线评估（第 21 章后）

两个模板。光照参数：

```text
我做一个 VRChat Gallery，主厅大约 10x15 米，挂 12 幅油画在四面墙上。
氛围目标是「[如"安静的当代美术馆，整体偏冷调，作品聚光偏中性白"]」。
请给一组起步参数：
- 环境光（Lighting → Environment）的颜色和强度
- 主灯（Directional Light）的角度、color、intensity，是否要开
- 每幅作品上方 Spot Light 的 color、intensity、range、cone angle
- 墙面材质的 Albedo、Smoothness、Metallic 推荐值
不要解释，直接给参数。
```

展线评估：

```text
我的 Gallery 布局是这样：[文字描述空间]
作品顺序是这样：[列出每件作品的位置]

请扮演三种观众走一遍：
1. 第一次进来、对作者完全不了解的访客
2. 一个有 5 分钟时间想快速看完的人
3. 一个仔细看每件作品的人
对每一种说出他们的观看顺序、可能漏掉什么、动线哪里别扭。
```

来源：[第 21 章 · Gallery](/world-types/gallery/)。**经验**：展线评估能找出作者走熟之后看不见的「死角」（最重要的作品被放在最不显眼的位置）。

## I.15 Narrative World：场景细节 + 情绪曲线（第 22 章后）

两个模板。场景细节生成：

```text
我做一个 VRChat [类型]向 Narrative World，设定是「[一句话设定]」。
请给出 10 件可以放在场景里的「环境叙事」物件，每件包含：
- 物件名（一个简单 3D 模型能做出来的）
- 放置位置（哪个房间、墙上 / 地上 / 桌上）
- 它在暗示什么剧情信息
要克制、间接、能让玩家自己拼出故事的。
```

情绪曲线检查：

```text
我的 Narrative World 节奏是这样：
[节点 1：玩家进入门厅，看到 X]
[节点 2：玩家走到 Y，发生 Z]
[...]

请按情绪强度给每个节点打分（0 到 10），并指出：
- 哪几个节点情绪曲线断裂
- 哪几个节点强度过早达到峰值
- 结尾是否有合理的情绪着陆
```

来源：[第 22 章 · Narrative World](/world-types/narrative-world/)。**经验**：AI 能找出作者反复看自己作品时麻木了的曲线问题，但具体修法需要自己设计细节。

## I.16 Event World：容量预估 + 时间线（第 23 章后）

两个模板。容量预估：

```text
我办一场 VRChat 演唱会，预期 [N] 人，演出 [M] 分钟。
我的世界 Capacity 设为 [C] 人（VRChat 单世界容量由创建者在 Scene Descriptor 里设，常见 32 / 40 / 80）。
请帮我估算：
- 需要几个实例
- 跨实例同步的几种方案各自的优缺点
- 前期 / 中期 / 后期各预计多少人在场
- 服务器 / 视频流 / 客户端各自的瓶颈在哪
```

时间线编排：

```text
我的 Event 时间线大致是：
[开场前 30 分钟：等待中]
[第 1 节 30 分钟：暖场表演]
[中场 10 分钟：休息]
[...]

请给每个段落建议：
- 灯光预设（亮度、色温、动态）
- 音频预设（BGM 音量、环境音、混响）
- 玩家可做的事（自由活动 / 必须坐下 / 互动机关开关）
- 可能出问题的地方
```

来源：[第 23 章 · Event World](/world-types/event-world/)。**经验**：AI 给的内容当起点用，Event 的体验是动态的，文档上看起来对的方案在实操中经常出意外，要按彩排实测调整。

## I.17 Tool World：UI 布局 + 功能完备性（第 24 章后）

两个模板。UI 布局：

```text
我做一个 VRChat [工具类型]，主要功能是：
[列出功能清单]

请帮我设计 World Space UI 的布局：
- 主面板有几块、各放什么
- 控件类型（滑动条 / 按钮 / 下拉 / 显示框）
- 控件之间间距和层次
- VR 友好的尺寸建议
按 1 个主面板 + 1 个副面板的结构来。
```

功能完备性检查：

```text
我做一个 VRChat [工具名]。
现在已经有的功能：[列出已计划功能]

请基于同类工具的常见功能，列出我可能漏掉的 5 到 10 个功能。
对每个说明：
- 功能描述
- 用户什么时候用得上
- 实现的复杂度（简单 / 中等 / 复杂）
```

来源：[第 24 章 · Tool World](/world-types/tool-world/)。**经验**：AI 在功能完备性检查上效率高，但具体的 UI 美感、VR 操作流畅度，还是要自己进 VR 实测。

## I.18 Commercial World：定价 + 体验平衡（第 25 章后）

两个模板。定价策略：

```text
我做一个 VRChat [世界类型] 世界，常驻群体大约 [N] 人，已经运营 [M] 个月。
现在想加 Creator Economy 元素：
[列出计划的商业内容]

请帮我设计价格策略：
- 各类内容定多少 VRChat Credits 合理
- 哪些应该捆绑、哪些独立
- 起步阶段 vs 稳定运营阶段的差异
- 跟同类世界的常见定价对比
```

体验平衡检查：

```text
我的 VRChat 世界商业元素布局：
[列出每个商业接口的位置和功能]
免费玩家的核心体验：[描述]
付费玩家的额外内容：[描述]

请评估：
- 免费玩家会不会感到「被歧视」
- 付费玩家会不会觉得「物有所值」
- 哪些商业接口可能让玩家不适
- 是否有 dark pattern 嫌疑
```

来源：[第 25 章 · Commercial World](/world-types/commercial-world/)。**经验**：AI 在「找出可能让玩家反感的设计」上有用，但 VRChat 具体的合规规则要查官方文档，AI 给的合规判断要交叉核实。

## I.19 发布世界：Description 和 Tags 撰写（第 44 章后）

上传世界时帮写元数据：

```text
我做了一座 VRChat 世界，类型是 [Chill / Game / Gallery / ...]，
核心体验是 [描述：玩家进来会看到什么、做什么、感受什么]，
推荐人数 [N 人]，支持平台 [PC / PC + Quest]，
主要受众 [中文社群 / 英文社群 / 日文社群 / 通用]。

请帮我写：
1. 一句话核心体验（用作 Description 第一句，限 30 字以内）
2. 一段完整 Description（150 字左右），含玩法亮点、推荐人数、平台支持、致谢栏位
3. 推荐 3-5 个 VRChat 标签（仅从官方支持的标签里选）
4. 缩略图构图建议（场景内能拍到的最有标识性的角度）
```

来源：[第 44 章 · 发布你的世界](/publishing/submit-your-world/)。**经验**：AI 给的标签建议要交叉核实。VRChat 官方支持的标签列表会变，最稳的查法是看自己 VRChat 列表里其他类似世界用了什么标签。

## I.20 维护世界：反馈分类整理（第 46 章后）

头几周大量反馈涌入时：

```text
我正在维护一座 VRChat 世界（类型：[Chill / Game / ...]）。
下面是过去一周收到的玩家反馈，请帮我：
1. 按「技术 bug / 体验摩擦 / 设计建议 / 其他」四类分类
2. 每一类按严重程度排序（影响多少人、是否致命）
3. 标注每条反馈是「必修 / 应修 / 看情况 / 拒绝」中的哪一档，给一句话理由
4. 估算修一遍的工作量（半小时 / 一小时 / 半天 / 一天以上）

反馈原文：
[贴 Discord / Twitter / 世界内反馈牌的原文]
```

来源：[第 46 章 · 维护一个世界](/publishing/maintaining-a-world/)。**经验**：AI 给的分类能当初筛用，省一半整理时间。最后的「修不修」判断仍然是创作者自己决定的事：AI 不知道你的创作意图。

## 通用注意

无论哪个模板，都遵循：

- 把 Unity 版本 / SDK 版本 / 平台（PC/Quest）告诉它，避免它给跨版本的过期答案。
- 让它先**分析**再**给方向**，不要直接让它改代码。
- 拿到答案后回 Unity 自己跑，跑通了才算。
- AI 给的组件名 / API 名要先在 SDK 控制面板或 `Add Component` 里搜一下，搜不到大概率是它编的（[第 3 章](/getting-started/ai-partner/#它会什么不会什么) 已经说明）。
