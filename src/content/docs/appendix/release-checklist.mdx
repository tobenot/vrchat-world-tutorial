新世界上传会建立 World ID；用同一 Blueprint ID 上传是更新。名称、描述等元数据可编辑，创建另一个 World ID 不会迁移原世界的收藏和历史。上传、更新与公开是不同操作。

附录 H 把第八部 + 第九部的发布相关项汇到一处，按发布流程顺序排：先验证前置条件 → 配置 Scene Descriptor → 跑三层测试 → 填元数据 → 切平台再发一遍 → 检查内容合规 → 上传后验证 → 公开（Public）前最后扫一眼。

## H.1 进 Builder 之前

检查项目能否构建、测试是否完成、备份是否可恢复，以及素材是否允许使用。

### H.1.1 编译与 Console

- [ ] Console 没有红色错误（编译错、Missing Reference 全清）
- [ ] Console 没有 `[UdonSharp]` 红字（白名单 / 编译器限制类）
- [ ] `Build & Test` 单人本地能进、能走、出生点对

### H.1.2 性能（详细见附录 G）

- [ ] 记录设备与帧率目标，例如 PC VR 90 FPS / Quest 72 FPS；公开提交文档另建议单人 VR 出生点至少 45 FPS，不是自动处罚阈值
- [ ] 若使用 Occlusion Culling，已烘焙并检查目标设备上的遮挡效果与帧时间
- [ ] 若使用烘焙光照，已生成匹配当前场景的 Lightmap，并检查静态表面与动态物体照明
- [ ] 适用的重复物体启用 GPU Instancing，并核对实际合批结果
- [ ] 镜子和视频播放器的初始状态符合设计与性能预算，并有适用的本地控制；默认关闭不是上传的统一前提
- [ ] 已按计划容量组织多人和代表性头像测试，并记录设备、人数、视角与功能状态

### H.1.3 备份与版本

- [ ] 项目目录已 `git commit`（或本地 / 云盘备份）
- [ ] **切平台之前**先 commit 一次（切换目标平台可能触发资源重导入，需保留可恢复的配置）

### H.1.4 素材合规

- [ ] 用到的 Booth / Gumroad 模型授权范围**包含「VRChat 上传」**（作者明确写「VRChat NG」的，买了也不能上）
- [ ] CC BY 类素材在世界 Credits 牌上有署名
- [ ] 引用的音频 / 字体 / 贴图来源全部在 `LICENSES.md`（或 `Assets/_Credits/CREDITS.md`）有记录
- [ ] 音乐、字体、角色与其他受保护素材有适用许可、作者授权或其他明确合法依据
- [ ] 实际使用的 AI 生成素材或 AI 辅助制作过程按真实情况保留 Credits 与来源记录

## H.2 VRC Scene Descriptor 的关键字段

世界根物体上挂的 `VRC Scene Descriptor` 是 SDK 识别这个 Unity 场景为「VRChat 世界」的核心组件。以下逐项核对配置。

### H.2.1 Spawns（出生点）

- [ ] 至少有一个可用出生位置；可使用 VRCWorld 默认位置，或在 Spawns 中配置明确的 Transform
- [ ] **Spawn Order** 选好：
  - `First`：使用列表第一个出生点
  - `Sequential`：按列表顺序选择
  - `Random`：随机选择出生点
  - `Demo`：room-scale 中心对齐（VR 房型对齐场景）
- [ ] **Spawn Orientation** 选好：
  - `Align Player With Spawn Point`（默认推荐）
  - `Align Room With Spawn Point`（VR 房型场景）
- [ ] Spawn 的 Z 轴（forward）**指向可辨识的出口、主通道或说明区域**，不指墙、不指角、不指关上的门
- [ ] Spawn 上方至少 2 米空间，下方落点稳固
- [ ] 第一帧画面里能看见可去的方向（开口、走廊、亮光）

### H.2.2 Respawn Height

- [ ] Respawn Height 低于所有允许活动区域，并使掉出场景的玩家能及时重生；例如最低可行走面在 Y=0 时可测试 -50。
- [ ] Object Behaviour At Respawn 按需求选择：Pickup 掉出世界时 Respawn 返回原位，Destroy 删除

### H.2.3 Reference Camera 与其他

- [ ] 需要自定义视图配置时指定 Reference Camera，并在客户端核对裁剪距离等效果
- [ ] Forbid User Portals 按是否允许玩家从世界菜单开传送门配置
- [ ] `Forbid Free Modification` 按场景需要勾
- [ ] `Interact Passthrough` 按需配置

### H.2.4 Builder 里会扫到的常见阻塞

- [ ] `A VRC Scene Descriptor is required`：场景里没有 → 找根物体加上去
- [ ] 出生位置不正确：检查 VRCWorld 默认位置或已配置的 Spawns 引用
- [ ] `Compile errors detected`：有 C# 编译报错 → 回 Console 修红字
- [ ] 平台 Shader 警告：按具体提示检查编译与性能；世界并非只能使用头像的移动 Shader 白名单

## H.3 三层测试：ClientSim → Build & Test → Friends 私密

三层测试覆盖的条件不同：编辑器模拟、本地客户端与真实多人实例各记录测试结果。

### H.3.1 ClientSim 层（5–10 分钟）

- [ ] 进入 Play Mode，无 Console 红字
- [ ] 主路线走一遍：出生点 → 主交互 → 关键 UI
- [ ] 每个按钮、Pickup、Station、传送门各点一次
- [ ] 在测试副本中移除一个引用，确认日志和空值处理；结束后恢复配置

### H.3.2 Build & Test 层（10–30 分钟）

- [ ] `Number of Clients = 2`，两个 VRChat 客户端同时进
- [ ] 用 `--profile` 至少试一次双账号 Master / Guest
- [ ] 实时日志（按客户端日志显示快捷键）无红字 `halted`
- [ ] Stats 浮窗 FPS 90+（PC）/ 72+（Quest）
- [ ] 关键同步交互：开关灯、抓 Pickup、坐 Station，两端一致
- [ ] 测 Late Joiner：让一个客户端先按几下按钮、改几个状态，再让第二个客户端加入，确认状态同步过去了

### H.3.3 Friends 私密上传层（30 分钟+）

- [ ] `Build & Publish` 成功，保留 Private 世界状态，并创建邀请制测试实例
- [ ] 邀请测试者进入，记录各端操作、日志与结果
- [ ] 测真实公网延迟：朋友按按钮，自己看到的反应时间是不是接受范围内
- [ ] 测 Late Joiner：朋友先进、自己后进
- [ ] 重启客户端后重新加入，检查初始化与状态恢复
- [ ] 平台抽测：用 **Quest 头显**（或 Android 客户端）进一遍
- [ ] 跨平台测试：PC 玩家和 Quest 玩家在同一实例里能正常互动

相关章节：[第 41 章 · 测试你的世界](/surviving/testing-your-world/)、[第 41 章 · 发布测试清单](/surviving/testing-your-world/#发布测试清单)。

## H.4 元数据填报

SDK Builder 面板的 **World** 区填这些字段。每一项的注意事项都在这里汇成一张可勾选清单。

### H.4.1 Name（名称）

- [ ] 名称清楚、可区分，并在实际列表界面检查是否被截断
- [ ] 名称不冒充官方、不误导内容性质；不推断未经证实的搜索降权词
- [ ] 若世界主用途是分享头像并需归入 Avatar World，按官方分类规则在标题使用 avatar / avatars / avi / avis；普通世界只含头像时使用相应标签

### H.4.2 Description（描述）

- [ ] 开头说明世界的核心用途；实际截断位置按客户端界面检查
- [ ] 正文说明：玩法 / 特色 → 推荐人数 → 是否支持 Quest → 致谢
- [ ] 链接到外部 Discord / Twitter（如有）放在末尾

### H.4.3 Image（缩略图）

- [ ] 按当前 SDK 的图片尺寸与裁剪要求准备缩略图，上传前检查预览
- [ ] 用世界里**能看到的真实画面**（Photoshop 拼贴或外部素材会让玩家发现「跟图不一样」，VRChat 提交规则明确写不能用误导性预览图）
- [ ] 缩略图的主体、文字和裁剪在小尺寸下仍可辨识

### H.4.4 Tags（标签）

- [ ] 只勾跟世界**实质相符**的几个：`game` / `avatar` / `chill` / `event` / `social` / `gallery` / `pvp` / `horror` / `mystery` 等
- [ ] 标签如实反映内容，不用无关标签操纵分类；平台处理依据官方规则

### H.4.5 Capacity（容量）

> SDK 上传面板把容量拆成两档：`Recommended Capacity` 是推荐人数，`Capacity` / `Maximum Capacity` 是实例硬上限。不同 SDK 面板版本的字段名可能略有差异，含义按「推荐值 / 硬上限」理解。

- [ ] 根据计划活动、可用空间和多人性能测试设置 Recommended；记录测试人数、设备、头像和开启的功能
- [ ] 核对 Maximum 与 Recommended 在当前 SDK 的取值限制和关系，确保不把推荐人数写成性能保证
- [ ] 如果未测到计划容量，记录未验证范围，并在达到相应测试条件后重新评估

世界类型不直接决定可承载人数。容量设置应同时考虑客户端性能、网络状态、交互设计与空间使用，而不是套用统一的分类数值表。

### H.4.6 Visibility（可见性）

分别检查世界发布状态与实例访问类型：

- [ ] 测试期保留世界 Private 状态，通过邀请安排测试
- [ ] Friends、Group 等属于实例访问类型，不是同一组世界发布状态；按实例权限控制参与者
- [ ] 需要公开时提交 Community Labs，核对 SDK 或网页的实际发布结果

### H.4.7 Content Warnings 怎么看

按当前 SDK 如实配置 Content Warnings；当前[官方建世界流程](https://creators.vrchat.com/worlds/creating-your-first-world/)说明它与 Content Gating 配合。旧公开提交说明中仍有“已弃用”表述，不能据此忽略现有字段。警告标记不允许上传违反 ToS / Community Guidelines 的内容。

相关章节：[第 44 章 · 第三节：容量与元数据](/publishing/submit-your-world/#第三节容量与元数据)、[第 44 章 · 第一节：上传条件与项目检查](/publishing/submit-your-world/#第一节上传条件与项目检查)。

## H.5 Quest / Android 平台版（如果做了）

同一世界的平台构建应使用同一 Blueprint ID。确认目标平台、平台资源设置和上传结果，避免误建新的世界条目。

- [ ] 已有目标 World ID，或明确本次是创建新的世界
- [ ] **切平台前已 commit / 备份**
- [ ] SDK Control Panel `Platform Target` 切到 `Android`
- [ ] 等待资源导入与编译完成；耗时取决于项目、缓存和硬件
- [ ] Builder 扫一遍，所有 Android 兼容性问题已修：
  - 高成本或 PC 专用 Shader → 优先换成 `Mobile/VRChat/Lightmapped` 或 `VRChat/Mobile/...`
  - 纹理内存过高 → 按画质需要降低 Android Max Size、配置压缩
  - 光照配置与目标 Shader 不兼容 → 调整并重新验证烘焙
  - 有 Cloth / Post Processing → 删
  - 有 Realtime Light → 尽量改成 Baked
- [ ] 核对当前 Android 下载包限制，并用构建结果确认实际大小；不能只凭预估值判定通过
- [ ] 用 [VRWorld Toolkit](https://github.com/oneVR/VRWorldToolkit) 跑过一次 Quick Audit
- [ ] 在目标 Quest 设备上核对已记录的刷新率、帧时间与人数预算
- [ ] 跨平台测试（PC 玩家和 Quest 玩家在同一实例里能正常互动）
- [ ] `Build & Publish` 上传 Quest 版完成
- [ ] 回 VRChat 客户端确认世界页面同时有 `PC` 和 `Android` 两个标识

详细见 [附录 G · G.6 Quest / Android 专项](/appendix/performance-checklist/#g6-quest--android-专项) 和 [第 39 章 · 一份工程里的平台差异](/placeness/pc-and-quest/#一份工程里的平台差异)。

## H.6 内容合规

以下区分内容规则、包体限制和性能建议，具体发布要求以[官方公开提交说明](https://creators.vrchat.com/worlds/submitting-a-world-to-be-made-public/)为准。

### H.6.1 占位头像欺骗（Avatar World 专项）

::::caution[头像内容一致性]
头像世界里展示的头像必须跟用户最终下载到的是同一个。不能在公开后用违反平台规则的头像替换占位内容。

官方说明对此可暂停 Community Labs 提交权限，并视违规情况采取应用内处理。
::::

- [ ] 头像世界里展示的头像 = 用户实际能下载到的头像
- [ ] 没有「先发干净版、过审后偷换」的计划

### H.6.2 文件过大

- [ ] PC 包体 ≤ **200 MB**（VRChat 软建议 `Try to keep your worlds under 200MB`，超过不会自动拒绝但运营可能要求缩减并临时下架）
- [ ] Quest 包体 ≤ **100 MB**（硬上限）
- [ ] 检查未压缩纹理 / 未清理的导入素材 / 过高 Lightmap 分辨率

### H.6.3 性能严重不达标

- [ ] 官方建议单人 VR 出生点至少 **45 FPS**，同时记录测试设备与设置
- [ ] 性能不足时按实际瓶颈优化；45 FPS 不是自动审核或处罚阈值
- [ ] 根据设备刷新率确定预算；例如 90 Hz 和 72 Hz 对应不同单帧时间，不是全部平台统一的合格线

### H.6.4 TOS / 社区准则

- [ ] 没有未授权电影 / 电视片段
- [ ] 没有未授权音乐
- [ ] 没有露骨 / 仇恨 / 骚扰内容（无论是否「标注过」）
- [ ] 标题、描述、缩略图跟实际世界一致（不是误导性宣传）

### H.6.5 镜子与视频的初始状态

官方性能说明强烈建议镜子默认关闭，并提供玩家开关或区域控制。这是性能建议；具体状态需和世界用途、实际负载一并验证。

- [ ] 按已选方案设置镜子初始状态与开启条件，记录关闭和开启时的帧时间
- [ ] 按播放需求设置视频初始状态，并提供适用的音量、停止或显示控制
- [ ] 初始画面满足性能预算，不依赖玩家进入后先关闭效果才能正常操作

### H.6.6 标签滥用

- [ ] Tags 跟世界类型实质相符（详见 H.4.4）
- [ ] 没有为骗曝光贴不相干的标签

## H.7 上传后第一轮验证

Builder 提示成功后，在客户端核对目标世界、版本、元数据与主操作路径。

### H.7.1 客户端基础检查

- [ ] `Esc` → `Worlds` → `Mine`，能看到刚上传的世界
- [ ] 缩略图、名称、描述都对
- [ ] 启动一个 Friends Only 实例进去：
  - Spawn 落点对，朝向对
  - 灯亮、声音响、地板能踩
  - 关键交互（按按钮、坐椅子、传送门）能用
  - 镜子默认是关的
- [ ] 按当前可见性从自己的世界列表或授权入口找到世界；Private 世界不以公开搜索可见为通过条件
- [ ] 网页 `vrchat.com` 找到这座世界，World ID、上传时间、容量都对

### H.7.2 元数据回检

- [ ] World ID 是 `wrld_` 开头的串
- [ ] 平台标识：PC 已显示，Quest（如果发了）也显示
- [ ] Capacity（Recommended / Maximum）跟填的一致
- [ ] Visibility 状态符合预期

### H.7.3 多人快速验

- [ ] 邀请 1–2 位朋友进 Friends 实例
- [ ] 让朋友走主路线、按主交互一遍
- [ ] 观察网络同步无延迟异常、无 desync

如果有不对的地方：保留目标 Blueprint ID 再次构建上传；核对上传目标确为原世界，避免创建另一条世界记录。

相关章节：[第 44 章 · 第五节：上传后的验证](/publishing/submit-your-world/#第五节上传后的验证)。

## H.8 公开（Public）之前最后扫一眼

提交公开申请后检查 Community Labs 状态与访问范围；是否已转为 Public 以平台实际状态为准。

**前置条件**

- [ ] Private 世界的授权测试实例已经完整测试
- [ ] 朋友反馈的卡点都修了
- [ ] 准备好接收公网访客 / Bug 报告

**Builder 状态**

- [ ] Console 没有红色错误
- [ ] `Build & Test` 单人通过
- [ ] 多人 + 真实头像测过
- [ ] 目标设备上达到已记录的帧率预算
- [ ] 若使用 Occlusion Culling，已完成烘焙并验证实际遮挡与开销
- [ ] 若使用烘焙光照，Lightmap 与当前场景一致
- [ ] 镜子与视频初始状态、开启条件和本地控制符合已验证的方案

**Scene Descriptor**

- [ ] Spawns 与 Respawn Height 已核对；需要覆盖相关渲染参数时才配置 Reference Camera
- [ ] Respawn Height 低于全部允许活动区域

**元数据**

- [ ] World Name / Description / Image / Tags 都准备好（H.4 节）
- [ ] Recommended Capacity / Capacity（或 Maximum Capacity）跟实测多人帧率一致
- [ ] Description 开头准确说明用途

**Quest（如果做了）**

- [ ] Quest 版的 Shader / 包大小 / 纹理符合 Android 限制
- [ ] 在目标 Quest 设备上核对已记录的帧时间预算与多人条件

**版本与备份**

- [ ] 项目已 commit / 备份
- [ ] 上传前的最后一份 Backup 留着，万一公开后回退方便

**发布安排**

- [ ] 核对 Community Labs 的状态和平台规则，相关说明见[第 44 章](/publishing/submit-your-world/)
- [ ] 7 天内不再投另一座新世界（每个账号每 7 天只能往 Labs 投一座新世界）
- [ ] 公开后头几天定期看 Bug 反馈

完成适用检查项后，通过 SDK 或网页提交公开；上传完成与公开成功分别核对。
