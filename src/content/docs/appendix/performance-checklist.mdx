本清单汇总光照、材质、渲染、脚本与跨平台测试项，供记录基线和验证改动。

附录 G 的服务对象是两类时刻：

- **优化中**：帧率未达目标时，按测量结果选择相关检查项。
- **上传前**：场景做完准备 `Build & Publish`，照 G.9 那一份完整清单一次扫完。

按目标设备、人数和场景填写本清单，不适用项标记原因。[官方公开世界建议](https://creators.vrchat.com/worlds/submitting-a-world-to-be-made-public/)提出单人 VR 出生点至少 45 FPS；这是测试建议，不能据此断言低于该数值就必然受处罚。

## G.1 测量先于优化

固定设备、分辨率、观察位置、人数与图形设置，再比较改动前后耗时。

- [ ] 跑 Stats 窗口（Game 视图右上角 `Stats` 按钮）记下基线：FPS / Batches / SetPass calls / Tris / Verts / Shadow casters。
- [ ] 跑 Profiler（`Window` → `Analysis` → `Profiler`）按一帧看 CPU 各类工作的占比，确认瓶颈是 Rendering / Scripts / Physics / GPU 哪一块。
- [ ] **优化任何一项之前**，先记下当前数。优化一项之后再记一次。两份数对比，确认改动真的让数下降了。
- [ ] 编辑器里的数只是参考，最终以 `Build & Test` 之后的真实运行时数为准（编辑器有 overhead）。

相关章节：[第 38 章 · Stats：快速查看渲染统计](/placeness/performance/#stats快速查看渲染统计)、[第 38 章 · Profiler：定位具体耗时](/placeness/performance/#profiler定位具体耗时)、[第 38 章 · 按测量结果确定优化顺序](/placeness/performance/#按测量结果确定优化顺序)。

## G.2 通用性能预算

下列 PC 数字是本书示例的初始预算，不是社区统一标准或上传硬阈值。记录目标硬件与实测结果后调整；Draw Call、面数与帧率之间没有固定换算关系。

### G.2.1 数字预算（PC）

- [ ] 示例目标帧率：**90 FPS**，应按所测设备刷新率调整
- [ ] Batches（Draw Call 批次）：< **200**
- [ ] SetPass calls（Shader 切换次数）：< **100**
- [ ] Tris（三角面数）：< **500k**
- [ ] Verts（顶点数）：< **600k**
- [ ] Shadow casters（投阴影物体数）：< **100**

### G.2.2 数字预算（Quest / Android）

Android / Quest 需单独测量，不按 PC 预算的固定比例推算。以下仅是记录起点：

- [ ] FPS：≥ **72**
- [ ] Batches：< **100**
- [ ] SetPass calls：< **50**
- [ ] Tris：≤ **250k**（VRChat 官方 Quest 优化建议）
- [ ] Verts：< **300k**
- [ ] Shadow casters：< **30**

### G.2.3 共性事项（PC + Quest 都看）

- [ ] 为适用物体分别设置 Batching Static、Occluder/Occludee Static、Contribute GI；不把全部 Static 标记当作同一功能。
- [ ] 烘焙了 **Occlusion Culling**（`Window` → `Rendering` → `Occlusion Culling` → `Bake`）。改了场景结构（拆墙、加房间）后要重烘。
- [ ] 对使用相同 Mesh / Material 且 Shader 支持的重复物体启用 GPU Instancing，并用 Frame Debugger 验证是否合批。
- [ ] 透明物体（Transparent Render Queue）数量最少化。需要半透明时保留 Transparent；只需硬边透明遮罩时可比较 Alpha Cutoff。
- [ ] `Edit` → `Project Settings` → `Player` → `Other Settings` → `Static Batching` 默认勾上，确认没被关掉。

相关章节：[第 38 章 · Stats：快速查看渲染统计](/placeness/performance/#stats快速查看渲染统计)、[第 38 章 · 批处理与 GPU Instancing](/placeness/performance/#批处理与-gpu-instancing)、[第 38 章 · Occlusion Culling](/placeness/performance/#occlusion-culling)、[第 38 章 · 透明、阴影与画面覆盖](/placeness/performance/#透明阴影与画面覆盖)。

## G.3 灯光与烘焙

烘焙把适用的静态光照计算保存为贴图或探针数据。实时直接光、动态阴影和采样仍有成本。

- [ ] 按是否需要运行时改变照明选择 Baked / Mixed / Realtime；关掉 Light 不会自动移除已烘焙的照明。
- [ ] 记录实际启用的实时光、覆盖范围和阴影；移动端优先使用烘焙，保留实时灯时单独测量。
- [ ] 只为确有动态阴影需求的光源启用 Shadows，并比较开关前后的帧耗时。
- [ ] 不必要的小物体 Mesh Renderer 的 `Cast Shadows` 设成 **Off**（确认关闭后不影响必要的空间信息）。
- [ ] 参与光照烘焙的 Mesh 有有效 Lightmap UV；导入资产已提供合适 UV 时不必重复生成。
- [ ] 撒了一组 Light Probe，覆盖玩家会走的所有空间（避免动态物体 / 玩家头像发灰）。
- [ ] 需要环境反射的空间配置 Reflection Probe，并检查覆盖范围、接缝与材质支持。
- [ ] 烘焙完没有明显的 UV 缝、亮斑、漏光。
- [ ] Android 构建核对 Shader 与 Mixed Lighting 模式兼容性；变更光照配置后重烘，并在目标设备检查结果。

## G.4 材质与贴图

材质、子网格、Shader Pass、可见性和批处理条件都会影响 Draw Call。共享材质有助于合批，但不保证任意一组 Mesh 只用一个批次。

- [ ] **材质合并**优先：从 Blender 导入的角色 / 道具检查一下是不是每个零件一个独立材质。根据绘制统计判断是否适合合并，保留所需的独立剔除与交互。
- [ ] 重复使用的材质用同一个材质资产，不要复制十份。
- [ ] 适用的重复物体启用 GPU Instancing，并确认实际合批。
- [ ] Albedo / Detail Albedo 勾了 sRGB；Normal / Metallic / AO 没勾 sRGB。
- [ ] 所有 Normal Map 的 Texture Type = **Normal map**（不是 Default）。
- [ ] 所有贴图 Max Size 设到「够用就好」（不是默认 2048）。装饰用的 512、墙面用的 1024、关键近景才上 2048。
- [ ] Quest 贴图按视觉需求与内存预算设置 Android Max Size，可从 1024 或更低开始；这不是世界贴图硬上限。
- [ ] 按音频时长、播放方式和平台设置导入压缩；源文件扩展名不等于运行时编码与内存占用。
- [ ] 混用受光与 Unlit 材质时检查不同照明条件下的结果是否符合需求。

## G.5 镜子、视频器、特效

镜子增加反射渲染，视频播放器增加解码、纹理和音频等开销；两者成本不同，不是固定的翻倍关系。

### G.5.1 镜子

- [ ] 默认 `enabled = false`，玩家手动开关（按按钮 / 走进区域才生效）。
- [ ] 只需头像时，在 `Reflect Layers` 保留 **Player** 与 **MirrorReflection**；后者用于镜中的本地玩家。其他所需层按用途添加，分别核对自己、他人与场景的反射。
- [ ] 测试镜面分辨率与反射内容，1024 可作为试验起点；更高分辨率增加开销，不保证某个值必然卡死。
- [ ] 按需要启用 Disable Pixel Lights，将镜中逐像素点光 / 聚光降为顶点光照。
- [ ] 同一房间内同时开镜数量 ≤ **1**（多个镜子只允许装在不同房间，避免叠加渲染）。

### G.5.2 视频播放器

- [ ] 播放与静音的初始状态符合用途，且进入场景时的负载和音量已验证。
- [ ] 同一房间视频播放器数量 ≤ **1**。
- [ ] 按屏幕尺寸、观看距离与设备解码能力选择视频分辨率。

### G.5.3 特效（粒子 / Cloth / Post Processing）

- [ ] 测量粒子数量、屏幕覆盖率和透明叠加；移动端单独验证填充成本。
- [ ] **Quest 上 Cloth = 0**（必须）。
- [ ] **Quest 上 Post Processing = 0**（必须，Android 版 SDK 不支持）。
- [ ] 透明物体（玻璃 / 烟雾 / 粒子）多层叠加避免——重叠区域可能被重复着色，具体成本取决于 Shader 与屏幕覆盖率。

相关章节：[第 38 章 · 镜子与视频播放器](/placeness/performance/#镜子与视频播放器)、[第 39 章 · 分清硬限制与建议](/placeness/pc-and-quest/#分清硬限制与建议)。

## G.6 Quest / Android 专项

Quest 是独立运行 Android 的头显，性能预算需按具体设备测量。下面这些分成两类：官方 Android 文档写明的硬限制，以及移动端性能预算下的强烈建议。

### G.6.1 包体限制与禁用组件

- [ ] 构建压缩后的 Android 世界包不超过官方 **100 MB** 限制，并核对 SDK 实际结果。
- [ ] 不依赖 Android / Quest 禁用的 Cloth 组件。
- [ ] 不依赖 Android / Quest 禁用的后处理。

### G.6.2 性能建议项

- [ ] 优先烘焙静态光照；保留的实时光逐项记录成本。
- [ ] 单世界三角面 ≤ **250,000**（官方 Android 优化文档建议给世界预留的预算）。
- [ ] 贴图以 1024 或更低为预算起点，必要例外经设备测试确认。
- [ ] 所有 Material Shader 优先换成移动端友好 Shader。官方文档推荐世界使用 `Mobile/VRChat/Lightmapped` 并烘焙光照；也可以按画面需要选 `VRChat/Mobile/...` 系列。
- [ ] 减少大面积、多层透明叠加，并在目标设备测量。
- [ ] 适合遮挡剔除的空间已烘焙 Occlusion Culling，并验证实际收益。
- [ ] 符合条件的重复物体启用 GPU Instancing，并验证绘制结果。
- [ ] Skinned Mesh 数量低（玩家头像已经吃掉一份预算，记录世界内容与头像各自的成本）。
- [ ] 用 [VRWorld Toolkit](https://github.com/oneVR/VRWorldToolkit) 跑过 `Quick Audit` 没红字。

### G.6.3 维护一份工程做两个版本

- [ ] 同一个 Unity 工程，PC 和 Quest 共享 Hierarchy。
- [ ] 平台专用物体使用明确的分平台构建配置；EditorOnly 会在所有平台构建中被剥离，并非 Android 专用开关。
- [ ] 关键资源用 per-platform 设置（贴图分别设 Default / Android Max Size）。
- [ ] 确认 PC 与 Android 的对象、引用和同步标识一致；平台差异只修改有记录的资源与表现。

相关章节：[第 39 章 · 分清硬限制与建议](/placeness/pc-and-quest/#分清硬限制与建议)、[第 39 章 · 一份工程里的平台差异](/placeness/pc-and-quest/#一份工程里的平台差异)、[第 39 章 · 发布前清单](/placeness/pc-and-quest/#发布前清单)。

## G.7 脚本（UdonSharp）性能

UdonSharp 程序通过 Udon 执行，有额外调度与调用成本。性能比例随操作而变，按实际脚本测量。

- [ ] 避免每帧重复查找不变的引用；GetComponent 查询对象组件，FindObjectOfType 涉及场景查找，两者范围不同。引用可在 Inspector 指定或初始化后缓存。
- [ ] 检查高频字符串拼接与临时分配的耗时，不把 UdonSharp 描述成另有一套更慢的 GC。
- [ ] 测量循环规模与每次处理成本；可按需减少频率或分帧处理。
- [ ] 不必要的 `Update` 删掉——脚本只在玩家点击时做事，就只放在 `Interact` 里。
- [ ] 用事件（`Interact` / `OnPlayerTriggerEnter`）或定时器（`SendCustomEventDelayedSeconds`）替代不必要的轮询。
- [ ] 引用槽用 `public` 字段在 Inspector 里指定，不靠运行时查找。

## G.8 多人 + 真实头像下测一遍

头像、人数、镜子与图形设置都会改变实际负载。保留单人基线，再逐步加入代表性的头像和人数，区分世界内容与头像产生的成本。

- [ ] 用第二个 VRChat 账号 + 一个常用复杂头像进自己的世界，加上自己一共两人。
- [ ] 邀请 3–5 个朋友各带自己常用头像进来，看 FPS。
- [ ] VRChat 客户端按帧率显示快捷键（具体快捷键以版本为准）开 Stats 浮窗，实时看帧率。
- [ ] 多人帧率下降时，分别测试头像隐藏、镜子关闭和场景简化，定位具体负载来源。
- [ ] 用 **Quest 头显**（或 Android 客户端）实测一次。手头没 Quest 设备的话，找个有的朋友帮忙测一次。

相关章节：[第 38 章 · 确定测试条件](/placeness/performance/#确定测试条件)、[第 41 章 · 第六节：Android / Quest](/surviving/testing-your-world/#第六节android--quest)。

## G.9 上传前最后一遍（一页纸版）

`Build & Publish` 之前最后扫一眼。完成适用项并记录不适用项的原因。

**测量与基线**

- [ ] 在目标设备上记录帧时间与所选刷新率预算；编辑器 Stats 读数作为辅助
- [ ] Profiler 跑过，CPU 各类工作占比无明显异常
- [ ] Batches < 200（PC）/ < 100（Quest）
- [ ] SetPass calls < 100（PC）/ < 50（Quest）
- [ ] Tris < 500k（PC）/ ≤ 250k（Quest）

**烘焙与场景**

- [ ] 适用对象的 Static 子标记已分别配置
- [ ] 烘焙了 Occlusion Culling
- [ ] 烘焙了 Lightmap，没有明显 UV 缝 / 亮斑 / 漏光
- [ ] 撒了一组 Light Probe
- [ ] 实时灯与阴影的必要性、成本已实测

**材质与贴图**

- [ ] 适用重复物体的 GPU Instancing 已验证
- [ ] 重复材质合并到同一份资产
- [ ] 贴图 Max Size 不是默认 2048（按需降到 1024 / 512）
- [ ] Quest 纹理尺寸和压缩符合项目预算
- [ ] 材质组合在目标照明条件下符合需求

**镜子与视频**

- [ ] 按所选方案配置镜子初始状态，提供本地开关并比较开启前后的性能
- [ ] 镜子 `Reflect Layers` 包含所需的 Player / MirrorReflection 等层，不遗漏本地玩家反射
- [ ] `Mirror Resolution` ≤ 1024
- [ ] 视频播放器单房间不超过 1 个

**Quest 专项**

- [ ] Android 光照与 Shader 兼容，变更后的烘焙已验证
- [ ] 所有 Material Shader 优先换成移动端友好 Shader
- [ ] 没有 Cloth / Post Processing；Realtime Light 尽量为 0
- [ ] Build Estimate ≤ 100 MB
- [ ] 用 VRWorld Toolkit 跑一次 Quick Audit

**脚本**

- [ ] `Update` 里没有 `GetComponent` / `Find` / 字符串拼接 / 大循环
- [ ] 不必要的 `Update` 删了

**多人测试**

- [ ] 多人 + 真实头像测过（≥ 3 人，常用复杂头像）
- [ ] 用 Quest 头显或 Android 客户端实测过 FPS

不适用或未通过的项目记录原因、影响范围和测试结果。
