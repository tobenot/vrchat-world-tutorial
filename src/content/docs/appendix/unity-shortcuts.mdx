## 主面板分工

| 面板 | 默认位置 | 干什么 |
|---|---|---|
| `Scene` 视图 | 中央上 | 三维搭建画布 |
| `Game` 视图 | 中央上（标签切换） | 模拟玩家相机视角 |
| `Hierarchy` | 左 | 当前场景所有 GameObject 的目录 |
| `Inspector` | 右 | 选中物体的所有组件和参数 |
| `Project` | 下方 | 项目所有资产文件夹 |
| `Console` | 下方（标签切换） | 报错、警告、Log |

详见 [第 4 章 · Unity 面板](/getting-started/tools/#unity-面板)。

## Lighting 窗口（光照与烘焙）

打开：`Window → Rendering → Lighting`。

Lighting Settings 中的关键字段；具体选项按目标平台、场景与 Unity 版本核对：

| 字段 | 推荐起点 | 作用 |
|---|---|---|
| `Mixed Lighting → Lighting Mode` | `Shadowmask` | 静态阴影与间接光可烘焙，动态部分仍有实时开销 |
| `Mixed Lighting → Baked Global Illumination` | 开 | 允许生成烘焙全局光照数据 |
| `Lightmapping Settings → Lightmapper` | `Progressive GPU` | 按显卡支持、可用显存与烘焙结果选择 GPU 或 CPU |
| `Lightmapping Settings → Lightmap Resolution` | 30–50 texels/unit | 影响每单位面积的采样密度；提高会增加贴图和烘焙成本 |
| `Environment → Skybox Material` | 默认或自定义 | 决定室外天光颜色 |
| `Environment → Ambient Mode` | `Baked` | 配合烘焙 |

烘焙按钮：面板**右下角** `Generate Lighting`。  
旁边的下拉箭头：

- `Bake Reflection Probes` — 只重烘 Reflection Probe（[第 36 章](/placeness/light/#reflection-probe环境反射)）
- `Clear Baked Data` — 旧 Lightmap 没清掉时强制清

详见 [第 36 章 · 生成 Lightmap](/placeness/light/#生成-lightmap)。

## Animator 编辑器

打开：选中物体 → `Window → Animation → Animation`（`Ctrl+6`）。

第一次给某物体新建 Animation Clip 时，Unity 会**同时**：

1. 给该 GameObject 添加一个 `Animator` 组件；
2. 新建一个 `Animator Controller` 资产并自动挂到 Animator 上；
3. 把新建的 Animation Clip 作为该 Controller 的第一个 State。

之后双击 Animator Controller 资产打开 **Animator 窗口**（状态机视图）：

| 区域 | 作用 |
|---|---|
| **网格视图** | 拖拽编辑 State、Transition |
| **Layers 标签** | 多动画层（VRChat 世界开发用得少） |
| **Parameters 标签** | `+` 新增 Bool / Int / Float / Trigger |

常见操作：

- 右键空白 → `Create State → Empty` 新建 State
- 右键 State → `Make Transition` → 拖到目标 State 创建 Transition
- 右键 State → `Set as Layer Default State` 设默认（橙色）
- 选中 Transition：Inspector 里调 `Has Exit Time` / `Conditions`（需要立即按参数切换时关闭 Has Exit Time；需要播到指定进度时保留）

详见 [第 17 章 · 门、机关和状态](/come-alive/doors-and-states/)。

## 性能分析窗口

### Stats 窗口

打开：`Game` 视图右上角 `Stats` 按钮。

主要看：`FPS`、`Batches`、`Tris`、`Verts`、`Saved by batching`、`Shadow casters`、`SetPass calls`。编辑器与客户端结果可能不同；在固定条件下比较趋势，并用客户端实测确认。

详见 [第 38 章 · Stats：快速查看渲染统计](/placeness/performance/#stats快速查看渲染统计)。

### Profiler

打开：`Window → Analysis → Profiler`（独立窗口）。

主要看三块：`CPU Usage`（脚本 / 渲染 / 物理 / UI 各耗时）、`GPU Usage`、`Memory`。点 `Game → Play` 之后开始记录。锁定某一帧（`Ctrl+点击时间轴`）能看 Hierarchy 视图里逐方法耗时。

详见 [第 38 章 · Profiler：定位具体耗时](/placeness/performance/#profiler定位具体耗时)。

### Frame Debugger

打开：`Window → Analysis → Frame Debugger`。

按帧拆开 Draw Call 序列，能看到「这一帧第几次 Draw Call 画的是谁、用的什么 Shader」。找 Overdraw / 透明物体批次很有用。用于逐项核对绘制来源；Profiler 用于测量各系统耗时。

### Occlusion Culling 窗口

打开：`Window → Rendering → Occlusion Culling`。

烘焙顺序：为适用对象分别配置 Occluder Static / Occludee Static 标记（Inspector 右上角 `Static ▾`）→ 打开本窗口 → 底部 `Bake` 按钮 → 等几分钟 → 烘焙数据存到场景里。

详见 [第 38 章 · Occlusion Culling](/placeness/performance/#occlusion-culling)。

## VRChat SDK Control Panel

打开：`VRChat SDK → Show Control Panel`。常用四个标签：

| 标签 | 用途 |
|---|---|
| `Authentication` | 登录 / 登出 VRChat 账号 |
| `Builder` | 构建 / Test / Upload 世界 |
| `Content Manager` | 管理已上传的世界（数据来自 VRChat 服务器） |
| `Settings` | SDK 行为开关、ClientSim 入口 |

`Builder` 标签下：

- `Build & Test`（在本机起一个 VRChat 客户端测试）
- `Build & Publish for Windows`（上传 PC 版）
- 切平台后是 `Build & Publish for Android`（上传 Quest 版）

Unity 顶部菜单 **`VRChat SDK → Udon Sharp → Class Exposure Tree`**：写 UdonSharp 时查"这个 API 在不在白名单"的入口（[第 12 章](/programming/udonsharp-personality/#api-开放范围)）。

## UdonSharp 编译触发

UdonSharp 脚本在以下时机会触发重新编译：

| 触发条件 | 说明 |
|---|---|
| 修改 `.cs` 文件并保存（IDE 里 Ctrl+S） | Unity 检测脚本变化并编译；UdonSharp 按项目设置将受支持的 C# 程序转换成 Udon 程序 |
| 在 Unity 编辑器里手动 `Ctrl+R`（Refresh） | 强制重扫资产 |
| 进入 Play 模式（`Ctrl+P`） | 编译失败时 Play 不会启动 |
| 切平台（PC ↔ Android） | 切完会全量重编译一次 |

编译产物：`Assets/Resources/SerializedUdonPrograms/` 下生成的 `.asset` 文件（Udon 字节码缓存）。这个目录可以 `.gitignore`，每次拉项目重编自动重新生成（[第 42 章](/surviving/version-control/#第六节vcc-与依赖恢复)）。

详见 [第 12 章](/programming/udonsharp-personality/)。

## 资源管理（VCC 与 Package Manager）

本书用 **VCC（Creator Companion）** 管理 VRChat SDK 与 VPM 包：

- VCC 修改的是项目根 `Packages/manifest.json` 与 `Packages/vpm-manifest.json`。
- Unity Package Manager（`Window → Package Manager`）仍可以装 Unity 官方的非 VRChat 包（如 TextMeshPro、Cinemachine）。

这两份 `manifest.json` **要进版本控制**，记录了项目依赖。`Library/` 不进版本控制，新机器拉下后 Unity / VCC 会按 manifest 重建（[第 42 章 · 第六节：VCC 与依赖恢复](/surviving/version-control/#第六节vcc-与依赖恢复)）。

### `.meta` 文件处理

每个资源都有同名 `.meta` 文件（存 GUID + 导入设置）。规则：

- **`.meta` 跟资源文件一起提交、一起删除**。`.gitignore` 里**不要**写 `*.meta`。
- 在 Unity 编辑器里删资源（Unity 会同步删 `.meta`），别在资源管理器里手动删。
- 拉取项目后引用变成 None 时，检查相关资产与 `.meta` 是否都已提交，并核对 GUID 和合并记录。

详见 [第 42 章 · 第一节：Unity 的序列化与 .meta](/surviving/version-control/#第一节unity-的序列化与-meta)。
