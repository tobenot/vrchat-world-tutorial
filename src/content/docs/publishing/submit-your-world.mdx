上传把场景构建发送到 VRChat，并关联一个 World ID。首次上传默认是 Private；提交 Community Labs 是另一步。Friends、Invite、Group 等描述实例的加入条件，不是世界上传可见性的同级选项。

## 第一节：上传条件与项目检查

官方创建流程要求 VRChat 账号达到 `New User` 或以上才能上传世界；仅使用 Steam / Meta 等平台账号时，按官方流程关联 VRChat 账号。未达到上传条件时仍可进行本地构建测试。

提交 Community Labs 的账号条件与上传不同，官方 Labs 页面列为 `User` 或以上。以当前账号和平台界面实际允许的操作为准。

上传前检查：

- [ ] Console 中没有阻止编译的错误，SDK 阻塞项已解决
- [ ] [分层测试](/surviving/testing-your-world/)已记录本地、多人和目标设备结果
- [ ] 出生点、碰撞、重生与关键交互符合预期
- [ ] 性能结果注明设备、人数、头像和效果设置
- [ ] 采用烘焙光照或遮挡剔除时，数据与本次场景一致
- [ ] 镜子和高开销附加功能有适当的默认状态与控制
- [ ] 素材授权与 Credits 已核对
- [ ] 源码已提交或备份，并记录本次发布平台

烘焙、默认关闭镜子等是有适用条件的优化选择，不能统一写成所有世界都必须满足的上传硬门槛。

## 第二节：Scene Descriptor

选择场景中的 `VRC Scene Descriptor`，检查实际使用的字段。

### Spawns、Spawn Radius 与朝向

Spawns 保存出生 Transform。Spawn Order 的含义：

- `First`：使用第一个出生点。
- `Sequential`：按列表顺序使用。
- `Random`：随机选择。
- `Demo`：出生点作为 room-scale 中心参考，玩家相对现实活动范围中心的偏移会影响落点。

Spawn Radius 大于零时，在出生点周围圆盘范围内随机落点；整个范围都要有合法地面。

Spawn Orientation 可对齐玩家朝向或 room-scale 范围。当前文档的 Default 等同 Align Player With Spawn Point。用桌面和 VR 实测落点与朝向，不只观察 Scene 视图的箭头。

### Respawn Height 与物体重生

玩家低于设定 Y 高度时重生；Pickup 按 Object Behaviour At Respawn 选择销毁或回到起始位置。它不是“玩家与物体一起回出生点”。

阈值放在所有合法活动区域之下，同时检查掉落到阈值前是否可能长期卡住。不用固定的 `-50` 替代对实际地形的检查。

### Reference Camera

Reference Camera 的设置用于进入房间的玩家相机，例如裁剪距离和适用平台上的后处理。它不是拍摄世界缩略图的必选相机，也不是摄影模式快捷键的配置项。

引用相机可来自场景或 Prefab。修改后检查近处物体是否被裁剪、远景是否消失，以及不同平台是否支持所用效果。

### 其他选项

Forbid User Portals 限制从世界菜单开启传送门。Interact Passthrough 涉及用户层的交互穿透。只修改当前世界需要的选项，其他字段按组件官方文档核对。

## 第三节：容量与元数据

Capacity 在 SDK Builder 的世界元数据中配置，不在 Scene Descriptor 中。

| 字段 | 作用 |
| :--- | :--- |
| Maximum Capacity | 实例最大人数；创建者、世界作者或群组拥有者等平台允许的身份有例外 |
| Recommended Capacity | 公开实例达到此人数后，平台减少继续加入的推荐，例如从公开实例列表隐藏 |

按已测试的人数配置，推荐人数不高于最大人数。旧世界未设置 Recommended 时存在兼容规则：旧容量作为推荐人数，最大人数按其两倍处理。不要把这个历史规则作为新世界的填写方法。

可选配置例：活动计划为 8 人，目前只完成 8 人测试，就先把两项都设为 8。若需要额外容纳 4 人，先以 12 人测试通路、关键交互与目标设备性能，再考虑把 Maximum 改为 12，Recommended 保持 8；这两个数字对应本例的计划和验证范围，不是活动世界的通用人数标准。保存后从世界详情页回查容量，并用新实例验证加入条件，测试身份要注明是否属于平台允许超限的例外。

其他元数据逐项核对：

- **Name**：准确描述作品，不冒用官方身份。
- **Description**：用途、操作、建议人数、支持平台、已知限制与联系渠道。
- **Thumbnail**：展示实际世界内容，并在 SDK 预览中检查裁剪与可读性。
- **Tags**：与主要内容一致，不用不相关标签误导搜索。
- **Content Warnings**：按当前 SDK 和 Content Gating 要求如实填写；内容标签不豁免平台规则。
- **World Debugging**：决定是否向其他玩家开放受限世界调试视图，按项目需要设置。

旧的公开提交 Tips 页面与当前创建页对 Content Warnings 有不同描述。本书按较新的创建流程保留填写要求，实际字段以当前 SDK 为准。

## 第四节：构建并上传 Private 世界

1. 保存场景，确认当前登录的是有权上传该世界的账号。
2. 打开 `VRChat SDK → Show Control Panel → Builder`。
3. 选择构建平台，核对 World 信息及现有 Blueprint / World ID。
4. 修复阻止构建的验证错误，阅读其余警告。
5. 选择 `Build & Publish Your World Online`，检查页面上的协议和内容确认，再执行上传。
6. 等待成功结果，记录 World URL、ID、平台和源码版本。

若上传失败，查看 Console 中完整错误，再判断是构建、登录、网络或平台校验失败。不要在尚未确认结果时新建世界或清除 ID 重试，以免生成重复资产。

首次上传可以是测试用途，不需要因为得到 World ID 就把内容当作不可修改的正式版。继续使用同一 ID 可以更新；复制场景也可能保留旧 ID，不能把“新建场景”视为自动生成新世界。

## 第五节：上传后的验证

从 SDK Content Manager、自己的世界列表或返回的世界链接打开详情，确认元数据和支持平台。创建受限访问的新实例，检查：

1. 出生、朝向、地面碰撞与重生。
2. 门、座位、拾取、传送和 UI。
3. 本地设置、共享状态与后加入者。
4. 镜子、视频和附加特效的默认状态。
5. 当前版本标记与实际功能一致。

Private 世界不一定出现在公开搜索中；不能把搜不到私有世界当作上传失败。分享链接或邀请也受平台访问规则影响。

## 第六节：Community Labs

准备公开后，在 SDK 或 VRChat 网站的 World Visibility 中使用 `Publish to Community Labs`。世界不再保持 Private，玩家可通过 Labs 入口发现和收藏。

官方当前规则是每个账号每七天提交一座新世界；已有世界的更新不受这项新提交间隔限制。Labs 到 Public 的评估自动进行，没有公开固定的通过时间，也不能保证几天或几周后一定晋升。

当前 Labs 浏览需要相应设置，世界页面与进入提示可能随客户端更新。发布后核对实际状态，不依据上传成功提示推断已经 Public。

公开内容仍需符合服务条款、社区及创作者规则。世界中的音乐、视频、图片和头像也在范围内；举报经核实或严重性能问题可能导致处理。

官方 Tips 有包体和性能建议，但建议值不是所有设备统一的上传硬限制。平台验证错误、平台文件限制与体验目标分别记录，不混为一项。

## 第七节：更新与跨平台

更新已有世界时保留正确的 World ID，再构建对应平台。确认 SDK 显示的是目标世界，而不是另一个场景中复制来的 ID。

PC 与 Android 是同一 World ID 下的不同构建。上传 Android 时：

1. 保存并备份当前工程状态。
2. 确认 Android Build Support 和项目平台设置。
3. 检查材质、音频、光照和组件在 Android 上的兼容性。
4. 保留同一 ID 构建上传。
5. 用实际 Android / Quest 客户端进入新实例验证。

各平台构建需要保持共享对象与网络逻辑兼容。页面出现平台标识只证明对应构建存在，不证明多人行为正确。

正在运行的实例不能被当作已自动更新。验证新上传内容时创建新实例，并通过世界内版本标记确认加载结果；仅重进原实例不足以证明使用了新构建。

## 练习：只改 Description

选择自己有权编辑的测试世界，先保存原 Description、World ID / URL、当前世界内版本标记与可见的构建记录。若要核对收藏入口，先确认测试账号已收藏这座世界。

1. 从 VRChat 网站自己的世界详情进入编辑，只在 Description 增加一行可识别的测试文字并保存。不要同时改容量、可见性、场景或重新上传构建。
2. 刷新网页和客户端详情，核对测试文字、World ID 与原链接。若显示尚未刷新，记录时间并稍后再查，不先用重传场景解决。
3. 创建新实例，走一遍原有交互并查看场内版本标记；它应仍对应原构建。核对原收藏入口是否仍指向同一 World ID。
4. 记录页面显示的更新时间或版本信息有没有变化；这些是观察项，不事先保证内部版本号的规则。恢复原 Description，再核对一次。

这个实验改变的是世界元数据。它不改变世界的 Private / Labs / Public 状态，也不把 Friends 等实例访问类型变成世界可见性选项。各字段的发布检查见[元数据填报清单](/appendix/release-checklist/#h4-元数据填报)。
