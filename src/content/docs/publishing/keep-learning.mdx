VRChat、Unity 和 SDK 的接口与工具界面会变化。查资料时先记录当前版本和问题范围，再判断资料中的步骤是否适用。本章是一份资料索引与核对方法，不假定读者已完成某座世界的发布或运营。

## 第一节：按问题找官方入口

| 问题 | 入口 |
| :--- | :--- |
| SDK 安装、支持的 Unity 与升级 | [VRChat Creator Docs](https://creators.vrchat.com/)与 [VCC 文档](https://vcc.docs.vrchat.com/) |
| Scene Descriptor、Pickup、Station 等 | [World Components](https://creators.vrchat.com/worlds/components/) |
| Udon 事件、网络与持久化 | [Udon](https://creators.vrchat.com/worlds/udon/) |
| UdonSharp 语法与支持限制 | [UdonSharp 文档](https://udonsharp.docs.vrchat.com/) |
| 客户端功能与实例 | [VRChat Wiki](https://wiki.vrchat.com/)与 [VRChat Docs](https://docs.vrchat.com/) |
| 商品、订阅与提现 | [Creator Economy](https://creators.vrchat.com/economy/) |
| Unity 组件和 API | 与项目版本匹配的 [Unity Manual](https://docs.unity3d.com/2022.3/Documentation/Manual/index.html) |
| C# 语言本身 | [Microsoft C# 文档](https://learn.microsoft.com/dotnet/csharp/) |

从官方导航或搜索进入实际页面，不按猜测拼接组件 URL。`docs.vrchat.com` 包含客户端资料，不能简单当作全部过时的 SDK2 文档。

Unity 或 C# 支持某个 API，不代表 Udon 已暴露该 API。结合 Class Exposure Tree、当前 SDK 文档和工程编译结果核对。

## 第二节：记录版本与证据

一条可复用的技术记录包括：

```text
问题：
Unity / Worlds SDK / UdonSharp 版本：
客户端与平台：
最小复现步骤：
官方页面与核对日期：
实际测试结果：
仍未确认的条件：
```

官方文档之间也可能存在更新不同步。优先核对与当前功能直接相关的专项页、更新记录和实际 SDK；仍有矛盾时保留差异，不把选择某一页写成已经实测。

## 第三节：使用官方示例

Worlds SDK 的示例和 Example Central 可提供组件、Udon Graph 与脚本的完整场景。检查示例所需版本和资源，然后在独立测试项目中运行。

观察一个示例时，分别记录：

1. 对象层级、组件与 Inspector 引用。
2. 输入或事件在哪里触发。
3. 条件判断与状态变量如何变化。
4. 哪些结果仅本地可见，哪些有网络同步。
5. 重复操作、重生、后加入和 Owner 离开的结果。

示例可能只演示一个机制。能够运行不表示它已经覆盖项目的权限、并发、错误处理或性能要求。

## 第四节：核对社区资料

[VRChat Ask Forum](https://ask.vrchat.com/)和 [VRChat 官方 GitHub](https://github.com/vrchat-community)可提供问题讨论与公开项目。中文资料可从 [VRCD 文档库](https://docs.vrcd.org.cn/)等社区入口查找。

选择具体资料时检查：

- 作者与原始来源是否可识别。
- 发布时间、更新日期和所用版本。
- 是否给出复现项目或完整步骤。
- 是否把观察结果与原因推断分开。
- 代码和资源是否有可用许可证。

资料的新旧不能只靠发布日期判断；某段旧资料可能仍适用，近期发布也可能复述错误。社区回答可以提供排查方向，但接口签名、权限和平台限制需要回到对应官方来源与项目验证。

## 第五节：检查公开源工程

下载获得授权的工程后，先阅读 README、许可证和版本要求。保留原件，在副本中打开；Unity 编辑器脚本与工具包可以在导入时执行，不导入来源不明的可执行工具。

用工程要求的版本恢复依赖，再运行示例流程。选中相关 GameObject，对照脚本、组件和 Inspector 字段检查行为。直接替换为本书所用 SDK，可能引入与原问题无关的迁移错误。

引用或分发代码时，按[素材与版权记录](/surviving/assets-and-licenses/)保留许可证。公开源码不等于可以忽略授权条件。

World Debugging 可以开放某些受限调试视图，但不等于向访客开放完整 Unity 工程或任意脚本变量浏览器。调试视图用途与权限按当前官方文档核对。

## 第六节：提出可回答的问题

把问题限定到一项行为，例如：“A 开门后 B 加入，B 的同步变量为 true，但 Animator 仍显示关闭。”附上最小脚本、必要 Inspector 配置、日志片段和版本。

说明已经测试过的条件，以及每次改变了什么。移除账号凭据、私密实例信息和无关玩家数据，避免公开没有分发许可的完整资源包。

如果问题仍无法复现，记录发生时间、环境和周围事件。暂时无法下结论是有效状态，不用猜测一个确定根因填补空缺。

## 第七节：选择下一项作品

可以先写下要练习的能力、可投入的时间与完成条件，再从以下方向选一个小范围项目：

- 同类型再做一座：沿用熟悉的构建和发布流程，只集中改进一个目标，例如动线、光照或交互反馈；保留前作以便比较。
- 换一种世界用途：从[世界类型与选读](/world-types/)选需要的机制，先做一个能验证核心体验的场景；原有 Unity 工作流仍可用，新增机制另行测试。
- 做共享组件或资料：把一个已验证功能整理成 Prefab、Shader、编辑器工具或教程，补齐安装步骤、依赖、使用限制和许可，目标是让别人能在独立项目中复现。
- 与他人合作：选一项边界明确的共同任务，先约定分工、源文件许可、版本管理与验收方式，再组合美术、程序、声音或活动安排。

例如想练“多人状态恢复”，完成条件可以是两人交替操作、第三人后加入和 Owner 离开后状态正确；不必同时新增整个游戏系统。需要定期练习时，给自己安排一段能完成这种小验证的时间，按实际结果调整节奏。

也可在论坛或熟悉的创作社群建立一两个可互相求助的联系；先分享明确问题和已做的测试，尊重对方是否有空。资料入口、个人创作者与源工程可按[社区资源](/appendix/resources/#社区资源)、[视频和中文内容创作者](/appendix/resources/#视频和中文内容创作者)、[可学习的示例项目](/appendix/resources/#可学习的示例项目)查找，不把加入社群当成保证得到答复。

## 本书的来源与使用范围

本书的技术说明应与引用来源和项目验证对照；具体按钮名、API、政策和平台限制都可能变化。目录和索引用于定位概念，版本相关结论需要注明适用环境。

本书采用了 AI 协作生成的制作方式，相关来源记录保留在[首页](/)和[关于页](/about/)。制作方式不是技术正确性的证明；章节中的机制、代码和规则分别由官方来源与测试证据支持。
