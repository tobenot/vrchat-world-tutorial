VRChat Creator Economy 提供平台内的商品与订阅交易。用户使用 Credits 购买，卖家在符合条件后申请提现。[第 25 章](/world-types/commercial-world/)中的商品范围与设计检查，在这里对应到平台对象、账号配置和 Udon 事件。

本章不预测收益，也不提供个人税务结论。政策核对日期为 2026-10-05；申请、定价和提现以实际官方页面为准。

## 第一节：产品、销售项与商店

Product 定义权益，Listing 或 Subscription 定义如何销售，Store 提供展示入口。当前体系还包含 Avatar Products；世界功能使用的是 Udon Products，不应把世界教程中展开的子集写成全部产品类型。

| 销售方式 | 持有方式 | 实现检查 |
| :--- | :--- | :--- |
| Permanent Listing | 产品不按时长到期 | 重入后恢复已有权益 |
| Temporary Listing | 设定期限内持有 | 加载、到期与显示同步 |
| Instant Listing | 即时发放效果，不作为持续持有权益 | 确认新购买、数量与重复处理 |
| Subscription | 购买期限内获得群组角色及所含产品 | 角色权限、权益到期和延期 |

订阅包含一个群组角色产品，也可加入 Udon Products。World Store 用于世界的 Listings，Group Store 用于订阅。商品类型、数量和价格范围以创建页面为准。

当前订阅不会到期自动续费，用户可以主动延期。多月订阅的卖家收入按平台规则分期结算，取消也影响未结算月份；不要把“按月计价”直接写成自动循环扣费。

## 第二节：卖家与 Tilia 入驻

从 [Creator Economy 官方入口](https://creators.vrchat.com/economy/)进入申请，并检查当前资格、支持地区及项目规则。不要以“常驻 30 人”“月活百人”或固定审核周数作为没有官方依据的申请门槛。

获得对应访问资格后，在 VRChat 网站的 My Store / Storefront 中进入 Tilia 验证。按页面提交所需资料，核对法律姓名、地区、身份和收款要求，并阅读协议。只向官方流程提供身份与支付信息，不把证件或税号放进项目、脚本或公开反馈贴。

入驻审核与提现审核是两个流程。结果和补件要求以账号页面及官方邮件为准；地区税务申报或收款限制需要向当地专业人士和收款服务核实。

## 第三节：提现与费用

截至核对日，官方 [Payout](https://creators.vrchat.com/economy/payout/) 页列出的要求包括：账号符合资格、至少 20,000 earned Credits、没有正在处理的提现、距离上次申请至少 24 小时。购买和促销所得 Credits 不计入门槛。

收款可选 PayPal 或适用国家的银行转账。费用因目的地而异；PayPal 页面列约 1.5%，非 USD 账户可能另有转换费。填写金额后，以最终确认页面显示的费用和到账总额为准。

官方概览的收入分配约为平台 30%、创作者 50%、VRChat 及合作方 20%，属于完整资金流程的近似比例，不是把商品 Credits 再简单减半的公式。不要将用户购买 Credits 的价格直接当成卖家到账价，也不要对已显示的净额重复扣费。

较旧的 Welcome 页仍出现 30,000 Credits，较新的专项 Payout 页列 20,000。本章采用专项页数值，并保留日期；办理时仍需核对账户实际条件。

## 第四节：建立 UdonProduct 引用

在网站建立 Udon Product 后，在 Unity 使用 `VRChat SDK → Utilities → UdonProducts Manager` 取得对应资产，或通过 `Assets → Create → VRChat → UdonProduct` 手动创建并填入真实 Product ID。

至少一个场景中的 UdonBehaviour 必须引用对应 UdonProduct，上传世界才能接收该产品的购买事件。监听脚本保持启用，不能和待解锁对象一起被禁用。

Product ID 与 Listing ID 用途不同：前者用于查询权益，后者用于打开销售项。不要因两者都属于商店数据就混用。

官方 Example Central 提供 Udon Product Toggle 等预制体。选择本地或实例范围的版本，指定 Product、Targets 和默认状态，再测试加载、购买与到期。拖入预制体不等于商品已经建立或发布。

## 第五节：权益加载、查询与回调

常用接口的用途：

```cs title="Store 调用片段（变量由所在脚本提供）"
bool ownsProduct = Store.DoesPlayerOwnProduct(player, product);
Store.OpenWorldStorePage();
Store.OpenGroupStorePage(groupId);
Store.OpenListing(listingId);
```

`DoesPlayerOwnProduct` 不能在 `Start` 后立即被当成最终答案，因为购买数据可能尚未到达。以 `OnPurchasesLoaded` 区分“未加载”与“加载后没有权益”。

以下示例的命名空间与回调签名按 Worlds SDK 3.10.5 核对。完整示例显示本地已购内容，并用交互打开当前世界商店；用于持续持有的 Product，不适用于 Instant 消耗品：

```cs title="LocalProductAccess.cs"
using UdonSharp;
using UnityEngine;
using VRC.SDKBase;
using VRC.Economy;

public class LocalProductAccess : UdonSharpBehaviour
{
    public UdonProduct product;
    public GameObject unlockedContent;
    private bool purchasesLoaded;

    private void Start()
    {
        if (unlockedContent != null)
            unlockedContent.SetActive(false);
    }

    public override void OnPurchasesLoaded(IProduct[] products, VRCPlayerApi player)
    {
        if (!Utilities.IsValid(player) || !player.isLocal) return;
        purchasesLoaded = true;
        RefreshAccess();
    }

    public override void OnPurchaseConfirmedMultiple(
        IProduct purchased, VRCPlayerApi player, bool isJustPurchased, int quantity)
    {
        if (!Utilities.IsValid(player) || !player.isLocal) return;
        if (purchasesLoaded) RefreshAccess();
    }

    public override void OnPurchaseExpired(IProduct expired, VRCPlayerApi player)
    {
        if (!Utilities.IsValid(player) || !player.isLocal) return;
        if (purchasesLoaded) RefreshAccess();
    }

    private void RefreshAccess()
    {
        if (product == null || unlockedContent == null) return;
        VRCPlayerApi player = Networking.LocalPlayer;
        if (!Utilities.IsValid(player)) return;
        unlockedContent.SetActive(Store.DoesPlayerOwnProduct(player, product));
    }

    public override void Interact()
    {
        if (!purchasesLoaded)
        {
            Debug.Log("[Store] Purchase data is not loaded");
            return;
        }
        Store.OpenWorldStorePage();
    }
}
```

脚本挂在始终启用的交互对象上，`unlockedContent` 指向另一个对象，不能指向监听脚本自己或其父物体。填入 Product 引用，确认世界商店存在；面向玩家的版本还应有清晰的加载和错误提示。

`OnPurchaseConfirmedMultiple` 也会在恢复既有购买时触发，`isJustPurchased` 用于区分新购买，`quantity` 表示本次购买数量。不要同时实现已弃用的单数版和 Multiple 版处理同一奖励。

### 列出商品持有者

`Store.ListProductOwners` 异步返回某个产品的持有者显示名，范围包括不在当前实例的人；它不等于查询某位在场玩家的权益。只有需要展示这类名单时才使用，也不要用显示名作账号标识或门禁判断。

在 VRChat 网站 `Marketplace → Storefront → My Products` 编辑对应 Udon Product，启用 `Owner Names in Udon` 并保存；Udon 接口页也把它写作 `Owners Names in Udon`。没有启用时，官方说明该回调不会触发。产品说明应让购买者知道名单的展示用途。

以下小例把返回结果显示到 TMP 文本，最多显示前 20 个名字。它们按返回顺序排列，不表示消费排名：

```cs title="ProductOwnersBoard.cs"
using UdonSharp;
using UnityEngine;
using TMPro;
using VRC.Economy;

public class ProductOwnersBoard : UdonSharpBehaviour
{
    public UdonProduct product;
    public TMP_Text namesText;
    private float nextRequestTime;

    public override void Interact()
    {
        if (product == null || namesText == null)
        {
            Debug.LogError("[Owners] Missing product or namesText");
            return;
        }
        if (Time.time < nextRequestTime) return;
        nextRequestTime = Time.time + 10f;
        namesText.richText = false;
        namesText.text = "正在请求名单；尚未收到结果";
        Store.ListProductOwners(this, product);
    }

    public override void OnListProductOwners(IProduct result, string[] owners)
    {
        if (result == null || product == null || namesText == null) return;
        if (result.ID != product.ID) return;
        if (owners == null)
        {
            namesText.text = "未取得名单数据";
            return;
        }

        string display = "返回的持有者数：" + owners.Length + "\n";
        int count = Mathf.Min(owners.Length, 20);
        for (int i = 0; i < count; i++)
            display += owners[i] + "\n";
        if (owners.Length > count) display += "本面板仅显示前 20 名";
        namesText.richText = false;
        namesText.text = display;
    }
}
```

建立一个带 Collider 的交互对象，只挂这一份 Udon 脚本，保持对象启用；同对象多份 UdonBehaviour 可能影响此接口。另建 TMP 文本并拖入 `namesText`，把产品资产拖入 `product`；回调接收者 `this` 就是发起请求的脚本。10 秒间隔只减少本地重复请求，不是接口速率保证。

先在 ClientSim / 本地测试交互，预期显示 `VRCat`、`Fred`、`VRRat` 这组占位姓名，不能据此证明真实持有者名单已加载。再用已上传的测试版本核对真实结果，比较产品 ID、网站开关和回调内容；没有回调时保留“尚未收到”的状态，不能当成零持有者。回调确实返回空数组时才显示数量 0。每台客户端各自请求，名单不会因为写入 TMP 就自动同步。

## 第六节：持久化、共享效果与安全边界

Creator Economy 记录购买权益；PlayerData 记录该玩家在该世界的选择或进度，例如选择的装饰颜色。PlayerData 不自动跨世界共享，也不应以一个普通 bool 替代购买验证。

本地 `SetActive` 不会自动让其他玩家看到相同结果。公共效果需要自己的同步状态。对于仅允许持有者发起的产品事件，可以核对官方 `Store.SendProductEvent` / `OnProductEvent`；平台在该事件路径中执行产品校验。

购买记录来自平台，不代表世界中的所有客户端逻辑都无法被绕过。不要承诺一个本地 Animator 门或布尔分支具有服务端级访问安全。

## 第七节：商品合规与外部销售

根据当前 Content Guidelines 检查：

- 有权销售和分发所含内容，第三方许可覆盖实际用途。
- 商品名称、价格、期限、平台差异和使用世界清楚，没有误导预览。
- 不采用虚假倒计时、诱导或其他暗黑模式。
- 不用 Credits 作为募捐渠道。
- 同等世界权益在平台内可以实现时，按规则同时提供 Creator Economy 购买。
- 不把平台内商品说明用于宣传站外更低价购买或引导退款后改用其他支付方式。

Booth、Gumroad 或其他服务可用于其允许的源文件等交易，但费用、退款、授权和交付条件各不相同。不要以固定抽成表代替当前条款核对，也不把“支持创作者”文案当成所有商品与募捐限制的例外。

商品说明示例：

```text
名称：观景室装饰套装
内容：三组指定装饰，可在个人设置中切换
范围：<世界名与链接>
期限：<Listing 实际持有方式>
平台：<经测试的平台与差异>
价格：<商店显示的 Credits>
售后：<官方取消/退款规则与问题反馈入口>
```

## 首件商品的实施顺序

可先选一个范围明确的 Permanent Listing，例如一件可选的本地装饰；这是缩小测试范围的方案，不是平台要求。

1. 从官方入口核对资格并申请；按[卖家与 Tilia 入驻](#第二节卖家与-tilia-入驻)完成账号步骤。等待期间可在工程副本准备装饰、说明和测试清单，不预估审核完成日。
2. 获得权限后，在网站建立 Udon Product；到 `Storefront → My Listings → Create Listing` 选择 Permanent、加入该 Product、填写名称、价格与准确内容，先保存为草稿。Listing 的期限类型创建后不能更换，创建前确认选择。
3. 按[建立 UdonProduct 引用](#第四节建立-udonproduct-引用)取得资产，完成 `LocalProductAccess` 或官方 Product Toggle 的接线。把商品区的 Collider、监听脚本和待解锁对象分开，确认实际变化符合商品说明。
4. 使用 [Testing Udon Products](https://creators.vrchat.com/economy/sdk/testing/) 的 ClientSim 测试面板切换持有状态，执行[集成验收](#集成验收)。随后上传测试版本，核对 Product 引用与回调；记录哪些只做了模拟、哪些已在客户端确认。商店尚未发布时，把购买入口记为待验，不把打不开草稿算成权益脚本错误。
5. 确认内容、许可与说明后发布 Listing。在网站 Store Manager 选择 `Set Up New Store → World Store`，选中目标世界并创建商店，加入已发布的 Listing，再发布商店。按[World Stores 官方步骤](https://creators.vrchat.com/economy/store/world-store/)核对世界关联，进客户端验证入口、已购重入与两个账号权益差异。保存发布记录和反馈入口，遇到说明不符先处理对应功能。

官方测试页说明，本地测试或以世界／群组作者身份测试时不会扣除 Credits；本地购买会在 60 秒后模拟到期，不能用来判断 Permanent 的线上期限。其他账号执行真实购买前，应确认实际费用与由谁承担；免费测试不验证结算和提现。

购买入口的可选布置：小屋中放有“装饰商品”标识的展示台；展厅在相关作品旁放“查看商品内容”按钮；游戏在结算页放可关闭的商品入口。都应说清出售内容，让玩家主动打开商店，不把邮筒或“支持”字样包装成无明确商品的募捐，也不预判这些位置的转化率。

## 集成验收

分别测试：未持有、数据尚未加载、已持有后进入、新购买、到期、离开再进入，以及两个玩家权益不同的情况。使用官方测试工具模拟交易；模拟通过不等于真实购买、结算和提现已经验证。

版本更新时，把商品说明与实际解锁内容再次比对。停止或改变服务前，核对对已购用户的义务与平台规则。
