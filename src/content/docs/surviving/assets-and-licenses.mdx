模型、纹理、音乐、字体、Shader 和脚本都可能来自外部。引入前需要确认权利来源、许可证与实际用途是否匹配。能下载或已经付款，不表示获得了任意修改、商业使用和再分发权限。

本章提供记录与核对方法，不对具体争议作法律结论。授权不明确或涉及商业合同、权属争议时，向权利人取得书面澄清，必要时咨询合格专业人士。

## 第一节：把使用方式拆开

对每件素材分别检查：

| 动作 | 需要核对 |
| :--- | :--- |
| 放进私有工程 | 使用许可、工具安装或席位范围 |
| 修改素材 | 是否允许改动，需保留哪些声明 |
| 上传 VRChat 世界 | 是否允许嵌入和平台分发 |
| 收费、赞助或品牌活动 | 商业用途是否覆盖这种方式 |
| 分享工程 / Prefab | 是否允许向合作者或公众分发源数据 |
| 展示或播放 | 图片、字体、音乐、视频各自的相关权利 |

看不到许可声明时，不把它当作已经获准使用。版权、法定例外和公有领域判断依地区及作品而异；工程记录应保存实际依赖的许可依据。

## 第二节：Booth 个别规约

Booth 商品可能附作者自己的利用规约，也可能采用许可证模板。阅读商品页、下载包内文件与附加说明，保存取得时的版本和日期。

日语字段可作为检索线索：

- `改変`：修改范围。
- `商用利用`：商业用途及条件。
- `再配布 / 二次配布`：再分发。
- `法人利用`：组织或公司使用的范围。
- `クレジット表記`：署名要求。
- `特記事項`：补充条件。

这些词的具体含义由该份规约定义。不要把 `個人利用` 一律翻成非商业，也不要认为“作为世界上传”必然不属于作者限制的分发行为。

若规约写“商用利用は応相談”，说明商业用途需要另行商谈。询问时说明平台、是否公开、是否收费或接赞助、是否修改、是否向合作者提供源文件，并保留作者答复。

## 第三节：VN3 License

VN3 提供虚拟内容许可模板。实际授权是作者提供的完整条款、个别选择与补充说明，不是 VN3 标志本身。

核对允许的使用主体、平台、修改、商业利用、分发和署名；未列出的用途不要自行推断为允许或禁止。若个别条款与通用说明看似冲突，先保存原文并向授权方澄清。

不同资源即使都使用 VN3，也可能有不同勾选和补充条件。台账记录实际许可证文件或链接，不只写“VN3，可用”。

## 第四节：Unity Asset Store

Asset Store 的资源一般适用标准 EULA，但也存在 Restricted Assets、单独供应商协议和第三方组件许可。应查看商品标注与随附条款，而不是假定所有资源完全相同。

标准许可下，符合条件的资源可嵌入包含实质原创内容的产品；它不等于可把原始模型、贴图或工具重新打包出售。是否满足嵌入条件、商业使用和 UGC 相关限制，要按实际产品核对。

团队使用还要区分普通资源的 Single Entity / Multi Entity 与 Extension Asset 的席位许可。把付费工具提交到私有仓库，不会自动给每位合作者补齐席位。

许可证中的限制应完整保留。例如当前 EULA 对未经明确同意将商店或资源用于 AI / 机器学习训练及相关输入用途有专门限制；这是许可记录的一部分，不是使用教学。

## 第五节：Creative Commons

CC 许可证的名称包含不同条件，还需记录版本：

| 条件 | 核对含义 |
| :--- | :--- |
| BY | 适当署名、许可证链接，以及需要的修改说明 |
| NC | 仅限许可证定义的非商业用途 |
| ND | 不允许按该许可分享改编作品；不能简化成任何私人修改都禁止 |
| SA | 分享改编作品时使用规定的相同或兼容许可 |

CC0 是尽可能放弃版权及相关权利的工具，但并不自动清除他人的商标、肖像、隐私等权利。CC BY 等也不是“署名后没有其他条件”。

收费、赞助或品牌用途与 NC 是否兼容，不能仅按“没有门票”判断。授权不覆盖时，换用适用素材或取得额外许可。

署名记录示例，以下名称与地址为占位：

```text
作品：Old Pump
作者：ArtistName
来源：<原作品页面>
许可证：CC BY 4.0，https://creativecommons.org/licenses/by/4.0/
修改：调整模型比例，重新制作碰撞体
```

把署名放在玩家可访问的 Credits 或说明中，并按许可证要求保留完整声明。只在不对玩家开放的私有仓库写一条记录，未必满足公开发布时的署名要求。

## 第六节：代码许可证

脚本、Shader 与编辑器工具分别核对所用版本中的 LICENSE、NOTICE 和第三方依赖。

- **MIT**：保留版权和许可声明；许可允许的使用范围较广，但不免除其他适用权利。
- **Apache 2.0**：除许可证外，还需核对修改标记、NOTICE 与专利条款等义务。
- **BSD**：版本不同，条款也不同，按实际文本处理。
- **GPL / AGPL**：分发、链接、修改及网络交互等条件可能触发相应源码义务，不能简化成“所有项目都必须公开”或“只要不用服务器就无影响”。

使用某个 MIT 许可工具，不会自动改变项目里所有素材的许可证。发布工程或售卖 Prefab 时，应逐项检查能否包含第三方代码与资源。

## 第七节：平台条款与真实来源

VRChat 上传还需符合平台服务条款与创作者规则。素材作者允许某种用途，不代表平台必然允许；平台可上传，也不能证明素材已获授权。

粉丝创作、游戏导出素材和品牌图案的授权需核对权利人政策。免费分享、修改了外观或仅放在 Private 世界，都不能自动解决权属问题。

真实制作来源、作者名、许可证与依法需要的声明应保留。某件资源有明确的生成或加工来源时，台账如实记录；不能为了精简正文而改写 provenance。台账用于追溯，不能把来源记录本身当成权利证明。

## 第八节：素材台账

项目可维护 `LICENSES.md`，随版本控制保存；凭证和私密授权材料放在访问范围合适的位置，不把个人信息公开到玩家 Credits。

```markdown title="LICENSES.md（占位模板）"
# 第三方素材记录

## FactoryPipes
- 类型：模型
- 作者：<作者名>
- 来源：<原始商品或发布页>
- 获取日期：<日期>
- 版本：<资源版本>
- 许可证：<名称、版本、文件路径或原始链接>
- 获准用途：<VRChat 上传、商业使用、修改等具体范围>
- 源文件分发：<合作者与公开分发范围>
- 修改：<实际改动>
- 工程位置：Assets/Art/FactoryPipes/
- 使用场景或 Prefab：<位置>
- 署名位置：<世界内 Credits 或发布说明>
- 补充授权：<授权记录索引，无则写无>
- 待确认事项：<明确问题，无则写无>
```

模型、音频、字体、代码和 Shader 都采用同样的字段。许可证全文、商品页快照与购买凭证按需要保存；购买凭证证明交易，不自动证明卖家拥有全部权利。

### 两条填写示例

以下资源和作者为虚构教学例子，假设已经取得所列许可，不代表某个真实素材已获授权。实际记录必须换成已核对的原始页面、版本与许可文本。

```text
代码：DoorHelper 1.0；作者：ExampleCoder
来源：<该版本的原始仓库链接>；获取日期：2026-10-01
许可：MIT；全文与原版权声明：Assets/ThirdParty/DoorHelper/LICENSE.txt
用途：本世界的本地门；工程位置：Assets/ThirdParty/DoorHelper/
修改：增加缺少 Animator 引用的错误提示
分发检查：随代码副本保留版权与许可全文；其他依赖分别登记
玩家 Credits：列出名称、作者与来源；不能用这一行替代包内许可证
待确认：无；补充授权：无

音频：RoomTone.ogg；作者：ExampleRecorder
来源：<该录音的原始页面>；获取日期：2026-10-01
许可：CC BY 4.0；链接：https://creativecommons.org/licenses/by/4.0/
工程位置：Assets/Audio/RoomTone.ogg；使用位置：TestRoom/RoomAudio
修改：裁去头尾静音、调整音量
署名：世界内 Credits 写作品、作者、原始来源、许可链接及上述修改
分发检查：保留适用的署名与许可信息；另查录音中的第三方权利
待确认：无；补充授权：无
```

代码示例指出许可全文放在哪里；音频示例指出玩家在哪里能读到署名。把两项用于正式工程前，分别打开记录中的位置检查一次；只有台账里写“已署名”，实际文件或面板没有内容，仍未完成核对。

## 练习：核对当前工程

1. 列出所有外部素材及项目内位置。
2. 找回原始发布页与许可证，标明未确认事项。
3. 对照实际上传、合作和商业用途逐项核对。
4. 将玩家可见的署名与台账比对，补充遗漏的许可证链接和修改说明。
5. 对无法确认权利的素材，暂缓使用或准备有明确许可的替代品。
