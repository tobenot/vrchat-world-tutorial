Prefab 把一组 GameObject、组件和配置保存为可复用资源。场景中的实例与这个资源保持联系，未被实例单独覆盖的属性可以随资源更新。

## 创建带点光源的 GlowBall

1. 在 Hierarchy 右键 `3D Object → Sphere`，命名 `GlowBall`，Position 设为 `0, 1.5, 0`。
2. 选中它，使用 `Add Component` 添加 `Light`。
3. 将 Type 明确设为 `Point`，Range 设为 `5`，Intensity 设为 `2`，Color 设为偏暖的橙黄色。
4. 将光源 Mode 设为 `Realtime`，Shadows 设为 `None`，观察周围受光表面。

这里的 `GlowBall` 是球体模型与 Point Light 的组合。Light 照亮周围，不代表球体材质本身具备 Emission；在未配置材质时，球体可以仍显示默认表面。

需要给球本身配色和自亮时，使用[灯球材质的创建与赋值步骤](/workbench/materials-light/#给灯球设置-emission)。它与 Light 的颜色分别设置，不把灯光颜色当作材质引用。

## 直接复制与 Prefab 的区别

直接复制一个普通场景对象，会得到独立配置。若有四个独立灯球，统一调整 Range 时需要同时选中它们批量修改，或逐个修改。

Prefab 则把共有配置保存在一处。实例可以使用各自的位置，同时继承资源中的 Light 参数。是否采用 Prefab，取决于这些对象是否需要共享配置和统一维护，不存在必须达到几次复制的固定门槛。

## 创建 Prefab 资源

1. 在 Project 的 `Assets` 下新建 `Prefabs` 文件夹。
2. 把 Hierarchy 中的 `GlowBall` 拖入这个文件夹。
3. 确认 Project 中生成 `GlowBall.prefab`，场景对象变为 Prefab 实例。
4. 保存场景。

Project 中的是资源，Hierarchy 中的是实例。两者不是同一个对象；修改范围取决于当前编辑的是哪一处。

## 创建多个实例

将 Project 中的 `GlowBall.prefab` 拖入场景三次，得到三个新增实例。分别命名为 `GlowBall_A`、`GlowBall_B`、`GlowBall_C`，并放在房间不同位置。

实例根物体的位置和旋转可以各自不同，适合把同一灯具摆在不同区域。这些位置差异不要求创建四份独立资源。

## 修改共有配置

1. 双击 Project 中的 `GlowBall.prefab`，进入 Prefab Mode。
2. 将 Light 的 Range 从 `5` 改为 `8`。
3. 保存 Prefab，并返回场景。
4. 逐个选择实例，检查 Range。

没有覆盖 Range 的实例会显示 `8`。这个更新是 Unity 编辑资源的行为，与 VRChat 多人网络同步无关。

## Override：实例覆盖

选中场景中的 `GlowBall_C`，单独将 Light 颜色改为绿色。Inspector 会标识它与 Prefab 资源的差异，这就是 Override。

此时修改 Prefab 的 Range，`GlowBall_C` 仍可继承新范围；修改 Prefab 的颜色，实例的绿色覆盖会保留。覆盖是按具体属性或结构记录的，不是把整个实例全部断开。

在实例的 Overrides 菜单里：

- **Revert**：撤销选定覆盖，恢复资源中的值。
- **Apply**：把选定修改写回 Prefab 资源，影响其他没有覆盖该属性的实例。

执行 Apply 前核对资源和属性，避免把某个位置专用的配置写成全部实例的共有设置。若一组实例需要共同保留另一套配置，可以创建 Prefab Variant，使差异有明确的资源来源。

## Unpack 的作用

对实例使用 `Unpack Prefab`，会解除它与对应 Prefab 资源的连接，同时保留场景中当前的物体和配置。资源的后续修改不再传播到这份解包对象。

存在嵌套 Prefab 时，普通 Unpack 与 Unpack Completely 的范围不同。需要保留内部嵌套资源联系时，先检查层级和菜单选项。解包不等于删除磁盘上的原 Prefab。

## 项目资源分类

以下结构可以按资源类型区分文件：

```text
Assets/
├─ Scenes/       场景
├─ Prefabs/      预制体
├─ Materials/    材质
├─ Audio/        音频
└─ Scripts/      脚本
```

在 Unity 的 Project 面板中移动资源，可以同时维护对应的 `.meta` 文件及引用。分类方式可以调整，关键是同类资源位置明确、移动后引用仍然有效。
