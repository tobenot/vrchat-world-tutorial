当前场景有地板、两面侧墙和带 Point Light 的 `GlowBall`。本章给它们设置材质，再调整方向光和局部光，检查颜色、亮度和可见范围。

本章示例使用 Unity 内置渲染管线和 PC 世界。其他 Shader 的字段、光照模型及移动平台支持可能不同，不能直接照搬所有参数。

## 比较同一场景中的光照变化

选中 `Directional Light`，记录原值，分别执行以下修改：

1. 将 Intensity 改为 `0.2`，观察地板和墙面。
2. 改为 `1.5`，比较受光表面的亮度。
3. 保持强度不变，把 Color 分别改为浅蓝和淡黄。

材料、天空环境光、其他灯光和后处理都会影响最终结果。若变化不明显，确认 Scene 视图启用了场景光照显示，并检查是否还有其他强光源。

这个对照只改变一项条件，便于区分强度和光色的作用。

## 材质与光共同决定表面外观

对于本章使用的受光 Shader，表面颜色受基础颜色、纹理、光色、光强、表面法线和观察方向等因素影响。间接光照、反射和 Emission 也可能参与。

同一面米白墙在偏蓝光下可能呈灰蓝，在偏黄光下可能呈暖黄。材质色板并不是最终屏幕颜色。排查颜色差异时，需要一起核对材质和照明条件。

## Material、Shader、Texture

- **Shader**：定义如何计算并绘制表面。
- **Material**：保存所选 Shader 及其具体参数。
- **Texture**：可被材质引用的纹理资源，例如木纹颜色、法线或发光图案。

Mesh 决定形状，Renderer 通过材质决定如何显示它。同一材质可以被多个物体共享；修改共享材质会影响所有使用它的 Renderer。需要独立外观时，创建另一份材质。

本章使用内置 `Standard` Shader。它的基础颜色字段叫 `Albedo`；其他 Shader 可能使用 `Base Color` 等名称，字段相似不代表整个 Shader 与项目管线兼容。

## 创建地板和墙面材质

1. 在 Project 的 `Assets` 下创建 `Materials` 文件夹。
2. 右键 `Create → Material`，命名 `Mat_Floor_WarmGray`。
3. 确认 Shader 为 `Standard`，Albedo 色值填 `#8A8178`。
4. Metallic 设为 `0`，Smoothness 设为 `0.25`。
5. 将材质拖到 `Floor`，在其 Mesh Renderer 的 Materials 槽中核对引用。

再创建墙面材质：

1. 新建 `Mat_Wall_OffWhite`，使用同一个 Shader。
2. Albedo 设为 `#D8D2C4`，Metallic 设为 `0`，Smoothness 设为 `0.15`。
3. 拖到 `Wall_Left` 和 `Wall_Right`。

这些操作改变表面外观，不会改变物体形状或 Collider。两面墙共用材质，修改这份材质时两面墙都会更新。

## 四个材质参数

- **Albedo**：表面的基础颜色，可与颜色贴图共同使用。
- **Metallic**：在 Standard 的金属度工作流中，`0` 对应非金属，`1` 对应金属；中间值可用于混合表面。
- **Smoothness**：影响反射与高光的集中程度，较低值产生更粗糙的表面效果。
- **Emission**：为表面增加自发光颜色和强度。

示例中的墙和地板按非金属表面配置。Smoothness 数值是本例的起点，需要结合光照与反射观察，不是所有墙面或地板的固定值。

## 给灯球设置 Emission

1. 创建 `Mat_GlowBall_Cyan`，使用 `Standard` Shader。
2. Albedo 设为 `#6EE7F9`。
3. 勾选 Emission，设置为同样的浅青色。
4. 本次对照将 Emission 的 Global Illumination 设为 `None`。
5. 将材质赋给 `GlowBall` 的 Renderer。

如果做霓虹字牌时发现字牌亮了、墙没被照亮，说明**可能只是材质 Emission 自亮，而没有实际 Light 照到墙面，也没有有效的发光烘焙贡献**。需要区分三种情况：

- **只显示自亮表面**：Emission 的全局光照贡献为 None 时，材质自身仍可见地发亮，不会因此自动照亮邻近物体。
- **实时 Light 照明**：启用 Point 或 Spot Light，设置范围和强度，受光表面还需要使用支持相应光照的 Shader。移动或切换这盏实时灯，可以改变当前照明。
- **烘焙发光贡献**：支持烘焙发光的材质配合 Baked GI、参与全局光照的对象及有效的接收表面配置，重新生成光照数据后，可以把发光对静态环境的贡献写入 Lightmap；配置好的 Light Probes 也可把烘焙光照提供给动态对象。运行时修改 Emission 不会自动重算已经烘焙的光照。

因此，「材质自亮」与「周围受到照明」需要分别检查，不能断言发光材质永远不照亮环境，也不能断言勾上 Emission 就能得到实时照明。参见 [Unity：Emission](https://docs.unity3d.com/2022.3/Documentation/Manual/StandardShaderMaterialParameterEmission.html)。

当前练习采用第一种表面外观加第二种实时灯光，不依赖发光烘焙。

:::caution[材质显示粉色]
粉色表示当前 Shader 无法正常使用，可能涉及丢失、编译失败或渲染管线不兼容。检查材质的 Shader、Console 中的相关错误及资源支持的平台。可以用当前项目支持的 Standard 材质做对照，确认问题来自网格还是原 Shader；这不是所有平台的通用材质替换方案。
:::

## 用纯色检查明暗和区域区分

本例用暖灰地板、米白墙和浅青灯球，便于观察照明对表面的影响。纯色省去了贴图图案的干扰，但不决定场景必须采用哪种美术风格。

从玩家视点检查地板与墙面的边界是否清楚、灯球是否能与背景区分，以及亮部是否因曝光或后处理丢失细节。底色、光强和反射都可以调整。

## 光源类型

- **Directional Light**：平行方向光，可模拟远距离光源。方向由 Rotation 决定，位置不影响它的照射方向与距离衰减。
- **Point Light**：从一点向各方向照射，在设定范围内随距离衰减。
- **Spot Light**：向一个方向形成锥形照射范围。
- **Area Light**：面光源。在本章使用的内置渲染管线中，Area Light 用于烘焙，不能当作同样的实时局部灯。

本例使用 Directional 与 Point 两种类型。

## 配置方向光

将 `Directional Light` 的 Rotation 设为：

```text
X = 50
Y = -30
Z = 0
```

Light 参数设为：

```text
Mode      Realtime
Color     #9AB4C8
Intensity 0.35
```

这会改变主方向光的光色和强度，但不会自动修改 Lighting 窗口中的天空盒环境光。

旋转光源并观察地板上的阴影方向。这里的 Euler 角以当前父级和变换为前提；存在旋转父级时，同一组局部角度不一定得到相同世界方向。需要对照时，让光源不受额外父级旋转影响。

## 阴影的条件和成本

需要实时阴影时，在方向光的 Shadows 选项中启用 Hard 或 Soft Shadows，并检查 Renderer 的投射、接收阴影设置以及质量设置的阴影距离。

阴影可以表达物体接触、遮挡和光源方向，但并非每种美术风格都需要它。实时阴影需要额外渲染，成本受灯光类型、范围、阴影分辨率和投射物体数量影响。

这个小场景可以保留主方向光的阴影，把装饰性 Point Light 的 Shadows 设为 None，再比较画面与性能。

## 配置局部点光源

选中 `GlowBall`，确认已有 Light 组件；如果缺少，再添加。设置：

```text
Type      Point
Mode      Realtime
Color     #FFE0B0
Intensity 2.5
Range     4
Shadows   None
```

将球放在靠近侧墙的位置，例如 `3.5, 1.5, 0`，避免目标墙面超出范围。保存并 `Build & Test`，对比灯附近的墙面、地板与远处区域。

在当前尺寸和参数下，局部区域受到偏暖光照，其余部分主要受方向光与环境光影响。发光球材质的青色与 Light 的暖色是两套独立参数；需要一致外观时，可以将它们设成接近的颜色。

## 调整光色、亮度和对比

冷色整体照明加暖色局部照明，是本例的一种配置。也可以反向设置，或只用同色不同强度来区分区域。

检查时分别回答：

1. 入口、通道和地面边缘能否辨认？
2. 局部灯照到的是目标区域，还是范围外的墙面？
3. 亮区是否过曝，暗区是否遮住了需要识别的物体？
4. 从出生点和房间两侧观察时，明暗关系是否仍符合需求？

用途决定检查条件。例如，展品的细节需要可见，游戏中的操作目标需要可辨认。不能只凭冷暖或整体亮度推断玩家是否愿意停留。

## 控制实时光照开销

实时灯数量不是唯一成本指标。影响范围重叠、阴影、Shader 和设备性能都会改变开销，所以不能保证「两三盏灯在任何设备上都没压力」。

- 使用能覆盖需要区域的范围，避免无效照射。
- 不需要投射阴影的局部灯可关闭阴影。
- 只需要表面亮起的装饰物，可以只使用 Emission。
- 固定照明可评估烘焙方案，但要同时检查静态接收、动态对象和平台条件。
- 在目标设备上测帧率与渲染成本，不能仅凭 Scene 视图判断。

Android/Quest 的 Shader 与性能限制需独立核对，PC 上可用的 Standard 材质和实时光照配置不能作为移动版通过测试的依据。

## 修改没有生效时

1. 检查 Renderer 是否实际引用了目标材质，修改的是否是另一份同名材质。
2. 检查是否在 Play Mode 修改过场景字段，退出后是否恢复。
3. 检查 Light 是否启用、Mode 是否符合当前测试方式，以及 Range 是否覆盖接收表面。
4. 检查其他光源、环境光和 Emission 是否掩盖了变化。
5. 检查 Scene 视图的光照显示与渲染模式，并用客户端作对照。
6. 使用烘焙时，检查光照数据是否重新生成；实时字段变化不会自动更新旧烘焙结果。

## 三组光照对照

保留相同模型，记录三组参数并分别测试：

1. 全局光较弱、偏冷，局部暖光较弱。
2. 全局光较强、偏暖，改变主光方向。
3. 全局光很弱，局部光承担主要照明。

每组都记录材质、光色、Intensity、Range 和阴影设置。在客户端从相同位置观察，比较墙地边界、物体细节和通道可见性。这些结果可以说明各参数改变了什么。

把同一站位的截图缩到相同大小，标出希望突出的灯球与入口，检查它们能否与背景区分。若要找出具体原因，先恢复一组基线，只改 Intensity，再恢复并只改光色，最后单独改方向；不要把三项同时变化的结果归因于其中一项。缩略图用于检查整体明暗，实际距离的文字与边缘仍需在客户端查看。
