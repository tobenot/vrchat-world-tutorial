一个场景概念需要转换成可创建和可检查的项目内容。例如，「带雨景的小屋」可以拆成房间结构、窗外景物、材质、灯光和音频等任务。概念中的内容不等于当前场景已经具备的内容。

按本部操作得到的是地板、两面侧墙、灯球、基础材质和光照。它仍是基础房间结构，没有自动包含窗户、桌椅、雨景或声音。

## 将目标列为对象清单

以下是一份小屋的设计清单示例，不是已经完成的 Hierarchy：

```text
房间结构：地板、侧墙、后墙、窗户
陈设：桌子、椅子
照明：整体光照、局部灯具
声音：雨声音频及播放设置
```

每项继续写明所需资源与组件：桌子需要模型、材质以及按需求配置的碰撞；灯具需要可见外观，照明则选择 Light 或合适的烘焙方案；雨声需要音频和 Audio Source，并明确播放条件。

如果只需要可见的椅子模型，就不必同时承诺坐下功能。需求包含座位时，再把站点位置和相应组件列为单独任务。

同一清单还可以展开为计划中的层级，逐项填写实施落点：`Room/Floor` 是地板，`Room/Window` 是待建窗户，`Furniture/Table` 是待建桌子，`Lighting/Lamp_Warm` 是待配置的局部光源，`Audio/Rain` 是待导入音轨及配置播放条件的音源。只有实际创建后才将该项标为已有；层级图本身不代表场景已经完成。

## 将外观目标转换为参数

「偏暖、局部较亮」可以写成可比较的设置：墙材质采用米白底色，方向光采用偏冷光色，角落 Point Light 采用偏暖光色。检查的是墙面与地面是否能分辨、通道是否可见，以及局部灯是否确实照到目标区域。

颜色并不能保证玩家产生某种情绪。光照结果还受到材质、强度、遮挡、视角和设备显示的影响，需要从玩家视点观察。

## 确定重复配置

如果多盏壁灯需要共同调整范围、强度和材质，可以保存为同一个 Prefab。只针对某个位置的差异用实例覆盖；多处共享另一套差异时，可以使用 Variant。

清单中同时注明「共有配置」和「实例差异」，能帮助判断一次修改应写到哪个位置。

## 给任务写完成条件

| 任务 | 完成条件 |
| :--- | :--- |
| 地板与墙壁 | 尺寸符合设定，碰撞测试通过 |
| 出生位置 | 位于可站立表面上方，朝向入口或主要区域 |
| 基础材质 | 指定 Renderer 使用正确材质，无丢失 Shader |
| 局部照明 | 指定区域亮度有变化，通道仍清楚可见 |
| 重复灯具 | 共用 Prefab，实例覆盖范围明确 |

为每项标记「已有、需要修改、未制作」，再记录对应的对象名或资源路径。这样的清单既能表达设计，也能说明当前完成到哪里。

另记三条可验证的问题：从指定 Spawn 第一眼应看见哪个对象；哪条开口通向下一处目标；必须操作的按钮控制哪个对象。用空 Cube 或文字占位也可以先检查视线和路线，但要在清单里写明替换任务。按[出生区无文字盲测](/placeness/first-thirty-seconds/#日夜对照与无文字盲测)记录实际路线，再决定是否调整光线、开口或标识。
