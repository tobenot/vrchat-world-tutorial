VRChat 由 VRChat Inc. 开发和运营。客户端、账号、世界访问和多人会话属于平台；创作者使用 Unity 和官方 SDK 制作上传内容。区分这几层，可以判断一个问题应当查 Unity 文档、SDK 文档还是客户端设置。

## Unity 与 VRChat 的分工

Unity 是通用游戏引擎。场景中的模型渲染、物理碰撞、动画和音频依赖 Unity 的相应系统。VRChat 在这些能力之上提供玩家、化身、世界实例、网络同步和内容加载等功能。

Worlds SDK 是安装在 Unity 项目中的开发工具与组件集合。它负责校验场景、配置 VRChat 所需信息、构建和上传世界，也提供 Udon 开发工具。它不是另一个完整游戏引擎。

例如，一块地板由 Unity 的 Mesh Renderer 显示、由 Collider 提供碰撞；玩家的出生位置由 `VRC Scene Descriptor` 的配置确定。这些部分协同工作，不能都归为某一种脚本。

## Worlds 与 Avatars

- **Worlds（世界）**：玩家进入的场景，例如房间、展厅或游戏关卡。
- **Avatars（化身）**：玩家使用的角色形象。

VCC 提供对应项目模板。制作世界选择 World 模板，使用 Worlds SDK；制作化身使用 Avatars SDK。两者的内容结构、校验要求和上传对象不同，本书中的「SDK」默认指 Worlds SDK。

世界项目中能看到以下官方包；实际安装项和版本以 VCC 的项目包列表为准：

```text
com.vrchat.base       SDK 共用基础设施
com.vrchat.worlds     世界组件、Udon 开发工具与编辑器测试工具
```

UdonSharp 和 ClientSim 都随 Worlds SDK 提供，不需要另外安装旧的独立包。ClientSim 用于在 Unity 编辑器中模拟部分世界行为，不是 Avatar 模板的测试工具。旧教程中的 `VRC_Trigger` 属于旧 SDK 工作流，与当前 Udon 事件系统不能直接互换。

## C#、.NET 和 Unity 的关系

**C# 是编程语言；.NET 是开发平台。** .NET 包含运行时、类库和开发工具等部分：

- **运行时（runtime）**负责代码执行、类型处理和托管内存管理等工作。
- **类库（libraries）**提供字符串、数学、集合、文件等现成类型和 API。某个类库存在，不代表所有运行环境都允许调用它。
- **编译器和工具**把源码转换成可执行形式，并协助构建、调试程序。

普通 .NET 项目通常先把 C# 编译成包含中间语言 IL 的程序集，再由运行环境执行。语言、类库和执行环境是三个不同概念。参见 [Microsoft：.NET 简介](https://learn.microsoft.com/en-us/dotnet/core/introduction)。

Unity 也使用 C# 和 .NET 生态，但不能等同于安装了最新现代 .NET 的普通应用。Unity 2022.3 使用其支持的 API 兼容范围和脚本后端：Mono 在运行时进行 JIT 编译，IL2CPP 将中间语言转换为 C++ 并预先编译为本机代码。编辑器与目标平台的执行环境也可能不同。因此，一段代码能在普通 .NET 项目中编译，不保证能用于 Unity，更不保证能用于 Udon。参见 [Unity 2022.3：.NET 概览](https://docs.unity3d.com/2022.3/Documentation/Manual/overview-of-dot-net-in-unity.html)。

## UdonSharp 写法与 Udon 执行环境

VRChat 世界的自定义运行逻辑使用 Udon。两种编写入口是 Udon Graph 和 UdonSharp：Graph 用节点组织逻辑，UdonSharp 用受支持的 C# 写法表达逻辑。

UdonSharp 将源码编译为 **Udon Assembly**，再生成 Udon 虚拟机执行的程序。Udon Assembly 是汇编形式的程序表示，不能直接把它与最终字节码当成同一种文件。运行世界时，Udon 程序通过允许的接口访问 Unity 和 VRChat 功能。

```text
C# 源码（受 UdonSharp 支持范围限制）
    → UdonSharp 编译
    → Udon Assembly / Udon 程序资产
    → 客户端中的 Udon 执行环境
    → 允许调用的 Unity 与 VRChat API
```

这是一条针对世界脚本的执行路径，不是把 VRChat 客户端或 Unity 的整个 .NET 环境替换掉。普通 Unity 编辑器脚本、SDK 工具代码和世界中的 Udon 程序也不能混为一谈。参见 [官方 UdonSharp 文档](https://creators.vrchat.com/worlds/udon/udonsharp/)。

## 可调用的 API 有边界

VRChat 要运行来自不同创作者的世界内容，因此 Udon 只开放指定的 API。例如，脚本可以修改受支持的 `Transform` 或 `Light` 属性，但不能任意读写玩家磁盘、启动外部程序或调用整个 .NET 类库。

检查方法是打开 Unity 菜单 `VRChat SDK → Udon Sharp → Class Exposure Tree`，查看类、方法和属性是否暴露给 Udon。绿色表示可用，红色表示未暴露。除了 API 是否开放，还要检查 UdonSharp 是否支持所用的语言特性。参见 [Class Exposure Tree](https://creators.vrchat.com/worlds/udon/udonsharp/class-exposure-tree/)。

限制 API 访问并不保证脚本低开销。反复执行的大循环仍可能影响帧率；工作量、执行频率和目标设备都需要测试。

## 官方组件不等于自定义 Udon 脚本

`VRC Scene Descriptor`、`VRC Pickup`、`VRC Station`、镜子等组件各有官方定义的行为。`Udon Behaviour` 则承载 Udon 程序。它们都能出现在世界里，但不能断言所有 SDK 组件背后都是 Udon 字节码。

配置出生点或镜子，不要求作者先编写一份 UdonSharp 程序。需要额外的事件响应时，可以在支持的组件和 API 上增加 Udon 逻辑。可用组件以 [官方世界组件列表](https://creators.vrchat.com/worlds/components/) 为准。

## 版本与平台

Unity 编辑器版本会影响资源构建和 SDK 兼容性。安装时使用 [VRChat 当前支持的 Unity 版本](https://creators.vrchat.com/sdk/upgrade/current-unity-version/)，由 VCC 管理项目依赖；不要依据普通 Unity 教程选择任意版本。

不同平台需要对应的世界构建。某个 Shader、组件或资源设置在 PC 上可用，不代表在 Android 或 iOS 上有相同支持。平台要求应同时查看 SDK 校验结果与 [官方平台文档](https://creators.vrchat.com/platforms/)。

## 社区资源的作用

模型、材质、Prefab 和开发工具可以来自创作者自己的制作，也可以来自社区。下载前核对资源许可、支持的 Unity/SDK 版本和目标平台；导入后检查它添加了哪些文件、组件与依赖。资源的宣传截图不能代替这些检查。

按用途查阅：[素材与工具入口](/appendix/resources/#资产平台)、[许可记录与导入检查](/surviving/assets-and-licenses/)、[定位可调用的 API](#可调用的-api-有边界)。选择第三方资源时，先列出它要解决的任务，例如补充一个静态模型或提供可配置的交互；再分别核对资产内容、安装依赖和使用许可。

本书的范围是用 Unity、Worlds SDK 和 Udon 制作 VRChat 世界。化身制作、VRChat 客户端内部实现以及通用 Unity 的全部功能不在这个范围内。
