本章创建一个能在 VRChat 中进入和移动的最小场景：地板、出生点、场景描述组件、默认天空和方向光。结果是本地测试世界，不会因测试而自动上传或公开。

## 场景需要满足的条件

1. **可以站立的表面**：地板具有启用的非 Trigger Collider。
2. **出生位置和朝向**：Transform 标记玩家出现的位置与面向。
3. **世界配置**：`VRC Scene Descriptor` 提供 SDK 所需的场景信息。

本章把出生点和描述组件放在两个物体上，便于单独调整。SDK 也支持使用描述组件所在物体作为默认出生位置，独立 `Spawn` 并不是所有世界都必须采用的结构。

## 第一步：新建并保存场景

打开[工具安装章](/getting-started/tools/)创建的 `MyFirstWorld` 项目。

1. 选择 `File → New Scene`，使用内置渲染管线的 Basic 场景模板。
2. 按 `Ctrl+S`，保存为 `Assets/Scenes/MyFirstWorld.unity`。目录不存在时先创建目录。
3. 确认场景中有 `Directional Light`。保存的是当前场景，不是另一个同名项目。

场景文件保存层级、组件配置和资源引用。尚未保存的编辑不会自动写入磁盘，构建前应保存当前修改。

## 第二步：创建地板

在 Hierarchy 空白处右键，选择 `3D Object → Cube`，命名为 `Floor`。在 Inspector 的 Transform 中填写：

```text
Position  0, 0, 0
Rotation  0, 0, 0
Scale     10, 0.2, 10
```

在默认比例下，它是一块 10 米见方、0.2 米厚的地板，上表面位于 Y = 0.1。保留默认 `Box Collider`，确认组件启用、`Is Trigger` 未勾选。

这里选择 Cube，是因为它同时提供有厚度的网格和简单的盒形碰撞体，尺寸便于核对。Plane 也能作为地板，其默认网格是细分平面；使用 Plane 时仍需检查碰撞和材质的背面显示规则。是否会穿透取决于具体碰撞配置和运动条件，不能仅凭模型类型判断。

## 第三步：标记出生位置

1. 在 Hierarchy 空白处右键 `Create Empty`，命名 `Spawn`。
2. Position 设为 `0, 0.2, 0`。
3. Rotation 设为 `0, 0, 0`。

这个点比地板表面高 0.1 米，避免放进地板内部。出生朝向由这个 Transform 的方向确定；改变 Y 轴旋转即可改变水平朝向。

## 第四步：添加场景描述组件

1. 新建空物体 `WorldDescriptor`。
2. 在 Inspector 点 `Add Component`，搜索并添加 `VRC Scene Descriptor`。
3. 展开 `Spawns` 列表；如果没有元素，添加一个元素或将 Size 设为 `1`。
4. 把 Hierarchy 中的 `Spawn` 拖入 `Element 0`。
5. 为了按指定点测试，把 `Spawn Radius` 设为 `0`，`Spawn Orientation` 选择 `Align Player With Spawn Point`。

场景只保留一个预期使用的 Scene Descriptor。如果模板场景已经包含它，使用现有组件，不再重复添加。SDK Builder 中的 `Add a VRCSceneDescriptor` 也是官方提供的添加入口。

## 第五步：Build & Test

1. 打开 `VRChat SDK → Show Control Panel`，在 Authentication 中登录 VRChat 账号。
2. 在 Builder 页处理阻止构建的校验项，包括 Layers、Collision Matrix 和 Scene Descriptor 等设置。
3. 选择 Windows 本地测试构建，客户端数量设为 `1`；使用键盘鼠标测试时开启 `Force Non-VR`。
4. 按 `Ctrl+S`，选择 **Build & Test**。
5. 等待构建完成和本机 VRChat 启动。

使用桌面模式时，以 `W`、`A`、`S`、`D` 移动，用鼠标转向。检查出生点是否在地板上、是否能停留而不下坠、转向和移动是否正常。

SDK 账号没有世界上传权限时，仍可以进行本地构建测试。正式上传的账号条件与本地测试不同，见[官方创建指南](https://creators.vrchat.com/worlds/creating-your-first-world/)。

:::caution[测试不符合预期时]
- **SDK 菜单缺失**：检查 Worlds SDK 包和 Console 中的编译错误。
- **缺少 Scene Descriptor**：确认当前打开场景中的目标组件存在，且没有误打开另一个场景。
- **玩家下坠**：检查 `Floor` 的 Collider 是否启用、是否为非 Trigger，以及出生点是否在地板上方。
- **客户端没有启动**：检查 SDK Settings 中的 VRChat Client 路径，以及 Builder 的客户端数量。
- **客户端里仍是旧结果**：确认保存过场景，并执行了构建，而不是仅测试上一次构建。
:::

## 参数对照测试

每次修改后保存场景，再重新构建，分别记录预期与实际结果：

- 把 `Floor` Scale 改为 `20, 0.2, 20`，检查可站立区域是否扩大。
- 把 `Spawn` Rotation Y 改为 `180`，检查出生方向是否反转。
- 复制一个 Cube 放在地板上，保留 Collider，检查能否阻挡移动或站立在其上。

测试结束后，把地板恢复为 `10, 0.2, 10`，出生点 Rotation 恢复为 `0, 0, 0`。额外测试用 Cube 可以移出房间或删除，保留明确命名的基础对象。
