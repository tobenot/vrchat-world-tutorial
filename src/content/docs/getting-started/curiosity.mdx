你最开始想做 VRChat 世界，大概是因为你在某个世界里停了下来。

可能是一间雨夜小屋。窗外有雨，屋里有暖光，朋友坐在地毯上聊天。也可能是一个游戏世界，机关、计分、复活点、音效都恰到好处。也可能是一个很小的角落，没什么名堂，但你忽然想知道：

> 这个地方，到底是怎么被做出来的？

这一章先不打开 Unity，先把这份好奇心放在桌上看一眼。

## 你想做的事，人类做了很久

「做一个 VRChat 世界」听上去像一件刚出现没几年的事。VRChat 2017 年才上线，确实是新的。但你想做的事情本身，人类做了几万年。

洞穴壁画里墙上的猎物和手印。神庙和教堂里用穹顶高度和光线落点制造的庄严。花园里被精心安排过的路径，游乐园里藏在每一个转角后头的体验。再到现代游戏关卡，设计师用地形、光线、敌人位置牵着玩家走的一切。

这条线很长，VRChat 世界是它最新的一环。你和那些前辈在做同一件事：构造一个别人可以走进去体验的环境。

区别在于，VRChat 世界是虚拟的、多人的、可交互的，一个人在家用电脑就能做，门槛比过去低得多。但要面对的核心问题没变：这个空间能给人什么感受？人进来之后知不知道往哪走？他们愿不愿意留下来？

这是创作。你要做的不是一张地图，是一个别人可以走进去存在的地方。

## VRChat 世界是作品，不是地图

很多游戏里，地图是玩法的容器。VRChat 不一样：世界本身就可以是作品。它可以是房间、舞台、展厅、一个游戏、一个工具，也可以只是让人愿意安静待着的那种地方。

这意味着做一个 VRChat 世界，会同时碰到好几摊事：空间布局、视觉、声音、交互、多人网络、性能。书后面会逐章拆开讲。现在只要知道：这不是单一技能，每一摊事最终都服务于同一件事，让人进来之后觉得这是个地方。

## 一个世界从你的电脑到玩家面前

动手之前，有一张粗略的全景图会有帮助。一个 VRChat 世界大致经过这几步走出去：

1. **Unity 场景**：你在 Unity 编辑器里搭出来的三维空间，里面有物体、灯光和脚本。
2. **VRChat SDK**：一组组件，负责告诉 VRChat「这个 Unity 场景是一个世界」。
3. **构建和上传**：把场景打包，上传到 VRChat 服务器。
4. **玩家加入**：别人在 VRChat 客户端里搜到你的世界，走进来。

每一步后面都会详细讲。现在先记住这条链就够了。

:::tip[为什么是这样？]
为什么不直接用一个简单的世界编辑器，而要走 Unity + SDK 这条路？因为 VRChat 世界要做三维渲染、物理模拟、脚本逻辑、网络同步。Unity 已经把这些做了二十年，没必要重造一遍。SDK 是一座桥，把 Unity 的能力接到 VRChat 的多人系统上。
:::

## 先做出来，再回头理解

这本书的路线很简单：先让你站进自己做的世界里。

第一阶段，你会装工具、建项目、放地板、放出生点、按 Build & Test，然后真的站进去。等你看见了结果，我再回头讲 Unity 在做什么、VRChat SDK 在做什么、那个出生点为什么决定了你的位置。

但跟纯照做不一样：动手之前，你会先知道自己在解决什么问题。「想站进自己做的空间对吧？那要解决三件事：有一块地面、有一个出生位置、有一个告诉 VRChat 这是世界的标记。来，逐个搞定。」

你不需要一开始就懂全部。只要知道自己往哪走。

## 卡住是默认状态

第一次打开 Unity 看到满屏面板，第一次盯着 C# 报错，觉得自己学不会，这些反应都很常规。这些工具的设计有它自己的历史包袱，很多地方对新手并不友好。是工具的问题，不是你的问题。

排行榜上那些热门世界的作者，第一天也对着空白场景发呆过。他们和你的差别只是扛过了前面几周的困惑期。

真正难的地方我会直说「这块容易懵，慢慢拆」；常踩的坑会提前提醒「看看是不是这个原因」。卡了的时候不是只有你卡。
