VRChat 世界是玩家可以进入的虚拟空间。房间、展厅、舞台和游戏关卡都可以做成世界。创建它需要在 Unity 中组织场景，再用 VRChat SDK 构建供客户端加载的内容。

世界不必有复杂交互。以观景、展示或聊天为目的的空间，可以主要依靠布局、模型、材质、灯光和声音；需要开关、计分或多人规则时，再加入对应的组件和脚本。功能多少不能直接说明作品质量，是否满足使用需求需要实际测试。

## 一个世界包含哪些工作

可以把制作任务分成六类：

- **空间布局**：地板、墙壁、入口、通道和出生位置。决定玩家在哪里出现、能走到哪里。
- **视觉资源**：模型、材质、贴图和灯光。决定物体的形状、颜色和明暗。
- **声音**：音频资源、播放条件、音量和空间化方式。决定何时听见什么声音。
- **交互**：玩家操作或事件触发的状态变化，例如切换灯光。
- **多人状态**：哪些变化只影响本地玩家，哪些需要让同一实例的其他玩家看到。
- **测试与性能**：检查碰撞、交互、加载时间和目标设备上的运行表现。

这些任务不一定都需要出现在同一个项目里。例如，固定陈列的展厅可以没有计分系统；一个规则游戏则需要明确计分条件和状态同步。

## 从项目到玩家客户端

一个可供访问的世界涉及四个环节：

1. **Unity 场景**：保存物体层级、组件配置及资源引用。
2. **Worlds SDK**：提供场景描述、世界组件、Udon 工具和构建检查。
3. **构建与上传**：把当前场景所需的资源构建成目标平台的世界包。上传与本地测试是不同操作。
4. **客户端加载**：VRChat 加载世界资源，把玩家放入一个具体实例。访问权限和平台支持决定谁能进入。

`Build & Test` 可以在本机加载构建结果，不会因此把世界公开。让其他玩家访问需要上传，并设置合适的访问权限。

## 把需求写成可检查的结果

用一间小房间举例，需求可以写成：

```text
出生位置在地板上方，面向房间内部
地板和墙壁具有碰撞
主要通道没有物体阻挡
墙面与地面在当前光照下能分辨
在目标客户端中可以移动和转向
```

这些描述都对应具体对象或测试结果。与「做一个好看的房间」相比，它们能说明哪里已经完成、哪里需要调整。

如果目标包含交互，也按同样方式写清触发和结果，例如「玩家与开关交互时，指定 Light 的启用状态翻转」。是否添加这个功能，由房间的使用需求决定。

## 遇到结果不符时记录什么

保存能复现问题的信息：当前 Unity 和 SDK 版本、操作步骤、预期结果、实际结果，以及 Console 中完整的相关错误。一次只改变一个与问题有关的设置，再重复同一组操作，便于判断这次修改是否生效。
