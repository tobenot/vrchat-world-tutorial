这一章把工具装好。

直接打开 Unity 动手很有诱惑力，但 VRChat 开发有一条铁律：**版本必须配对**。Unity 版本、VRChat SDK 版本、项目模板，三者要严格对齐。版本对不上，后面会撞上各种诡异的编译报错，且很难定位。

最省心的路线，是跟着官方的 VRChat Creator Companion（简称 VCC）走，由它统一管理版本。

## 即将装的几样东西

四样工具，各管一摊：

```text
VRChat Creator Companion (VCC)
  │  项目管家：建项目、装 SDK 包、提醒更新
  │
  ├─► Unity Hub
  │     管理本机的多个 Unity 编辑器版本
  │
  ├─► Unity Editor
  │     真正搭世界的工作台
  │
  └─► VRChat SDK – Worlds
        装在 Unity 项目里，让场景能被 VRChat 识别
```

VCC 是这套链条的入口。它负责下载正确版本的 Unity，给项目装好对应版本的 SDK，以后还会在版本过期时提醒升级。绕过 VCC，自己点开 Unity Hub 装一个 Unity 起手，多半装不进 VRChat 项目。版本号差一位都可能让 SDK 罢工。

## 第一步：装 VCC

打开官方页面 [creators.vrchat.com/sdk](https://creators.vrchat.com/sdk/)，下载 VRChat Creator Companion 安装包，按默认提示装下去。

打开后会要求登录 VRChat 账号，登一下。后面 Build & Test 和发布世界都要用这个账号验证身份，保持登录状态即可。

以后开项目都从 VCC 进，由它检查 SDK 版本是否对齐。

## 第二步：装官方指定版本的 Unity

这一步是最容易翻车的一步。

VRChat 对 Unity 版本管得很死。装错（哪怕只差最后一位）轻则 SDK 不工作，重则项目文件被破坏。

正确做法：打开 [Current Unity Version](https://creators.vrchat.com/sdk/upgrade/current-unity-version/) 页面，看官方当前指定的版本号是什么。然后在 Unity Hub 里装**完全一致**的版本，包括末尾那个 `f1`。安装模块默认勾上 Windows 平台基础编译支持就够了。

::::caution[踩坑预警]
Unity 的版本号长得像 `2022.3.22f1`，最后的 `f1` 也是版本号的一部分。`2022.3.21f1` 和 `2022.3.22f1` 是两个版本，错装会出问题。一定要和官方页面上那一串字符逐字对齐。

如果以后想让世界支持 Quest 或手机端，可以在 Unity Hub 里给当前版本「Add Modules」勾上 Android 支持，不需要重下整个 Unity。
::::

## 第三步：用 VCC 创建第一个世界项目

打开 VCC 进 Projects（项目）页，点创建新项目。模板选 **World**，另一个 Avatar 模板是用来做人物模型的，别选错。

项目命名用小写英文为主，比如 `MyFirstWorld`。存放位置选一个干净目录，例如 `D:\VRChatProjects\MyFirstWorld`。

点创建，VCC 会在后台下载并搭出一个干净的、装好 Worlds SDK 的 Unity 项目。

::::caution[踩坑预警]
不要把项目放在中文路径下（如 `D:\我的项目\`），不要放在桌面，不要放在网盘同步目录里（OneDrive、Google Drive、坚果云）。

原因有两条，都很硬：

1. **Windows 的 `MAX_PATH` 限制**。Win32 API 的传统上限是 **260 个字符**（结构是「盘符 + `:\` + 256 字符路径 + 末尾 `\0` 终止符」），Unity 项目里随便一个 `Library/PackageCache/com.vrchat.worlds@xxxxxxxx/Samples~/.../Materials/xxx.mat` 就能轻松撑到 200 字符以上，再叠一层"中文项目名 + OneDrive 同步目录"就溢出了。Windows 10 1607 之后系统层面可以通过组策略 + 应用 manifest 解锁长路径，但 Unity、Visual Studio、各种 Asset 打包工具默认仍走旧 API，一旦超限就会出现「文件存在但读不到」「编译报 `IOException`」「.meta 找不到对应资源」等怪现象，且报错信息往往不指向真正原因。
2. **网盘的实时同步会和 Unity 的文件监视互相打架**。Unity 编译时会高频读写 `Library/`、`Temp/`、`Logs/` 这些缓存目录，OneDrive / Google Drive / 坚果云会把这些频繁变动的中间文件也当成"用户文件"上传，结果是：上传途中文件被锁，Unity 读不到；多设备协同时一边同步一边 Unity 还在写，`.asset` 直接损坏；冲突文件名（`xxx (1).asset`）混进 Project，编辑器一加载就崩。

把项目放在 `D:\VRChatProjects\` 这种短英文路径下，关掉所在目录的所有同步客户端，是最省事的预防。这些问题真出了，排查起来都很贵。
::::

## 第四步：第一次打开项目

回到 VCC 项目列表，点 `MyFirstWorld` 右边的 Open。

这次启动会比较慢。Unity 第一次打开新项目要解析依赖、编译初始脚本、导入场景资源，3 到 10 分钟很常见。进度条卡在右下角是正常的，倒杯水回来差不多。

进 Unity 之后，做四件事确认工具链完整：

1. 顶部菜单栏有 `VRChat SDK` 这一项。
2. 左下角 Project 面板的 Packages 目录下，能看到 SDK 相关的包。
3. 底部的 Console 面板里没有红色错误图标（黄色警告先忽略）。
4. 按一下 `Ctrl+S`，场景能正常保存。

四项都对，环境就齐了。

## 第一次面对 Unity

打开后是一个塞满按钮和面板的界面。第一天只用认四块区域：

- **Scene**（屏幕中间最大那块）：搭世界的画布，可以三维视角摆物品、调灯光。
- **Hierarchy**（通常在左边）：场景里所有物体的目录清单。
- **Inspector**（通常在右边）：选中某个物体后，这里展示它身上挂的所有参数。
- **Project**（通常在下方）：整个项目的文件夹，材质、模型、脚本、声音都在里头。

剩下的 Console 面板（看报错）和 Game 视图（模拟玩家视角）以后会用到，今天不用管。

## 别急着塞插件

新手在第一天最容易做的事，是塞一堆炫酷的资源进来：Shader 包、现成模型、后处理特效、社区脚本库。

先别塞。

第一个世界跑起来之前，工具链就保留这几样：VCC、Unity Hub、官方指定版本的 Unity、Worlds SDK，加一个干净的项目。地基稳了再加东西。

软件开发里有一条很实用的思维方式叫「隔离变量」：一次只加一个新东西，出问题立刻知道是谁引起的；一次塞十个插件，报错时就是一场灾难。

## 启动卡点速查

如果出问题了，按这几条顺序排查：

- **VCC 提示找不到 Unity**：去 Unity Hub 确认对应的 Unity 版本装好了；回到 VCC 的 Settings，手动指定 Unity 编辑器路径。
- **首次打开卡在右下角**：Unity 在生成初始缓存，耐心等。超过十分钟没动静，关掉 Unity，从 VCC 重新启动。
- **Console 红字一片**：先看 Unity 版本和 VRChat 官方指定版本是不是字符对字符一致。绝大多数初次启动的脚本报错都来自微小版本号对不上。

报错读不懂的话，把那一行复制下来，连同 Unity 版本号、SDK 版本号一起发给 AI 或贴到社区论坛，先判断是环境问题还是项目设置问题，再对应排查。
