本章添加三个独立功能：座椅固定玩家的位置并应用坐姿，镜子渲染反射视图，传送区域把本地玩家移到指定位置。是否需要这些功能取决于场景用途，不是房间完整与否的判定标准。

在 Hierarchy 新建空物体 `Fixtures`，Position、Rotation 都设为零，Scale 设为一。用它整理对象：

```text
Fixtures
├─ Chair
├─ MirrorRoot
├─ MirrorSwitch
└─ Teleporter
```

容器的变换会影响子物体；下面标注的子物体坐标均为相对父物体的局部坐标。

## 第一节：用 VRCStation 做座椅

`VRCStation` 配置玩家进入座位时的位置、姿势与移动限制。自制座椅还需要 Collider 和处理坐下动作的 Udon 程序；单独加一个 Station 组件不等于完成可点击座椅。[官方座椅示例](https://creators.vrchat.com/worlds/components/vrc_station/#creating-a-station-with-udon)

### 建立椅面与坐姿定位点

在 `Fixtures` 下新建空物体 `Chair`，放到例如 `2.5, 0, -2.5`。在其下创建 Cube `Chair_Seat`：

```text
Position   0,    0.45, 0
Rotation   0,    0,    0
Scale      0.6,  0.05, 0.6
```

这块板作为可见椅面，保留它的实体 Box Collider。可再添加靠背与椅腿，但它们不负责坐下事件。

给 `Chair` 添加 `VRC Station`，设置：

```text
Player Mobility               Immobilize
Can Use Station From Station  关闭
Disable Station Exit          关闭
Animation Controller          None
Seated                        开启
```

`Immobilize` 限制座位中的移动，不表示 VR 玩家不能转头。`Seated` 使用座位的坐姿行为；具体呈现还受 Avatar、动画与追踪设置影响。

在 `Chair` 下建立两个空子物体：

- `EnterPoint`：先放在椅面中心附近，例如 `0, 0.45, 0`，作为坐姿定位的起点。
- `ExitPoint`：放在椅前有地板且无阻挡的位置，例如 `0, 0.05, 0.8`。

分别拖入 `Station Enter Player Location` 和 `Station Exit Player Location`。旋转 EnterPoint，使玩家面向房间；根据实际 Avatar 的坐姿结果调整高度和前后位置。这里的 Y 值不是对所有 Avatar 都保证骨盆贴合椅面的通用公式。

### 添加交互区域和脚本

在 `Chair` 根物体添加一个 Box Collider：

```text
Center       0, 0.5, 0
Size         0.65, 0.15, 0.65
Is Trigger   开启
```

它是座椅的交互区域，与根物体上的 Station 和 Udon Behaviour 配套。椅面的实体 Collider 仍负责物理碰撞。此处使用 Trigger 作为交互命中形状，说明 `Interact` 并不要求所有 Collider 都必须是非 Trigger。

新建 U# Script `ChairSeat`，挂到 `Chair`：

```cs title="ChairSeat.cs"
using UdonSharp;
using VRC.SDKBase;

public class ChairSeat : UdonSharpBehaviour
{
    public override void Interact()
    {
        if (!Utilities.IsValid(Networking.LocalPlayer)) return;
        Networking.LocalPlayer.UseAttachedStation();
    }
}
```

`UseAttachedStation()` 使用与这个 Udon Behaviour 同一物体上的 Station。在该 Udon Behaviour 中把 `Interaction Text` 设为 `坐下 / Sit`，Proximity 设为 `2`。提示属于 Udon Behaviour，不需要寻找一个假定隐藏在 VRC Station 里的文字字段。

### Build & Test

1. 靠近并指向椅子，检查双语提示。
2. 发起 Interact，应进入座位。
3. 尝试正常移动或跳跃退出。由于 `Disable Station Exit` 关闭，正常退出操作应可用；不是再次 Interact 才一定能起身。
4. 检查退出点有地板、不与墙或其他 Trigger 重叠。
5. 分别在桌面、VR 和不同身高 Avatar 下检查坐姿及视角。调整 EnterPoint 后重新构建。

如果没有提示，检查根物体的 Collider、脚本与交互距离；如果有提示但不能坐，检查 Station 是否在脚本同一物体，以及当前玩家是否已经处于不允许切换的 Station。坐姿不合适时，先调整定位点，再检查 Avatar 与坐姿动画，不要用同一个高度解释所有姿势问题。

### 可选：用回调控制这份脚本的交互入口

需要比较座位进出与交互提示的关系时，把以下两个方法加入 `ChairSeat` 类，与它的 Interact 放在同一对类大括号内：

```cs
public override void OnStationEntered(VRCPlayerApi player)
{
    if (!Utilities.IsValid(player)) return;
    DisableInteractive = true;
}

public override void OnStationExited(VRCPlayerApi player)
{
    DisableInteractive = false;
}
```

`DisableInteractive` 控制的是这份 Udon Behaviour 的 Interact 与交互轮廓。因此把这两段放到另一份没有 Interact 的脚本，并不能代替关闭 ChairSeat 的入口。保持 Chair 的 Station 与退出设置不变，进入前提示应可用，收到进入回调后关闭，正常起身并收到退出回调后恢复。

在各回调中临时记录 `player.playerId` 和 `player.isLocal`，分别做单人进出、双客户端轮流坐下、有人坐着时另一人加入实例的测试。有效性判断应先于访问 player 字段。[Station 组件文档](https://creators.vrchat.com/worlds/components/vrc_station/)给出事件和参数；[官方事件页](https://creators.vrchat.com/worlds/udon/graph/event-nodes/#onstationentered)将进出描述为本地事件，不能从这两段代码推导出所有客户端一定得到了完整占用状态。

这份小例处理的是「收到座位回调后开关交互入口」，不是多人预订或排他占座机制。它不处理同时点击、漏掉退出或迟到者的占用恢复；项目若需要公共占用状态，应另行保存和同步该状态，不能把本地 DisableInteractive 当成网络锁。

### 进入和离开时添加本地反馈

Station 提供 `OnStationEntered(VRCPlayerApi player)` 与 `OnStationExited(VRCPlayerApi player)`。例如本地玩家坐下时降低一盏灯的亮度，起身恢复：

```cs title="ChairLightFeedback.cs"
using UdonSharp;
using UnityEngine;
using VRC.SDKBase;

public class ChairLightFeedback : UdonSharpBehaviour
{
    public Light targetLight;
    public float seatedIntensity = 0.5f;
    private float previousIntensity;

    public override void OnStationEntered(VRCPlayerApi player)
    {
        if (!Utilities.IsValid(player) || !player.isLocal) return;
        if (targetLight == null) return;
        previousIntensity = targetLight.intensity;
        targetLight.intensity = seatedIntensity;
    }

    public override void OnStationExited(VRCPlayerApi player)
    {
        if (!Utilities.IsValid(player) || !player.isLocal) return;
        if (targetLight != null) targetLight.intensity = previousIntensity;
    }
}
```

把它挂到 `Chair` 并配置目标 Light。单人 Build & Test 记录原强度，坐下应变为 Seated Intensity，正常起身应恢复原值；再连续坐下、起身两次，检查恢复值没有漂移。身份判断表达的是「只处理本地玩家」；这段代码不是跨客户端座位占用锁，也不负责协调其他脚本同时修改灯光的情形。

## 第二节：做一面可开关的镜子

`VRCMirrorReflection` 需要同物体上的 Mesh Renderer，并把反射结果写入第一个材质的 `_MainTex`。仅给普通 Quad 加一个组件而不确认材质，不足以保证反射呈现正确。本章复用 SDK 的 `VRCMirror` Prefab，保留其配套网格、材质与组件。

### 放置 SDK 镜子

1. 在 Project 中把搜索范围设为整个项目，搜索 `VRCMirror`，选择 Worlds SDK 提供的 Prefab。
2. 在 `Fixtures` 下新建 `MirrorRoot`，把 Prefab 拖到它下面。
3. 调整位置、旋转和缩放，让镜面朝向房间并与墙面保持少量间距。
4. 展开 Prefab，确认实际镜面上的 Mesh Renderer、材质和 `VRCMirrorReflection` 保留；不要用普通默认材质替换镜面材质。

如果需要自制网格，可对照官方 Prefab 配置 Renderer 与镜面材质。Plane 或 Quad 都需要正确的网格朝向和材质，不能把「旋转 Plane 必定让镜像颠倒」当成规则。

### 反射层与分辨率

选中带 `VRCMirrorReflection` 的物体，检查：

- `Reflect Layers`：只渲染需要的层。只看玩家时，应包含 `Player` 和 `MirrorReflection`；前者用于其他玩家，后者用于镜中的本地玩家。仅选 Player 不能保证看到自己。
- `Mirror Resolution`：本例用 `Auto`。官方说明 Auto 随显示分辨率变化，通常上限为每眼 `2048×2048`，用户设置可能影响实际限制。
- `Disable Pixel Lights`：控制镜中逐像素点光／聚光的处理，不会关闭场景中所有灯。
- `Custom Skybox`：只有相应 Camera Clear Flags 配置生效时才控制镜中背景。

减少反射层或分辨率可降低额外渲染负担，实际收益取决于场景、Avatar、平台与当前画质设置。镜子关闭时不产生这份可见镜面渲染，所以本例默认关闭，由本地玩家开启。[镜子官方说明](https://creators.vrchat.com/worlds/components/vrc_mirrorreflection/)与[VRChat 层定义](https://creators.vrchat.com/worlds/layers/)

### 默认关闭并连接独立按钮

取消勾选 `MirrorRoot` 顶部的 Active 复选框。在 `Fixtures` 下另建小 Cube `MirrorSwitch`，不要把开关放进已禁用的 MirrorRoot。

给开关挂上脚本：

```cs title="MirrorSwitch.cs"
using UdonSharp;
using UnityEngine;

public class MirrorSwitch : UdonSharpBehaviour
{
    public GameObject mirrorObject;

    public override void Interact()
    {
        if (mirrorObject == null) return;
        mirrorObject.SetActive(!mirrorObject.activeSelf);
    }
}
```

把 `MirrorRoot` 拖到 `Mirror Object`，保留按钮的 Collider，提示设为 `镜子开关 / Toggle mirror`。

### Build & Test

- 进入时 MirrorRoot 关闭，镜面和它的子物体都不可见。如果要保留镜框，镜框应放在这个禁用层级外。
- 按钮操作后镜子出现，检查能否看到自己的 Avatar；再操作后消失。
- 多人测试时检查其他玩家的反射。
- 比较开启与关闭时的性能，按目标平台调整反射层与分辨率。

若开启后显示黑色或缺少对象，检查镜面材质、Renderer、视角是否在镜面正面、Reflect Layers 及背景清除设置。只反射玩家而排除场景时，空白或纯色背景可能是过滤结果；不能仅凭背景黑就判断镜子完全失效。

## 第三节：区域传送

传送脚本改变同一世界内本地玩家的位置。它不切换世界，也不能直接把远端玩家传走。

### 建立区域与目的点

在 `Fixtures` 下新建 `Teleporter`，Transform 保持单位变换。在它下面创建：

1. `EntryZone`：例如 Position `0, 1.1, -3.8`，添加 Box Collider，Size `1.2, 2.2, 1.2`，勾选 `Is Trigger`。
2. `Destination`：放在房间另一头有地板的空地上，接近地面但不埋入地板。调整 Y 轴 Rotation 表示目标朝向。

目的点应在 EntryZone 外，不与墙、另一传送区或障碍物重叠。没有二楼平台时，不要把坐标设到空中并假定那里有落脚点。

### 传送脚本

新建 `Teleporter` 并挂到 `EntryZone`：

```cs title="Teleporter.cs"
using UdonSharp;
using UnityEngine;
using VRC.SDKBase;

public class Teleporter : UdonSharpBehaviour
{
    public Transform destination;

    public override void OnPlayerTriggerEnter(VRCPlayerApi player)
    {
        if (!Utilities.IsValid(player) || !player.isLocal) return;
        if (destination == null) return;

        player.TeleportTo(destination.position, destination.rotation);
    }
}
```

把 `Destination` 拖到引用槽。这里在确认 `player.isLocal` 后直接对这个 player 调用 `TeleportTo`。传入的 `.position` 与 `.rotation` 是世界坐标，不是 Transform 的局部坐标。

`TeleportTo` 只能移动本地玩家，某些 Station 配置会阻止传送。官方还要求避免在 `OnDeserialization` 等网络更新回调中直接传送；这种场合需延迟到另一帧执行。[Player Positions：TeleportTo](https://creators.vrchat.com/worlds/udon/players/player-positions/#teleportto)

### Build & Test

1. 正常步行进入 EntryZone，检查是否到达 Destination，以及脚下地面和面向是否正确。
2. 在目的点站定，不应立刻再次传送。
3. 走回原区域再次测试；此实现只有一个方向，不会自动生成反向入口。
4. 双向传送需要第二个 EntryZone 和对应目的点，两端目的点都应位于接收区域之外，避免循环。

传送后下坠时，检查目的点是否缺少地板、埋入地板或被放到场景外。没有触发时，检查 Is Trigger、区域位置和脚本引用。瞬移与高速穿越有 Trigger 漏发边界，不能把正常步行测试扩展成所有移动方式的保证。

### 改成主动传送按钮

若希望玩家确认后才移动，可将事件替换为：

```cs
public override void Interact()
{
    if (destination == null) return;
    if (!Utilities.IsValid(Networking.LocalPlayer)) return;
    Networking.LocalPlayer.TeleportTo(destination.position, destination.rotation);
}
```

给按钮配置可命中的 Collider 和 `传送 / Teleport` 提示。`Interact` 本身就是本地操作，不需要一个 player 参数。

`VRC Portal Marker` 的用途不同：它提供进入其他世界的入口；`TeleportTo` 只移动当前世界内的位置。跨世界入口的创建与测试见 [传送门与导航](/placeness/portals/)。

## 调整与练习

- 给座椅更换可见模型，保持 Station、交互 Collider 和脚本关系，重新校准 EnterPoint 与 ExitPoint。
- 为镜子做两个独立按钮：一个开关显示，一个切换两组 Reflect Layers。分别记录反射内容和性能变化。`Interact` 本身没有「按住五秒后松开」事件，不能只靠一个延时事件假定玩家一直按着。
- 把区域传送改为 `OnPlayerTriggerExit` 触发，验证离开整个区域时才移动，并检查目的点不会触发另一个离开／进入循环。

## 按用途组合功能

以下是可选方案，不表示某类世界必须包含这些组件：

- 交流区：座位配置明确出口，镜子使用独立本地开关；验证坐下后仍能退出和操作附近必要控件
- 展览：Station 提供一个固定观展位置，保留正常退出；若启用 Disable Station Exit，必须另做并验证退出入口，不能只等待一段未实现的动画来解锁
- 关卡或舞台分区：用区域传送把本地玩家送到已配置的等待点；检查终点地面与回流路线。Trigger 不承担权限或防作弊保证
- 掉落恢复：复用 Teleporter 的本地玩家和目标引用检查，布局及重生高度的配合见 [返回安全点的区域](/come-alive/trigger-zones/#返回安全点的区域)

## 三个功能的连接关系

- 座椅：Collider + Interact → `UseAttachedStation` → Station 与进入／退出定位点。
- 镜子：独立按钮的 Interact → `SetActive` → 镜子网格、材质与反射组件。
- 传送：Trigger → 本地玩家过滤 → `TeleportTo` → 有安全落脚空间的目的点。
