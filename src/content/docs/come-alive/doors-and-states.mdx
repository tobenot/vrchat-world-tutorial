灯光开关直接修改 `enabled`，旋转门则需要在一段时间内改变角度。本章用脚本记录目标开关状态，让 Animator 负责从关闭角度转到打开角度，以及反向转回。

本例是绕铰链转动的门，不是沿轨道滑动的门。脚本里的 `isOpen` 表示目标状态；动画播放期间，门板可能尚未转到终点。

## 状态与表现的连接

```text
玩家操作按钮
    ↓
脚本翻转 isOpen
    ↓
Animator.SetBool("IsOpen", isOpen)
    ↓
Animator 按参数选择动画
    ↓
DoorPivot 的局部 Y 旋转改变
```

字段保存逻辑状态，Animator 保存和播放运动曲线。单独在 Inspector 改 Animator 参数不等于同步修改脚本字段，因此测试时要区分动画预览与按钮控制。

## 第一步：建立铰链和门板

在墙上留出真正的门洞。若墙仍是覆盖整个开口的 Cube，门打开后玩家也会被墙的 Collider 挡住；可用门洞左右及上方的独立墙块围出开口。

在 Hierarchy 创建空物体 `DoorPivot`，放在门框一侧的铰链位置，例如：

```text
DoorPivot
Position   -1.5, 1.0, 2
Rotation    0,   0,   0
Scale       1,   1,   1
```

在其下创建 Cube `DoorBoard`，局部坐标：

```text
DoorBoard
Position   0.5, 0,   0
Rotation   0,   0,   0
Scale      1,   2,   0.05
```

门板中心偏离父物体原点半米。旋转父物体时，子门板绕父原点运动；直接旋转这个 Cube 则绕 Cube 自身中心运动。

```text
DoorPivot          ← Animator 与旋转轴
└─ DoorBoard       ← 门板网格与 Collider
```

保留门板 Collider，让关闭的门能阻挡玩家。此示例不处理夹住玩家、推挤刚体或安全回弹；测试时应检查开门方向是否有空间。

## 第二步：制作关闭姿态与开关动画

选中 `DoorPivot`，打开 `Window` → `Animation` → `Animation`。点击 `Create`，在 `Assets/Animations/` 保存 `Door_Closed.anim`。Unity 会给物体添加 Animator 并创建 Controller；确认该 Controller 已绑定到 DoorPivot。

### 关闭姿态

`Door_Closed` 是一个静止姿态：在时间 `0:00` 给 Rotation 添加关键帧，X/Y/Z 均设为 `0`，退出录制。这个状态用作场景启动姿态，不播放「从打开到关闭」的动作。

### 开门动画

在 Animation 面板的剪辑下拉框选择 `Create New Clip`，保存 `Door_Open.anim`：

1. 把 Samples 设为 `60`。
2. 开启录制，在 `0:00` 设置 Rotation 为 `0,0,0`。
3. 在 `0:30` 设置 Rotation 为 `0,90,0`。
4. 退出录制并预览。

时间标记中的 `30` 是帧位置；只有 Samples 为 60 时，30 帧才对应 0.5 秒。也可直接按时间轴的秒刻度放置终点。

### 关门动画

同样创建 `Door_Close.anim`，Samples 设为 `60`：

- `0:00`：Rotation 为 `0,90,0`。
- `0:30`：Rotation 为 `0,0,0`。

在 Project 中分别选中这三段 Animation Clip，取消 `Loop Time`。开关门剪辑需要播一次停在终点，不能每半秒回到开头重播。保存后退出 Animation 预览，确认编辑态门板为关闭角度。

## 第三步：配置 Animator Controller

双击 DoorPivot 的 Controller 打开 Animator。确保有三个状态，Motion 分别指向对应剪辑，状态 Speed 均为 `1`：

```text
Door_Closed   静止关闭姿态
Door_Open     0° → 90°，0.5 秒，结束后保持 90°
Door_Close    90° → 0°，0.5 秒
```

在 Parameters 添加 Bool 参数 `IsOpen`，默认不勾选。右键 `Door_Closed` → `Set as Layer Default State`，让它成为橙色默认状态。

使用 `Make Transition` 建立以下连接：

| 起点 → 终点 | 条件 | Has Exit Time |
| :--- | :--- | :--- |
| Door_Closed → Door_Open | IsOpen = true | 关闭 |
| Door_Open → Door_Close | IsOpen = false | 关闭 |
| Door_Close → Door_Open | IsOpen = true | 关闭 |
| Door_Close → Door_Closed | IsOpen = false，Exit Time = 1 | 开启 |

所有转移的 `Transition Duration` 设为 `0`，不加入额外混合时间。此配置让动画时长与 0.5 秒的脚本锁对应。

`Has Exit Time` 开启时，转移还要满足当前状态的退出时间条件；关闭时，不等待该时间。开关指令转移不等待片段结束，关门完成后回到静止姿态则等待完整片段。它不是一个必须对所有状态机关闭的选项。[Unity 转移条件说明](https://docs.unity3d.com/2022.3/Documentation/Manual/class-Transition.html)

在 Play Mode 下手动切换 Animator 的 `IsOpen`，验证打开和关闭曲线。退出 Play Mode 后，再检查初始参数未被编辑为 true。

## 第四步：写门的状态脚本

新建 U# Script `AnimatedDoorController`。它与 [逐帧移动门模型](/programming/csharp-just-enough/#完整示例逐帧移动门模型)中的 `DoorController` 使用不同类名，可在同一项目中保留：

```cs title="AnimatedDoorController.cs"
using UdonSharp;
using UnityEngine;

public class AnimatedDoorController : UdonSharpBehaviour
{
    public Animator doorAnimator;
    private bool isOpen = false;

    private void Start()
    {
        if (doorAnimator != null)
        {
            doorAnimator.SetBool("IsOpen", isOpen);
        }
    }

    public override void Interact()
    {
        if (doorAnimator == null) return;
        isOpen = !isOpen;
        doorAnimator.SetBool("IsOpen", isOpen);
    }
}
```

`isOpen` 是实例字段，同一个脚本实例在多次 Interact 之间保存这个值。每个独立 AnimatedDoorController 实例各有一份状态。

`doorAnimator` 是 Inspector 中配置的引用，使用 public 字段。`isOpen` 由脚本修改，设为 private，避免把它当成可独立编辑的配置项。这是一种职责划分，不意味着所有运行时状态都必须 private，或 private 字段永远不能通过序列化显示。

### 连接按钮

在门旁创建 Cube `DoorButton`，例如 Position `-0.5,1.2,2`，Scale `0.15,0.3,0.05`。把它放在墙面外、可触及的位置。

- 添加 `AnimatedDoorController`。
- 把 DoorPivot 上的 Animator 拖到 `Door Animator`。
- 保留按钮的 Box Collider，`Is Trigger` 不勾选。
- 提示设为 `开关门 / Toggle door`。

### Build & Test

进入时门保持关闭，不应先从 90° 播一次关门。操作一次，门在半秒内转到 90°；动画结束后再操作，半秒内回到 0°。

检查门板 Collider 是否与网格一起转动、打开后的门洞是否可通过。若门打开仍有阻挡，检查墙体或重复 Collider；若按钮能操作但门不动，检查 Animator 引用、Controller、参数名 `IsOpen` 和每条条件。

## 直接旋转、逐帧移动与 Animator 的取舍

若只需要瞬间开关，可在单独测试副本中新建 U# Script `InstantDoorController`：

```cs title="InstantDoorController.cs"
using UdonSharp;
using UnityEngine;

public class InstantDoorController : UdonSharpBehaviour
{
    public Transform doorPivot;
    private bool isOpen;

    public override void Interact()
    {
        if (doorPivot == null) return;
        isOpen = !isOpen;
        doorPivot.localRotation = Quaternion.Euler(0f, isOpen ? 90f : 0f, 0f);
    }
}
```

挂到有 Collider 的独立按钮，提示设为 `瞬时开关门 / Toggle door`，把铰链 Transform 拖入 Door Pivot；测试副本禁用门的 Animator，并把初始局部旋转设为零，避免两个控制器同时写旋转。连续两次交互应立即转到 90°、再回到 0°。

需要连续运动时，可以由 Update 每帧推进变换，完整的字段、按钮接线与测试见 [DoorController 逐帧移动例](/programming/csharp-just-enough/#完整示例逐帧移动门模型)。该例移动位置，替换为旋转时还需选择对应插值方法。Animator 则适合在剪辑里编辑曲线、停顿或多个属性；音效和材质变化仍要明确接线，不会因为添加 Animator 自动出现。

## 在动画期间禁止重复操作

上述版本允许动画中再次切换参数。由于开关剪辑各自从固定角度开始，中途反向可能出现角度跳变。本例使用固定时长锁，在一段动画结束前忽略新操作。

用这一版替换 `AnimatedDoorController`，不要把同名类重复添加到项目：

```cs title="AnimatedDoorController.cs（动画锁版本）"
using UdonSharp;
using UnityEngine;

public class AnimatedDoorController : UdonSharpBehaviour
{
    public Animator doorAnimator;
    public float animationDuration = 0.5f;

    private bool isOpen = false;
    private bool isAnimating = false;

    private void Start()
    {
        if (doorAnimator != null)
        {
            doorAnimator.SetBool("IsOpen", isOpen);
        }
    }

    public override void Interact()
    {
        if (doorAnimator == null || isAnimating) return;

        isAnimating = true;
        isOpen = !isOpen;
        doorAnimator.SetBool("IsOpen", isOpen);
        SendCustomEventDelayedSeconds(nameof(OnAnimationFinished), animationDuration);
    }

    public void OnAnimationFinished()
    {
        isAnimating = false;
    }
}
```

`SendCustomEventDelayedSeconds` 在指定延迟后调用公开事件方法，`nameof(OnAnimationFinished)` 取得方法名字。相比手写字符串，方法重命名与拼写错误更容易被编辑器检查。延时调用的目标要是可调用的 public 方法。

这个锁按计时工作，不读取动画是否真的播放完。剪辑长度、Animator Speed 或 Transition Duration 改了，`animationDuration` 也要重新核对；动画被暂停或对象被禁用时，不能继续假设两者一定同时结束。

Build & Test 时快速连按：锁定期间只有第一次操作生效，动画完成后再次操作才反向。测试关闭过程中也应得到相同结果。

## 多个状态：三色信号灯

两态门可用 bool；红、黄、绿三种状态可用 int。例子把状态选择和灯光应用分开：

```cs title="TrafficLight.cs"
using UdonSharp;
using UnityEngine;

public class TrafficLight : UdonSharpBehaviour
{
    public Light trafficLight;

    private const int STATE_RED = 0;
    private const int STATE_YELLOW = 1;
    private const int STATE_GREEN = 2;
    private int currentState = STATE_RED;

    private void Start()
    {
        ApplyState();
    }

    public override void Interact()
    {
        currentState = (currentState + 1) % 3;
        ApplyState();
    }

    private void ApplyState()
    {
        if (trafficLight == null) return;

        if (currentState == STATE_RED)
        {
            trafficLight.color = Color.red;
        }
        else if (currentState == STATE_YELLOW)
        {
            trafficLight.color = Color.yellow;
        }
        else if (currentState == STATE_GREEN)
        {
            trafficLight.color = Color.green;
        }
    }
}
```

把脚本挂到有 Collider 的按钮，配置 Light 和提示。开始时 Start 应用红色，每次 Interact 切换为黄、绿、红。没有 Start 的初始化，场景里的原灯色可能与 `STATE_RED` 不一致。

`const int` 给状态数字命名；`ApplyState()` 集中维护状态对应的颜色。若另一种事件也要改变状态，可以设置字段后调用同一个方法，避免复制颜色规则。是否拆分方法取决于职责与复用，不取决于任意固定行数。

### 对照：在同一事件内同时切状态和颜色

在 TrafficLight 的测试副本中，仅替换 `Interact` 为以下方法，其余字段与 Start 保留：

```cs
public override void Interact()
{
    if (trafficLight == null) return;
    if (currentState == STATE_RED)
    {
        currentState = STATE_YELLOW;
        trafficLight.color = Color.yellow;
    }
    else if (currentState == STATE_YELLOW)
    {
        currentState = STATE_GREEN;
        trafficLight.color = Color.green;
    }
    else
    {
        currentState = STATE_RED;
        trafficLight.color = Color.red;
    }
}
```

这个版本能完成三色循环。现在增加一个「重置为红色」入口，就需要同时维护状态数字与颜色；若只改 `currentState`，画面不会跟着更新。正例可直接设置 `currentState = STATE_RED;` 再调用 `ApplyState()`，让初始化、交互和重置共用颜色映射。比较三次交互后的颜色循环，再恢复正例；这里对照的是重复规则的维护成本，不是声称短 if/else 本身不能运行。

## 本地状态与同步边界

本章 AnimatedDoorController 没有同步字段，因此每个客户端各自维护 `isOpen`。某位玩家开门，不会自动改变其他客户端的门状态。

`VRC Object Sync` 主要同步 Transform 和物理状态，不能单靠添加它就让脚本 bool、Animator 参数和门的逻辑一致。此处 Animator 正在控制 DoorPivot 旋转，再由另一套系统写同一个 Transform，还需要解决控制权冲突。

共享门状态需要明确谁能写入状态、如何传递给其他客户端，以及新加入玩家如何得到当前值。逻辑状态与动画表现仍可分开：接收到目标状态后，再把它应用到 Animator。完整的字段、所有权检查、接收回调和接线见 [同步门实现](/with-others/tell-everyone/#同步门的目标状态)。

## 调整与练习

- 在测试副本中依次把开关剪辑改为 1.5 秒、0.15 秒，每次同时修改 `animationDuration`，保持状态 Speed 为 1、Transition Duration 为 0。比较快慢两种节奏，并验证连按时是否仍在完整动画期间锁定。
- 添加 `AudioSource openSound`，当 `isOpen` 变为 true 时判空并播放音效。
- 用 Trigger 实现自动门：本地玩家进入时把目标状态设为 true，离开时设为 false。不要简单在每次进入时 Toggle，否则第二次进入可能关门。若沿用动画锁，还要保存锁定期间收到的最新目标状态，避免忽略离开后门仍停在打开状态。

## 状态交互的组成

状态字段表示目标，事件决定何时提出改变，条件决定是否接受，表现方法或 Animator 把状态应用到场景。动画中的当前角度与目标开关状态是不同信息；初始状态、重复触发与多客户端行为都需要单独验证。
