让 Alpha 先把第 28 章的同步灯打开，再让 Charlie 加入同一实例。Charlie 收到最新的 `isOn` 后，通过 `OnDeserialization → ApplyState` 将灯设为开启，不需要 Alpha 再按一次。

这里的「最新」指已经同步出去的状态。Owner 尚未成功发送的本地修改，不会因为有人加入就自动成为可恢复的结果。

## 状态与历史事件

| 内容 | 后加入者的处理 |
| :--- | :--- |
| UdonSynced 字段 | 收到最近已同步的值后应用 |
| 已经发送的网络事件 | 不重放 |
| Object Sync 管理的位置与旋转 | 由组件恢复当前同步状态 |
| Animator 当前播放进度 | 不因同步了 bool 就自动恢复 |
| 计分板、回合和玩家槽位 | 应由同步数据重建显示 |

同步到达不是加载瞬间的原子动作。可在初始同步完成前显示「同步中」，避免把临时初值误当成最终结果。

## OnPlayerJoined 与 OnDeserialization

`OnPlayerJoined(VRCPlayerApi player)` 表示本机获知一位玩家加入；`OnPlayerLeft` 表示离开。新客户端也需要建立已有玩家的名单，不能假定它只收到一次「自己加入」事件。

`OnDeserialization()` 表示本 Behaviour 收到了同步字段。它不是每个玩家加入都无条件调用一次，也不保证先于或后于某次 OnPlayerJoined。

分别承担责任：

- OnPlayerJoined / OnPlayerLeft：更新或核对玩家名单，处理加入离开的业务条件
- OnDeserialization：根据收到的字段重建本地灯、门、UI
- 本地初始化标记：区分第一次显示与后续变化，不同步给别人

VRChat 会为后加入者提供同步变量，无需为了普通初始恢复在每次 OnPlayerJoined 里额外广播全部状态。只有名单等共享数据确实变化时，Owner 才需要发布新值。

## 门方案 A：首次接收时显示终态

设开门动画长 0.5 秒，Alpha 已经看到门开始移动。Charlie 之后才收到 `isOpen=true`：如果从头播放，他看到的进度就以自己的接收时刻为起点，不能从这个 bool 得知 Alpha 已播放多久。将动画临时改长到 5 秒，在动画途中加入，会更容易观察这一区别；两端偏差应以实际日志为准，不能把加入耗时固定成某个数值。

如果需求是「加入后立刻看到门已打开」，可以跳到明确的 Animator 状态。用这个完整版本替换 `SyncedDoorController.cs`，不要另建第二个同名类，也不要同时挂载两个控制门的脚本。沿用第 17 章的 `Door_Closed`、`Door_Open`、`Door_Close` 状态与 `IsOpen` 参数：

```cs title="SyncedDoorController.cs（初始状态恢复版）"
using UdonSharp;
using UnityEngine;
using VRC.SDKBase;

[UdonBehaviourSyncMode(BehaviourSyncMode.Manual)]
public class SyncedDoorController : UdonSharpBehaviour
{
    public Animator doorAnimator;
    public float animationDuration = 0.5f;

    [UdonSynced] private bool isOpen;
    private bool hasInitialized;
    private bool displayedIsOpen;
    private float nextLocalInteractTime;

    private void Start()
    {
        if (Networking.IsOwner(gameObject)) _InitializeOwner();
    }

    public void _InitializeOwner()
    {
        if (!Networking.IsOwner(gameObject) || hasInitialized) return;
        if (!Networking.IsNetworkSettled)
        {
            SendCustomEventDelayedSeconds(nameof(_InitializeOwner), 0.5f);
            return;
        }

        ApplyStateInstant();
        hasInitialized = true;
        RequestSerialization();
    }

    public override void Interact()
    {
        if (!hasInitialized || Time.time < nextLocalInteractTime) return;
        if (!Networking.IsOwner(gameObject))
            Networking.SetOwner(Networking.LocalPlayer, gameObject);
        if (!Networking.IsOwner(gameObject)) return;

        isOpen = !isOpen;
        RequestSerialization();
        ApplyAnimatedState();
    }

    public override void OnDeserialization()
    {
        if (!hasInitialized)
        {
            ApplyStateInstant();
            hasInitialized = true;
        }
        else
        {
            ApplyAnimatedState();
        }
    }

    public override void OnOwnershipTransferred(VRCPlayerApi player)
    {
        if (!Utilities.IsValid(player) || !player.isLocal) return;
        _InitializeOwner();
    }

    private void ApplyStateInstant()
    {
        displayedIsOpen = isOpen;
        if (doorAnimator == null) return;
        doorAnimator.SetBool("IsOpen", isOpen);
        doorAnimator.Play(isOpen ? "Base Layer.Door_Open" : "Base Layer.Door_Closed", 0, 1f);
        doorAnimator.Update(0f);
    }

    private void ApplyAnimatedState()
    {
        if (displayedIsOpen == isOpen) return;
        displayedIsOpen = isOpen;
        nextLocalInteractTime = Time.time + Mathf.Max(0f, animationDuration);
        if (doorAnimator != null) doorAnimator.SetBool("IsOpen", isOpen);
    }
}
```

配置条件：

1. Animator 层名为 `Base Layer`，状态名与代码一致；使用其他名称时改完整状态路径。
2. `Door_Open` 为不循环的开门剪辑，标准化时间 `1` 对应末端姿态。
3. `Door_Closed` 是静止关闭姿态；不能误用从打开开始的关闭动画作为初始姿态。
4. 过渡条件与[本地门的 Animator 配置](/come-alive/doors-and-states/)一致，避免进入终态后又无条件退出。
5. 脚本挂在门的交互对象上，保留普通 Collider，把实际 Animator 拖入 `Door Animator`，确认 Manual 模式。`Animation Duration` 填从触发过渡到门停止移动的时长；本例以 0.5 秒为测试值。

后续本机点击和远端状态变化都调用 `ApplyAnimatedState`，因此两条路径都会开始本机点击冷却。重复收到同一个目标值不会重开动画或延长冷却。首次接收直接显示终态，不进入动画冷却。这个时间闸只限制本机输入，不是网络互斥锁；收到另一个有效目标仍会更新门。若修改了剪辑、播放速度或过渡时长，需要一并调整 `Animation Duration` 并实测。

`Animator.Play` 指定状态和标准化时间，`Update(0)` 立即求值当前姿态。不能仅调用 `Animator.Update(animationDuration)` 就保证任何 Controller 都到达正确终态，过渡和状态配置会影响结果。

`hasInitialized` 只表示本机完成初始显示。初始 Owner 可能不收到自己的 OnDeserialization，因此 Start 和未初始化的接管都调用 `_InitializeOwner`。它等待 `IsNetworkSettled` 后才应用当前值、允许交互并请求发布；所有权变化本身不能当作状态已经恢复。已通过 OnDeserialization 初始化的客户端保留收到的状态。

## 门方案 B：恢复正在进行的进度

如果动画进度影响玩法，例如长时间运行的升降台，可同步：

- 目标状态
- 开始状态或开始位置
- 使用共同时间基准记录的开始时间
- 持续时间

接收端使用 `Networking.GetServerTimeInSeconds()` 计算已过去的时间，再限制到合法范围，并设置动画或 Transform。该 API 提供各客户端可比较的服务器时间估计，不代表所有机器在同一瞬间读取完全相同的数值。

选择终态恢复还是进度恢复取决于需求。正在运行的计时器、电梯或演出不能一律跳到终点；也无需为只有当前状态有意义的开关回放全部历史。

## 玩家槽位：重复事件与接管

玩家列表应以 playerId 识别当前实例中的玩家，由 Owner 写共享数组。至少检查：

1. 加入时先查是否已有槽位，避免重复注册。
2. 容量满时保留明确的观战或拒绝加入状态。
3. 离开时清理对应槽位，重算人数。
4. Owner 接管时核对当前在线玩家，不依赖固定的 OnPlayerLeft / OnOwnershipTransferred 顺序。
5. Owner 修改后同时更新本机 UI；不能只等待远端的 OnDeserialization。

以下是加入处理的节选，不能单独作为一个脚本使用。所需的数组、查找方法、离开清槽、接管核对和 UI 都在[GameManager 完整实现](/with-others/multiplayer-mini-game/#gamemanager)中；[场景与 UI 配置](/with-others/multiplayer-mini-game/#搭场地与-ui)和[按钮引用配置](/with-others/multiplayer-mini-game/#gamebutton)给出挂载与 Inspector 接线。

```cs
public override void OnPlayerJoined(VRCPlayerApi player)
{
    if (!Networking.IsOwner(gameObject) || !Utilities.IsValid(player)) return;
    if (FindSlot(player.playerId) >= 0) return;

    int slot = FindEmptySlot();
    if (slot < 0) return;
    playerIds[slot] = player.playerId;
    RequestSerialization();
    UpdateUI();
}
```

要显示已占用槽位人数，在该 GameManager 的 `UpdateUI` 中，创建计分板字符串前加入：

```cs
int registeredCount = 0;
for (int i = 0; i < playerIds.Length; i++)
    if (playerIds[i] != 0) registeredCount++;
```

再将原来的字符串初始化改成 `string text = $"Scoreboard / 计分板 ({registeredCount}/{playerIds.Length})\n\n";`。人数从同一份 `playerIds` 推导，不再另同步一个可能失配的计数。它表示计分槽位占用数，不包括无槽位的观战者；实例总人数可另用 `VRCPlayerApi.GetPlayerCount()`。测试两人加入、离开一人、第三人补位以及 Owner 离开，逐次核对名单、人数和剩余分数。

OnPlayerJoined 不是可信外部服务器的注册接口。VRChat 的 Owner 是参与者客户端，关键操作仍要校验状态和输入。

## 瞬时反馈是否补播

已经结束的爆炸音效不需要默认补播给后加入者。若需要让玩家知道累计次数，可以同步 `explosionCount`；若需要显示最近发生时间，可以同步服务器时间戳。

这不是后加入者能够获取信息的唯一形式：也可专门设计有界历史记录。区别在于数据被明确保存，而不是期待旧网络事件自动重放。

### 灯：首次静默，后续真实变化有声

下面是独立的 `SyncedLampFeedback.cs`。在测试副本中用它替换灯按钮上的 `LampToggle`，不要让两个脚本同时控制同一盏灯。它保持同步 bool 为状态来源，用两个本地字段记录「是否已显示初始状态」和「上次显示的值」。

```cs title="SyncedLampFeedback.cs"
using UdonSharp;
using UnityEngine;
using VRC.SDKBase;

[UdonBehaviourSyncMode(BehaviourSyncMode.Manual)]
public class SyncedLampFeedback : UdonSharpBehaviour
{
    public Light targetLight;
    public AudioSource clickSound;
    [UdonSynced] private bool isOn;
    private bool hasInitialized;
    private bool displayedIsOn;

    private void Start()
    {
        if (Networking.IsOwner(gameObject)) _InitializeOwner();
    }

    public void _InitializeOwner()
    {
        if (!Networking.IsOwner(gameObject) || hasInitialized) return;
        if (!Networking.IsNetworkSettled)
        {
            SendCustomEventDelayedSeconds(nameof(_InitializeOwner), 0.5f);
            return;
        }
        ApplyState(false);
        hasInitialized = true;
        RequestSerialization();
    }

    public override void Interact()
    {
        if (!hasInitialized) return;
        if (!Networking.IsOwner(gameObject))
            Networking.SetOwner(Networking.LocalPlayer, gameObject);
        if (!Networking.IsOwner(gameObject)) return;

        isOn = !isOn;
        ApplyState(true);
        RequestSerialization();
    }

    public override void OnDeserialization()
    {
        ApplyState(hasInitialized);
        hasInitialized = true;
    }

    public override void OnOwnershipTransferred(VRCPlayerApi player)
    {
        if (Utilities.IsValid(player) && player.isLocal) _InitializeOwner();
    }

    private void ApplyState(bool allowSound)
    {
        bool changed = displayedIsOn != isOn;
        if (targetLight != null) targetLight.enabled = isOn;
        displayedIsOn = isOn;
        if (allowSound && changed && clickSound != null) clickSound.Play();
    }

    // 本地调试入口：发布同一个值，不制造一次开关操作。
    public void _ResendStateForTest()
    {
        if (!Networking.IsOwner(gameObject) || !hasInitialized) return;
        ApplyState(true);
        RequestSerialization();
    }
}
```

用于重复同值测试的按钮单独写在另一个文件中，测试结束可以移除这个按钮：

```cs title="LampResendTestButton.cs"
using UdonSharp;
using UnityEngine;

[UdonBehaviourSyncMode(BehaviourSyncMode.None)]
public class LampResendTestButton : UdonSharpBehaviour
{
    public SyncedLampFeedback lamp;

    public override void Interact()
    {
        if (lamp != null) lamp._ResendStateForTest();
    }
}
```

接线与验证：

1. 按钮保留普通 Collider；`Target Light` 拖入 Realtime Light。初始 `isOn=false`，可在场景里也关闭这盏灯，避免加载时短暂显示另一状态。
2. 给按钮添加 AudioSource，填写已获授权的短音效，取消 `Play On Awake` 和 `Loop`。如果存在 VRC Spatial Audio Source，还需在 `Advanced Options` 中取消 `Enable Spatialization`。这项对照用 `Spatial Blend=0` 的 2D 音频，降低音量，排除两人距离不同导致听不到的干扰；拖入 `Click Sound`。若要做空间音效，另按[声音配置](/placeness/sound-and-mood/)设置并测试距离。
3. Alpha 首先进场，初始化完成后第一次主动按灯，应听到一次音效。不能等待初始 Owner 收到自己的反序列化才启用声音。
4. 灯开启后让 Beta 加入：Beta 应恢复亮灯但不出声。随后 Alpha 或 Beta 按灯，已初始化的各端应在状态真实改变时播放一次。
5. 在测试副本另建带普通 Collider 的 Cube，挂 `LampResendTestButton`，把灯按钮上的 SyncedLampFeedback 拖入 `Lamp`。由当前 Owner 按这个测试按钮，确认两端灯不变且不多播声音；在 `_ResendStateForTest` 的 RequestSerialization 前加一条 `[LampTest] resend` 日志，并在 OnDeserialization 开头加 `Debug.Log($"[LampTest] received isOn={isOn}");`。只有看到接收日志且值与上次相同，才能记为“收到同值后未播声”；若没有接收日志，只能记为“本次未观察到重复同值接收”，不能据此声称该分支已实测。
6. 把 `Click Sound` 留空重测，灯仍应可同步。测试结束移除调试按钮。

这里的声音对应本机观察到的状态变化，不代表每一次点击都有可靠音效记录。两个快速切换可能在接收端合并成同一个最终值；需要逐次瞬时反馈时可用[一次性网络事件](/with-others/tell-everyone/#一次性网络事件)，并另处理事件频率与状态到达顺序。

### 扩展：累计开门次数

在本章「初始状态恢复版」SyncedDoorController 上做一个可选练习：

1. 添加 `using TMPro;`，类内增加 `[UdonSynced] private int totalOpens;` 和 `public TextMeshProUGUI openCountText;`。
2. 只在 `Interact` 的 `isOpen = !isOpen;` 后加 `if (isOpen) totalOpens++;`。已有 Owner 复查必须保留；关门不增加开门次数，已有 `RequestSerialization()` 会一起发送计数。
3. 类内加入下面的方法；在 `_InitializeOwner`、`Interact`、`OnDeserialization` 应用门状态之后各调用一次 `UpdateOpenCount()`。

```cs
private void UpdateOpenCount()
{
    if (openCountText != null) openCountText.text = $"开门次数：{totalOpens}";
}
```

4. 创建 World Space Canvas 和 TMP 文本，拖入 `Open Count Text`。按开、关、开三次，预期累计为 2；让 Charlie 后加入，确认他直接看到 2，不靠重播开门事件累加。Owner 离开后再操作，检查计数继续增加而不是归零。

## 加入时的欢迎效果

这个可选例子只在本机初始化名单之后，为新出现的远端 playerId 播一次短音效。初始化期间已有或新到的玩家都归入初始名单，不补播欢迎；它不依赖「自己的 Join 一定最后到」这样的顺序假设。

```cs title="LocalJoinWelcome.cs"
using UdonSharp;
using UnityEngine;
using VRC.SDKBase;

[UdonBehaviourSyncMode(BehaviourSyncMode.None)]
public class LocalJoinWelcome : UdonSharpBehaviour
{
    public AudioSource welcomeSound;
    private int[] knownIds = new int[0];
    private bool ready;

    private void Start()
    {
        _InitializeRoster();
    }

    public void _InitializeRoster()
    {
        if (ready) return;
        if (!Networking.IsNetworkSettled)
        {
            SendCustomEventDelayedSeconds(nameof(_InitializeRoster), 0.5f);
            return;
        }
        VRCPlayerApi[] players = new VRCPlayerApi[VRCPlayerApi.GetPlayerCount()];
        VRCPlayerApi.GetPlayers(players);
        for (int i = 0; i < players.Length; i++)
            if (Utilities.IsValid(players[i])) Remember(players[i].playerId);
        ready = true;
    }

    public override void OnPlayerJoined(VRCPlayerApi player)
    {
        if (!ready || !Utilities.IsValid(player)) return;
        if (!Remember(player.playerId) || player.isLocal) return;
        if (welcomeSound != null) welcomeSound.Play();
    }

    public override void OnPlayerLeft(VRCPlayerApi player)
    {
        if (player == null) return;
        for (int i = 0; i < knownIds.Length; i++)
            if (knownIds[i] == player.playerId) knownIds[i] = 0;
    }

    private bool Remember(int id)
    {
        for (int i = 0; i < knownIds.Length; i++)
            if (knownIds[i] == id) return false;
        for (int i = 0; i < knownIds.Length; i++)
        {
            if (knownIds[i] != 0) continue;
            knownIds[i] = id;
            return true;
        }
        int[] expanded = new int[knownIds.Length + 1];
        for (int i = 0; i < knownIds.Length; i++) expanded[i] = knownIds[i];
        expanded[knownIds.Length] = id;
        knownIds = expanded;
        return true;
    }
}
```

挂到一个始终激活的空物体，添加 AudioSource，取消 `Play On Awake`、`Loop`，用低音量 2D 短音效并填入 `Welcome Sound`；若带 VRC Spatial Audio Source，在 Advanced Options 取消 Enable Spatialization。Alpha 先加入并等初始化完成，再让 Beta 加入：Alpha 播一次，Beta 不为 Alpha 和自己补播。等 Beta 初始化完成后让 Charlie 加入，Alpha、Beta 各播放一次，Charlie 初次建立名单保持静默。短时间多个新人加入时 `Play()` 可能重启同一音源，这个例子没有排队播报功能。

OnPlayerJoined 本来就在各客户端触发，本例不再广播 All。初始名单快照避免已在场玩家的迟到回调被误当成新人；本地的 `knownIds` 只用于去重，不是共享计分名单，也不替代 Owner 的槽位管理。

## 测试矩阵

- Alpha 开灯，Charlie 加入，确认无需下一次点击即可恢复开启状态
- 门动画结束后加入，确认初次显示为终态
- 门动画途中加入，确认符合所选终态或进度恢复方案
- Alpha 改门后，Beta 在自己的后续动画期间按门，应被本地冷却拦住；结束后可再按
- 重复收到同一灯值不多播声；重复门值不延长动画冷却
- 音效已经播放后加入，确认不重播过去效果
- 玩家离开后加入另一人，确认槽位可重用
- 当前 Owner 离开，确认名单和状态仍可恢复
- 网络同步尚未完成时尝试交互，确认不会用初值覆盖已存在状态
