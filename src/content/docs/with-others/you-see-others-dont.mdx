第 13 章的灯开关只修改本机 Light。两位玩家进入同一实例后，各自拥有一份灯和脚本实例，按按钮不会自动修改另一台客户端的灯。

## 保留一个本地开关

```cs title="LampToggle.cs"
using UdonSharp;
using UnityEngine;
using VRC.SDKBase;

public class LampToggle : UdonSharpBehaviour
{
    public Light targetLight;

    public override void Interact()
    {
        if (targetLight == null) return;
        targetLight.enabled = !targetLight.enabled;

        VRCPlayerApi local = Networking.LocalPlayer;
        string who = Utilities.IsValid(local) ? local.displayName : "unknown";
        Debug.Log($"[Lamp] {who} pressed. enabled = {targetLight.enabled}");
    }
}
```

确认 `Target Light` 引用已填，Light 为可以运行时切换的 Realtime 灯，初始状态为开启。否则灯的可见结果还可能受 Baked 光或错误引用影响。

`Networking.LocalPlayer` 是本机客户端对应的玩家；日志记录本机事件与组件状态，不代表消息已经发送给其他人。

## 准备双客户端测试

单客户端 Build & Test 可检查编译和引用，不能证明多人同步正确。可使用[多客户端 Build & Test 与独立 profile](/surviving/testing-your-world/#第三节build--test)，或按[构建并上传 Private 世界](/publishing/submit-your-world/#第四节构建并上传-private-世界)邀请测试者进入同一实例。

上传测试时：

1. 保存场景，打开 `VRChat SDK → Show Control Panel`，在 Builder 检查验证信息。
2. 确认世界名称、描述、图片及内容使用权。
3. 使用对应平台的 Build & Publish，将测试版本保持为 Private。
4. 从 SDK Content Manager 或客户端自己的世界列表打开已上传世界，创建适合测试范围的实例，邀请第二个账号进入。
5. 确认双方进入同一实例、加载同一版世界。

世界发布状态与实例访问类型是两个独立设置，不能把 Private 世界简单等同于 Friends 实例。

客户端日志可用于比较本地事件。Windows 日志位于 `%USERPROFILE%\AppData\LocalLow\VRChat\VRChat\`，按时间选择本次会话文件。ClientSim 的模拟玩家可帮助检查事件，但不替代真实网络测试。

两边同时打开各自本次会话日志，先记下「A 第一次按」「B 第一次按」「A 第二次按」的操作顺序，再搜索 `[Lamp]`，把每一步的玩家名和灯状态并排记录。两台机器的日志时间不一定严格对齐，先按操作标记对应事件，不用时间戳差值直接计算网络延迟。

Quest / Android 真机需先按[目标设备测试](/surviving/testing-your-world/#第六节android--quest)完成设备授权与连接。可在可信电脑运行 `adb logcat`，或在 Unity 的 `Window → Analysis → Android Logcat` 选择实际设备与 VRChat 进程，搜索 `[Lamp]`。这是设备日志入口，不是 Unity Console；能否看到目标输出需实测，不能把编辑器日志当作真机证据。日志获取方式见 [Unity Android 调试文档](https://docs.unity3d.com/2022.3/Documentation/Manual/android-debugging-on-an-android-device.html)。

## 逐步记录两边的灯

两边初始灯都开启时：

| 操作 | A 客户端 | B 客户端 |
| :--- | :--- | :--- |
| A 按一次 | 灯关闭，记录 A 的日志 | 灯仍开启，无该次 Interact 日志 |
| B 按一次 | 灯仍关闭 | 灯关闭，记录 B 的日志 |
| A 再按一次 | 灯开启 | 灯仍关闭 |

第二步中两边都关闭，只是各自按了一次后的结果。**B 的 Interact 不会把 A 的灯重新翻转。** 判断同步要看一次操作是否传播，不能只比较某一时刻两张画面是否相同。

[本地动画门](/come-alive/doors-and-states/)也适用同一检查：A 开门只改变 A 的本地状态；B 操作自己的门，不改变 A 的状态。在其 `AnimatedDoorController.cs` 顶部保留或添加 `using VRC.SDKBase;`，把下面片段插在 `Interact` 内、`isOpen` 翻转和 Animator 调用之后。不要插在动画期间早退的前面，也不要重复声明已有同名局部变量。

```cs
VRCPlayerApi local = Networking.LocalPlayer;
string who = Utilities.IsValid(local) ? $"{local.displayName} ({local.playerId})" : "unknown";
Debug.Log($"[Door] {who} pressed. isOpen={isOpen}");
```

先让 A 按一次并等动画完成，再让 B 按一次，分别查两端 `[Door]` 日志。只替换操作人，不改脚本、初始门状态或 Animator 配置；这能直接检查是哪台客户端执行了门的本地交互。

## 客户端与脚本实例

```text
A 客户端                         B 客户端
LampToggle 实例 A                 LampToggle 实例 B
Light.enabled = false             Light.enabled = true
       ↑                                 ↑
A 的 Interact 修改 A               B 的 Interact 修改 B
```

- 每个客户端加载自己的场景副本。
- `Interact` 由进行交互的本机调用，不自动成为网络事件。
- 普通脚本字段与 Unity 组件属性不因名字相同而共享内存。
- 显式同步需要选择数据、发送方式和负责写入的客户端。

这样可以控制需要传输的数据范围。音量、语言和镜子显示等个人选项可以保持本地；全局计分或门的共享状态才需要跨客户端协调。

## 为什么 Pickup 可以自动移动

第 15 章的 Pickup 如果配有 `VRC Object Sync`，物体位置和旋转可由组件同步。拿起物体还涉及所有权转移。

但 Object Sync 不等于同步所有字段：

- 位置和旋转，以及组件明确管理的物理状态，按组件机制同步
- 任意脚本 bool、Light 强度、Animator 参数或 Transform 缩放，不因此自动同步

玩家位置、加入离开等也有 SDK 内置机制。需要判断的是具体字段或事件由谁管理，而不是把所有 SDK 组件视为同一种脚本同步。

## 四个独立的设计问题

| 问题 | 机制 |
| :--- | :--- |
| 哪个客户端负责发布这个对象的状态 | Ownership |
| 当前状态怎样到达其他客户端 | 同步变量与序列化 |
| 只有当前在场者需要的瞬时操作怎样触发 | 网络事件 |
| 中途加入后怎样显示已有状态 | 接收同步变量并更新本地表现 |

所有权不等于权限管理，也不自动把任意字段变成同步字段。网络事件不会为后加入者回放历史。

## 对照已实现的交互

- **区域音乐**：第 14 章检查 `player.isLocal`。A 进入区域只播放 A 的音乐；B 尚未进入时不播放。若移除本地过滤，远端玩家的进入事件也可能改变本机播放状态。
- **Pickup 发光**：Object Sync 处理物体移动；本地 Pickup 事件改变的 Light 强度，需要单独判断是否同步。
- **本地门**：未同步的 `isOpen` 只控制本机 Animator。

可在各自事件中加入 `Debug.Log`，同时记录玩家 ID、当前客户端与字段值。根据日志确认事件发生在哪台机器，不用画面相似性代替事件证据。

再做一轮受控对照：保留同样的两位测试者、初始关闭状态、Light 模式、引用与点击顺序，分别在本地版本和[同步灯版本](/with-others/tell-everyone/#同步灯开关)中执行 A 按一次、B 按一次。只更换开关脚本并重新构建；记录 A 的一次操作是否改变 B 的灯，而不是只比较最后两张画面。区域音乐与 Pickup 则保持原脚本不变，逐项观察声音、亮度和物体位置，不把不同输出混成一个“已同步”的判断。

## 检查清单

- [ ] 双方进入同一实例并使用同一版本
- [ ] 初始灯光状态与测试记录一致
- [ ] A 操作时只出现 A 的本地 Interact 日志
- [ ] B 操作不会改变 A 的未同步字段
- [ ] 已区分 Object Sync 的范围与自定义脚本状态
- [ ] 区域音乐保留本地玩家过滤
